# Panasonic LUMIX S5 / S5M2 固件研究交接报告

更新日期：2026-10-10

## 范围与证据边界

本报告整理现有 `contributors/williamwu1234` 分支中关于 Panasonic DC-S5、LUMIX Sync 与 S5M2 跨机型样本的研究结果。

- 已完成实机验证的 HTTP 协议与无令牌行为，样本机为 DC-S5。
- 完整 UPD 容器与 48 个分区的结论，主要来自 `S5___V29.bin`。
- S5M2 目前仅有固件 ZIP 前 64 KiB 样本及跨机型比较证据。
- 除非另有明确输入散列与实机记录，本报告不把 S5 的实测结果直接等同于 S5M2。

## 已确认结果

### 1. LUMIX Sync 与 DC-S5 HTTP 控制协议

相机通过明文 HTTP 暴露 `/cam.cgi`。现有实测表明，DC-S5 的 `getstate`、`getinfo`、`camcmd`、`camctrl`、设置读取及部分设置写入可在不取得会话令牌的情况下使用。

`accctrl&type=req_acc` 返回四字段响应；未观察到第五字段令牌。`req_acc_g` 与 `req_acc_e` 返回 `err_param`。这说明当前 DC-S5 样本不签发 app 可保存的会话令牌，但不能据此断言所有 S5M2 固件版本行为相同。

固件更新由 `startsenddata`、`senddata`、`requestsenddata`、`endsenddata` 等步骤构成，属于 app 向相机发送更新包的单向流程。

### 2. UPD 固件容器

现有 DC-S5 样本由外层 UPD 头、内层头、目录、分区数据与末尾 RSA-4096 签名组成。已识别 48 个命名分区，包括：

- `loader1/2/3`
- `program`
- `dtb`
- `zimage`
- `rootfs1/2`
- `storage`
- `eep_*`
- `ipu_data/code`
- `rc_data/code`
- `nr_data/code`

分区表条目包含名称、偏移、大小、加载地址候选、类型字段及 48 字节字段。相邻分区在样本中连续铺满数据区。

### 3. 加密与解密尝试

`dtb`、`zimage`、`rootfs1/2`、`program` 等目标分区未出现预期明文魔数，数据熵接近加密或强压缩数据。现有实验已排除以下简单方案：

- 单字节及重复密钥 XOR；
- 以 `panasonic`、头部 64 字节块、分区 48 字节字段等作为候选材料的 XOR；
- 多组 AES-128/256 ECB、CBC、CTR 组合；
- 将 48 字节字段直接视为 SHA-384 标签。

这些负结果仅排除已测试参数组合，不能证明具体算法或密钥位置。

### 4. S5 与 S5M2 的跨机型证据

S5 与 S5M2 固件样本在偏移 `0x220` 的 64 字节块不同，因此该块不是可直接跨机型复用的全局明文密钥，更像签名、设备族相关数据或其他每包变化的材料。

现有 S5M2 输入仅记录为固件 ZIP 前 64 KiB 样本。尚未取得足以独立验证 S5M2 完整分区布局、加密算法、HTTP 鉴权行为或设备端加载链的完整公开证据。

## 已排除或受阻方向

1. LUMIX Sync APK 静态分析未发现读取相机内存、固件、OTP 或密钥的公开命令。
2. 对 DC-S5 的隐藏 `getinfo`/`mode` 候选探测未得到内存、固件或密钥数据。
3. 现有文件内候选材料无法通过常见 XOR/AES 组合还原已知文件魔数。
4. 固件上传接口只能证明相机接受并处理更新包，不能证明它会向客户端泄露解密结果。

## 下一步建议

1. 取得完整且可公开复现的 S5M2 固件包，记录来源、大小与 SHA-256。
2. 使用相同解析器独立验证 S5M2 的头部、目录、分区数量、连续性与签名位置。
3. 对 S5、S5M2、S5M2X 的同版本族样本做字段级差分，区分固定结构、版本字段、签名材料与加密数据。
4. 在不修改机身的前提下，抓取 S5M2 的 LUMIX Sync 握手、能力查询及更新传输，验证其是否沿用 S5 行为。
5. 若研究硬件提取或构造更新包，应先建立可恢复方案；任何设备端写入实验都存在变砖风险。
