# Panasonic S1M2 固件研究需求与交接

记录日期：2026-10-07；授权边界更新：2026-10-08。本文用于与原厂升级包一起放入后续项目，作为需求与研究边界；不是已完成的可行性报告。

## 项目目标

研究 Panasonic LUMIX S1M2 的原厂固件，判断哪些拍照和视频功能能够解锁、扩展或新增。机主已确认 S1M2、国行、购入后未升级；机身在 2026-10-08 只读采集中返回版本 1.4。优先解决实际拍摄限制，兼顾成片质量、实用性和机身风险，不优先做装饰性菜单或小工具。

已取得供离线分析的 V1.4 原厂升级包；来源和散列见阶段结果汇总。未升级不能据此认定出厂版本为 V1.0。第一阶段仅离线分析，不连接或修改相机。

## 机主明确提出或关注的需求

### 1. 机内多曝光 HDR 合成

- 利用曝光包围，合成高动态范围照片。
- 希望支持手持对齐和运动去重影。
- 机主指出相机已有手持高分辨率（俗称“摇摇乐”）合成，认为其对齐与运动处理可能可以复用。
- 研究判断：值得查找可复用模块，但同曝光像素位移合成与不同曝光 HDR 不同，不能预先认定可以直接接用。
- 可考虑的原型：三帧曝光包围、原生分辨率 JPEG 输出、保留原始 RAW。这是助手提出的原型，尚非机主确定的最终规格。
- 处理器、内存、专用图像处理通路及恢复机制均未验证。

### 2. 保存高分辨率合成的全部输入帧

- 机主明确表示此提案有意思，是值得优先调查的方向。
- 用途：原厂合成出现运动伪影时，可重新处理；也可将相同素材交给其他多帧算法比较。
- 首先确认是否存在完整单帧数据、其排列与位深、缓冲区生命周期，以及黑电平、曝光和传感器位移信息。
- 不能假定所有完整帧同时保存在内存中；可能边采集边融合，或直接进入专用硬件。
- 初步成果可以是正确导出的原始数据及元数据，不必一开始就生成完整 RW2。
- 保存必须避免干扰采集时序；需要分析额外内存、复制带宽、写卡及错误处理。

### 3. 改善对焦的主体锁定策略

- 机主限定讨论主体锁定，不是重写整个 AF 或提升传感器测距能力。
- 目标：减少跳背景、换人；短暂遮挡时保留原目标；原主体出现后尽量恢复锁定。
- 可能调整：目标切换滞后、丢失宽限、重新捕获条件。
- 所需信息：主体候选框、类别、置信度、当前锁定状态、跨帧匹配或外观特征、位置与运动信息，以及最终目标选择入口。
- 检测“这是一个人”不等于确认“这是同一个人”。跟踪 ID 是匹配后的标签，不是身份证据。
- 可以在内存里暂存外观模板或特征向量，不必保存照片到卡上。松下是否提供这种数据未知。
- 若只能读取最终对焦框，可能只能改善短期稳定性，无法可靠解决相似主体交叉或长时间遮挡后的身份匹配。
- 取舍：锁定越牢，主动切换目标可能越慢。用户点选、解除锁定等操作必须优先。

### 4. H.265 / HEVC All-Intra 4:2:2 视频

- 机主描述原厂有 H.264 All-Intra 4:2:2，希望增加 H.265 All-Intra 4:2:2。具体原厂模式需按固件核实。
- 目标分辨率、帧率、位深、码率和封装尚未确定。
- 关键：硬件编码器是否同时支持 HEVC、4:2:2、全帧内编码及目标分辨率/帧率。
- H.264 支持 4:2:2、All-Intra，不证明 HEVC 同样支持，不能简单替换格式参数。
- 调查模式表、编码器初始化参数、4:2:2 输入通路、缓冲区、封装和写卡流程。
- 字符串或菜单项存在，不等于编码功能可用。
- 不预设 HEVC All-Intra 一定更省空间、更好剪辑或画质更高。

## 助手提出、尚未确定采用的方向

### 相对优先

1. 扩大曝光包围步长至 2/3 EV，支持更自由的张数或序列。
2. 曝光包围与间隔拍摄组合，用于 HDR 延时素材采集。
3. 原生分辨率多帧降噪；不要求超分辨率或大型神经网络。

官方基础说明书列出的包围曝光上限为七帧、1 EV 间隔，且不允许与间隔拍摄、高分辨率模式等组合。需核实后续固件是否改变这些限制。

### 视频候选，尚未确认缺失或决定实现

- 更可控的自动 ISO、白平衡过渡速度及临时锁定。
- 视频跟踪目标锁定策略。
- 在硬件已支持范围内开放码率或 GOP 参数。
- 导出与视频同步的陀螺仪数据；还需时间戳、镜头和滚动快门信息支持。
- 视频交替曝光序列：难度高，存在运动、闪烁和有效时间采样问题，不作为初始目标。

机主不满意泛泛的小工具提案，如参考图叠加、参数提醒、检查页等。后续建议应对应真实短板，并先核对原厂已有功能。

## 安全与授权边界

- **机主明确表示绝对不会拆机。这是研究的硬条件：不得要求拆外壳、焊接、连接内部测试点、JTAG/UART 接口或拆取芯片；不得将这类方法作为用户必须完成的下一步。**
- 在此条件下调查公开固件、开源资料、官方电脑软件和外部 USB/网络协议。研究外部接口不等于授权连接实机或发送命令。
- 若最终只能通过拆机获得必要证据，应报告该路线不满足条件，并明确相应功能仍未证明可实现；不得继续劝说机主拆机。
- 机主关心变砖风险，助手明确不能保证修改固件上机零风险。
- 不向相机写入、只在电脑上分析文件，不会因该分析改变机身状态。
- 固件备份不等于有可用恢复路径；启动失败后可能无法进入原厂升级。
- 当前授权为离线分析与可行性评估。未经机主明确同意，不刷写、不执行实机修改、不改变启动或升级状态。
- 功能本身较轻，不代表其安装方式风险低。修改启动、升级、传感器时序、编码器或实时内存通路需分别评估。
- 不绕过温度、电池等保护来追求规格。
- 静态分析工具不得运行下载的未知 EXE。若需要动态验证，使用合适的隔离环境并明确范围。

## 后续项目的建议工作流程

1. 读取本文；登记相机型号、当前版本、地区、原厂包版本与来源。
2. 保留原厂文件不变，记录文件大小和 SHA-256；所有提取与实验在副本中进行。
3. 判断容器、架构、压缩/加密、校验/签名，以及更新包包含哪些组件。未证实的签名机制不得当作事实。
4. 先找模式表、模块边界和数据流，不以搜索到关键词作为可用功能证据。
5. 分别评估：摇摇乐输入帧导出、AF 锁定策略、HEVC 4:2:2 All-Intra、曝光包围扩展与 HDR 延时。
6. 输出候选功能报告：发现依据、可行性等级、硬件或接口依赖、风险、未知项及下一步验证方式。
7. 实机验证前，提出具体可审查方案、恢复条件与停止条件，由机主明确决定是否继续。

可行性等级建议：已有完整隐藏路径 / 可复用现有模块 / 需要新增实现 / 硬件限制或证据不足。始终区分文件分析、作者自述、实机观察和实际验证。
