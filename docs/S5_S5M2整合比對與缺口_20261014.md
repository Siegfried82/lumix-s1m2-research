## 4. 統一採用的糾正

1. **S5M2 完整樣本已取得。** [舊交接稿](S5与S5M2固件研究交接报告.md)保留歷史正文且已有維護者狀態註；不要繼續把 64 KiB 限制當現況。
2. **有限密碼枚舉未命中不證明「離線永不可能」或「密鑰一定在 OTP/eFuse」。** 直接閱讀來源 `parse_upd.py` 仍見 `raw[doff:doff+dsize]`；正確 S5 V29 文件起點應加 `0x200`。來源 `keyhunt.py` 的 CTR 分支使用 `iv=` 並吞掉異常，無有效陰性覆蓋。參見[腳本審查](../analysis/s5_github_review_20261013/delta_review/DELTA_FINDINGS.md)。
3. **舊配對資料不能照用。** 35 條 V29 a 側加 3 條版內 b 側共 38 側首塊，先前實物核驗均來自錯位切片；V2.4 原件仍缺，不能把已核 V29 結果當作完整兩側糾正。標成 IV 的尾欄位也仍是語義假設。
4. **S5 exFAT「可控內核寫已成功」已撤回。** 未崩潰／螢幕報错不足以定位 NULL 檢查；「所有路線均不存在」也超出現有證據。
5. **ROM BACKUP 是區域參數備份。** 三份邏輯區域不是已核實連續 384 KiB 物理空間，更不是完整固件或 RAM。未取得驗證密鑰不等於證明任何位置均沒有密鑰材料。
6. **MOV／C4K 不宜一概稱為新增編碼能力。** [松下官方 V2.0 更新記錄](https://av.jpn.support.panasonic.com/support/global/cs/dsc/download/ff/dl/s5.html)已列出 MOV C4K 60/50p 150 Mbps 8-bit 及 30/25/24p 150 Mbps 10-bit。設定／菜單變化應與這個官方基線比較。
7. **媒體證據的型號要核對。** 來源 `hidden_format_evidence/verified_findings.json` 指向 S1H V2.8、`mp4ed_25p_400mbps_4k_10bit`，並明列 `S5_hardware_verified=false`；不能因資料放在 S5 倉庫就當作 S5／S5M2 成片。原影片未分發，這次無法獨立解碼。
8. **欄位名和功能字串不是裝置能力證明。** 返回 `ok`、有 token、顯示選單、同候選摘要或公開源碼均需各自的本機資料／消費者閉合。

## 6. 本次驗證範圍與重算方式

本次完成：固定 Git tree 的完整性／數量檢查、跨路徑 Git blob 身份交集、舊比較紀錄逐項身份核對、S5M2 清單 flags 重新計數、選定原稿與現有核驗對照、新文件引用路徑檢查。S5M2 清單仍為 54 項、40／14；舊比較 864 條均與来源身份相符。

重算內容交集時，對兩個固定提交使用 GitHub `git/trees/<commit>?recursive=1`，先拒絕 `truncated=true`；只保留 `type=blob`。按目标 `sha` 建多值索引，逐條來源查找相同 SHA；保留所有路徑而非檔名字典。JSON記錄的是Git blob SHA-1身份，不是固件SHA-256；未下載所有檔案重新計算完整位元組或逐檔語義審查。

本次沒有本庫完整本地checkout，沒有重新執行 `python3 evidence/verify_public.py`、歷史固件／ROM檢查或原媒體解碼；[既有发布验证](RELEASE_VALIDATION_20261013.md)與[接续运行](FOLLOWUP_RELEASE_20261013.md)是2026-10-13歷史證據。新增文件經API讀回核對；修改範圍只增加本頁與內容比較紀錄，既有歸檔保持原字節。
