# 跨机型"录制规格移植"的可行性边界（2026-10-13）

问题：S1H 与 S5 不是同一块传感器，那若拿到 **S5II（S5M2）的录制规格**，能不能移植到 S5？

## 1. 先把前提纠正一半

- **S1H 与 S5 属于同一代 24MP 全画幅家族**（S5 常被视作 S1 系简化版；差异主要在 OLPF、
  视频规格与散热，不是换代）。这正是 `videoformat=mov` 能在 S5 上解锁 MOV 家族的原因——
  **两台机共用同一套固件血统**，S5 固件里本来就带着 MOV 的实现，只是被配置门关着。
- **S5II 是换代平台**，不是 S5 的兄弟：S5 = **MC801**（32-bit，Cortex-A7 级）；
  S5II / S1M2 一代 = **SC2006A / MC8243**（4×Cortex-A53，64-bit）。
  连设置文件结构都不是一路（见下表）。

| | S5 | S5II / S5IIX |
|---|---|---|
| SoC | MC801（A7 级，32-bit） | SC2006A / MC8243（4×A53，64-bit） |
| CAMSET 大小 | **65,533 B** | **2,252,861 / 2,253,165 B** |
| 记录数 | **831** | **966 / 978** |
| 头部 | 44 B（`Panasonic`+`DC-S5`）+ 8 B 前导 | 49 B 头 + 3 B 架构版本标记 |
| 记录流 | 起点 `0x34`，6 B 记录头，紧凑排布 | 4 字节对齐的"双格式"TLV（小记录 + 大记录） |
| 本机最大 tag | `0x04b5` | 含 S5IIX 专属 `0x0534`/`0x0536–0x0540`（USB-SSD/ProRes/推流/HDMI RAW） |

⇒ **两机的"字段地址"根本不一一对应**。S5II 的 tag `0x0534` 之类在 S5 上压根不存在
（实测 S5 blob 最大 tag `0x04b5`，无 ≥`0x0500` 的记录）。

## 2. 关键分层：能力在固件，设置在"选择层"

- **能力层** = 固件里的编码管线 + 机型能力表（能不能真的做 5.9K/ProRes/400Mbps）。
- **选择层** = camsetting blob 里的开关与码（`videoformat`、`videoquality`、各家族质量记忆项）。
- 我们**只有选择层的写权限**（`setsetting` / camsetting 上传）。选择层**只能选出固件已实现的东西**，
  不能凭 token 字符串让固件长出一条新管线。

证据（实测）：

| 尝试 | 结果 |
|---|---|
| S5 固件词汇表（`curmenu` 255 个 v_quality token） | **没有 prores / ssd / raw / 8k / anamorphic** |
| `mov_*_5_9k_*`（S1H/S5II 级开片门） | setter 有时 ok，但实拍只出 C4K 60p（回退顶档）→ 见 08 报告 |
| `mov_*_6k_*` | `err_param` |
| `mov_*_a6k_*`（变形 6K） | setter 回 ok 但**静默忽略**（码不变） |
| `mp4ed_*_400mbps_*`（S1H 验证过的 ALL-I） | 44 个 NTSC 候选 **0 个读回正常**（`err_critical`） |

⇒ S5 的固件词汇表**就是它能力的上界**；表外的 token 要么被拒、要么被静默回退。

## 3. 就算拿到"S5II 录制规格地址"，也没有可用通路

1. **设置地址不可移植**：两机 blob 布局与 tag 编号体系不同，写过去只会被校验/忽略。
2. **固件地址不可用**：要改固件内存或代码，需要写原语，而本项目已证：
   - 网络侧无 RCE（GoAhead/LD_PRELOAD/exec 全阴性；仅剩未测 CVE-2019-5096）；
   - 固件 AES 密钥不可离线恢复（MC801 片内）；
   - 固件升级写路径卡在最终部分块 flash 定址，从未见过一次成功 `endsenddata`。
   所以"知道地址"在没有**代码执行或固件替换**之前等于零。
3. **换 SoC 家族更致命**：SC2006A 的格式化/编码路径不能直接搬到 MC801 的固件里，
   即便有源码级地址也需重编译与签名——签名是硬门。

## 4. 真正可移植的边界

- ✅ **同代同族**（S1 / S1H / S5，MC801 一代）：值得挖。我们已借此拿到 MOV 全家族 与 `mp4ed`。
- ⚠️ **同代但不同定位**：token 可能"读回正常"却录不出东西（S1H 报告：16 候选里仅 2 个出真媒体）。
- ❌ **换代平台**（S5II / S1M2 / S1RM2，SC2006A 一代）：token、tag、地址、编码管线四层都不同，
  **移植没有可行性**；除非先拿到该平台的代码执行或固件改写能力。

## 5. 若仍想实测（零风险，低成本）

可以拿一份 S5II 的 `allmenu`/`curmenu`（或公开的 token 清单），把其中 S5 没有的 token
逐个 `setsetting` + 连续读回 + （有意义的）实拍解码。方法与判据同本次。
按现有证据，预期结果是**全部被拒或被静默回退**，但真做一遍可以把"不可能"变成实测结论。
**注意**：不要用 S5II 的 blob 或 tag 值去直写 S5 的 camsetting——布局不同，属于盲写，
既无收益又增加变砖风险。
