# 02 · 攻击面总览

> 按"能否**改内容 / 拿 shell**"的价值排序。每条给出：能力边界 + 现状 + 对应章节。

## 四类攻击面

| 面 | 通道 | 最强能力 | 现状 | 章节 |
|---|---|---|---|---|
| **A 固件升级写路径** | Wi-Fi CGI `startsenddata / senddata / endsenddata` | **重写整个 rootfs**（= 改内容最强原语） | 卡住（最终-chunk 定址失败，未打通一次成功 `endsenddata`） | §04 |
| **B Wi-Fi HTTP 服务** | GoAhead（`Server: Panasonic`，CGI） | RCE / 溢出 / 信息泄露 | **RCE 全阴**，仅剩 CVE-2019-5096 未测（需堆控） | §05 |
| **C USB 私有 PTP** | `pvc_mass_storage`（非标准 SCSI PTP） | 读全量配置 / 探测升级状态机 | 只读 dump 成功（0x9421）；**无任意地址写**；length-DoS 已证 | §07 |
| **D DLNA / 内容** | `:60606/Lumix/Server0/ddd`（SOAP ContentDirectory） | 内容浏览 | 非升级流，价值低 | — |

## 关键洞察（贯穿全报告）

1. **不需要 AES 密钥**。只要拿到**开机后 DDR 里的运行时明文**，就绕开了密钥本身。最现实的高价值动作在**物理 / 调试侧**（UART/JTAG 读明文、SD.DAT 绕验签），而非软件侧。
2. **软件侧唯一能"写整个 rootfs"的是固件升级写路径**（§04）——它是"改内容"的主通道，但当前被"最终-chunk flash 定址失败"卡住，差最后一步。
3. **Wi-Fi 是验证型 oracle，不是提取通道**（§08）：只能验证（版本门 / 签名 / 校验和），不能提取密钥 / 明文，也没有调试后门。
4. **已确认的实机漏洞只有一条：PTP length 不校验导致的本地 DoS**（§06），挂死、拔插 USB 恢复、无写 / 不砖机。
5. **RCE 目前全部阴性**（§05）：编译 C / `LD_PRELOAD` 无效，已公开 GoAhead CVE 多数不适用，仅 CVE-2019-5096（multipart UAF→RCE）未测。

## "改内容"可行性排序（回答用户核心问题）

| 优先级 | 路径 | 能否改内容 | 性质 | 现状 |
|---|---|---|---|---|
| 1 | **固件升级写路径**（刷写=重写 rootfs） | ✅ 最强（改代码+数据） | 软件 / Wi-Fi | 卡住（§04） |
| 2 | **物理 / 调试侧**（UART/JTAG 读明文、SD.DAT 绕验签） | ✅ 可写自编代码 | 需拆机 | 列为后续首选（§10） |
| 3 | **PTP 配置写回**（0x9422 / 0x9423） | ⚠️ 只改设置分区（数据，非代码） | 软件 / USB | 只读探测了状态机；**未执行写**（安全红线） |
| 4 | **CAMSET 校验和可伪造**（写设置分区） | ⚠️ 数据级 | 软件 / Wi-Fi | 校验和已反推、可伪造；仍是设置数据非代码 |

**一句话**：软件侧唯一真正"能改内容"的通道是固件升级写路径；它差最后一步（打通一次成功 `endsenddata`）。在此之前，最现实的高价值动作是**拆机走 UART/JTAG 读运行时明文**（零风险、不需密钥、直接绕开 AES）。
