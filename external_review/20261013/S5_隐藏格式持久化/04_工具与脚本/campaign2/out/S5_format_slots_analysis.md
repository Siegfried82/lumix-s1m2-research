# S5 format-slot analysis — record 0x005e payload and boot-default container search

Date: 2026-10-12. Pure offline parse of the six 65533-byte `camsetting` blobs already in the
repo. No camera / network contact.

## Corrections to Hank's fieldmap (verified against the raw bytes)

1. **The record stream starts at `0x34`, not `0x2c`.** Hank's map said "payload begins at
   `0x2c`", but `0x2c` is actually a second, 8-byte sub-header
   `cc ff 00 00 00 03 00 00`, byte-identical across all six blobs. The first TLV record is
   tag **`0x0001`** at `0x34` — the **model-identity field**: 13× `u16 0x0049` = ASCII `'I'`
   (S5), matching the `"DC-S5"` header and the S1M2 reference convention where `0x004a='J'`
   (S5II) / `0x004b='K'` (S5IIX).
2. **There are 831 records, not 830** (Hank's count omitted tag `0x0001`).
3. **Record `0x005e` header sits at `0x0bf0` (3056)**, not `0x0bee` (3054). Hank's own hex
   context dump and his "active value = byte 3062" were both correct; only the listed record
   offset `0x0bee` was off by 2.
4. **`videoquality` (`0x0124`) has 13 u16 slots, not 16.** `len=0x20=32` is the *whole record*
   (6-byte header + 26-byte payload = 13×u16). Slot 0 holds the active code; slots 1..12 hold
   `0x00c0`. Hank's "16-entry / slots 1..15" was an off-by-3 error.

Layout summary: `0x00..0x2b` header · `0x2c..0x33` sub-header · `0x34..0xfff7` 831 TLV records
· `0xfff8..0xfffb` trailer `ff ff 00 00` · `0xfffc` checksum byte.

## (a) Field dictionary

831 distinct `field_id`s across the six blobs; **115** have >1 payload variant (almost all of
those are blob C's burst/photo state; the campaign states A/B/D/E/F differ at only the 52
offsets Hank already tabulated). `len=20` records (14-byte payload = 13 value bytes + 1 NUL)
are the "small"/scalar setting type; larger records (`0x0043`=1308 B, `0x0044`=476 B,
`0x0431/0x0432/0x043d/0x0440`=404 B, etc.) are arrays/lookup tables.

The full per-field dump is in `04_工具与脚本/campaign2/out/parse_out.txt` (831 lines under
`(a)`), generated by `parse_s5_records.py` (source reproduced at the bottom of this file).

## (b) Record `0x005e` (videoformat) payload per blob

| blob | state | 14-byte payload |
|---|---|---|
| A | pal+mp4+0xc1 | `05 05 05 05 05 05 05 05 05 05 05 05 05 00` |
| B | == A | `05 05 05 05 05 05 05 05 05 05 05 05 05 00` |
| C | burst/photo | `05 05 05 05 05 05 05 05 05 05 05 05 05 00` |
| D | ntsc+**mov**+0x8b | `06 05 05 05 05 05 05 05 05 05 05 05 05 00` |
| E | ntsc+mp4+0x8b | `05 05 05 05 05 05 05 05 05 05 05 05 05 00` |
| F | == E (post-reboot) | `05 05 05 05 05 05 05 05 05 05 05 05 05 00` |

**Only `byte[0]` (file offset 3062) ever changes** — `0x05`=mp4, `0x06`=mov. Confirmed:
bytes[1..12] are `0x05` in all six blobs and `byte[13]` is the `0x00` terminator.

## (c) Interpretation of bytes[1..12]

`0x005e` is a **13-slot array + NUL terminator** (the generic shape of every "small" scalar
setting), where only slot 0 is the live/active value. Evidence that the 13 slots are a *shared
generic structure*, not a per-format layout:

| field | meaning (active) | slot 0 | slots 1..12 |
|---|---|---|---|
| `0x005e` | videoformat | `05`/`06` | all `05` (mp4) |
| `0x048f` | (flips with pal/ntsc) | `02`/`00` | all `02` |
| `0x0495` | ntsc_pal | `01`/`00` | all `00` |
| `0x0124` | videoquality | `0xc1`/`0x8b` | all `0x00c0` (disabled) |

So bytes[1..12] of `0x005e` are **twelve shadow slots, all holding the same value `0x05`
(mp4)**. They are *not* per-mode format defaults: the S5 recmode list has **10** unique values
(`program_ae, aperture_ae, shutter_ae, manual_exposure, creative_movie, slow_quick, c1, c2, c3,
ia`), which does not match 12 or 13, and every slot is identical rather than varying per mode.

The one concrete hint that the 12 slots are individually meaningful comes from the **S1M2
reference** (`07_参考仓库/s1m2-research/analysis/lumix_settings_structure.json`, tag `0x005e`,
`data_head_hex "5e001400010005060505050505050505"`): there, slot 1 held `0x06` (mov) while slot
0 = `0x05` and the rest = `0x05`. So the array is a per-slot format memory whose slots *can*
differ; in the S5's captured states they are all mp4. The most plausible reading is a fixed-width
"format × context" table (e.g. per system-frequency / per My-List entry), but there is **no
in-blob evidence tying any specific slot to any specific mode**, and the 10-recmode hypothesis
does not fit the slot count.

## (d) Constant-value candidates (step-5 scan)

Scanned every payload byte of every record in all six blobs for bytes `0x05`/`0x06`/`0x08` that
are *constant* across all six (Hank's byte-diff cannot see these, because they never move). Two
clearly different classes:

**Meaningful scalar candidates** (len=20, 13-slot shape, constant):
| field_id | payload | note |
|---|---|---|
| `0x0059` | `06 ×13` | constant mov-like value |
| `0x0164` | `08 ×13` | |
| `0x01ac` | `05 ×13` | constant mp4-like value |
| `0x01ad` | `05 ×13` | constant mp4-like value |
| `0x01e6` | `06 00×12` | slot 0 = `06`, rest zero |
| `0x034d`,`0x034e`,`0x034f`,`0x0350` | `06 ×13` | four adjacent constant mov-like values |
| `0x03a9` | `08 ×13` | |
| `0x03b2` | `06 ×13` | constant mov-like value |

**LUT/table noise** (large array records where `0x05/0x06/0x08` are the low bytes of u16 entries
inside repeated capability tables, e.g. `00 00 06 00 00 00 f0 00 5e 01 f4 01` or `63 08`/`40 08`
= `0x0863`/`0x0840`): `0x015b, 0x02e7, 0x02f9, 0x0343, 0x03f6, 0x03f7, 0x0402..0x040a, 0x043e,
0x0461, 0x0431, 0x0432, 0x043d` and siblings. These are **not** container fields.

**No field holds a format whitelist/mask/registered-list**: a scan for any constant record whose
payload contains *both* `0x05` and `0x06` (or `0x07` for MP4-HEVC) as an enumeration returns
**zero** hits. And the S1M2 research already concluded (offline) that `.DAT` record semantics are
100% firmware-confined — there is no host-side tag→name table — so the scalar `0x06`/`0x05`
fields above cannot be attributed a meaning without a single-variable A/B capture. Crucially,
**none of them changes on the mov↔mp4 switch**, so none is an *active* container mirror.

## (e) videoquality slots on the 0xc1↔0x8b switch

Only **slot 0** changes (`0x00c1` ↔ `0x008b`). Slots 1..12 stay `0x00c0` (disabled sentinel) in
every state (blob C's extra `0x00c1` at slot 11 is burst-state noise, per the task). There is
**no per-format quality memory** paired with a per-format container slot — the quality array's
12 shadow slots are all disabled.

## (f) Recommendation — what to set for mov to survive a power cycle

**There is no second/boot-default container field anywhere in the blob.** The container is one
byte: field `0x005e`, slot 0 = **file offset `3062` (`0x0bf6`)**. The value-based scan found no
constant field that acts as a separate "factory default container", "format whitelist/mask", or
"registered format list".

To persist mov across a power cycle the only byte that carries the container is `3062`, so:

1. Set **offset `3062` (`0x0bf6`) = `0x06`** (mov).
2. Recompute the **checksum byte at `0xfffc`** so `sum(blob) % 256 == 0` (the only other byte
   that changes on the format switch).
3. Write the **full 65533-byte blob to flash** (valid `sum%256==0`), *not* a RAM `setsetting`.
   Empirically the mov value captured in `diff_blob_mov.bin` was RAM-only: on reboot (blob F)
   `3062` reverted `06→05` while the quality code `0x8b` persisted — i.e. `videoformat` is a
   boot-re-initialised "menu visibility" flag, whereas `videoquality` survives.

**Open caveat (honest uncertainty):** the 12 shadow slots at offsets `3063..3074` (`0x005e`
bytes[1..12]) are all `0x05`. The captured mov RAM state left them at `0x05` and the camera
still entered mov, so they are *not* the active value. If the firmware at boot re-derives the
container from a per-slot memory (as the S1M2 slot-1=`0x06` hint suggests), then for full
coverage one may also set offsets `3063..3074 = 0x06`. This is not required by any evidence we
have, but it is the only additional, non-destructive change that could plausibly matter, and it
is worth one controlled experiment (flash the blob with all 13 slots = `0x06` vs. slot 0 only)
to settle it.

## Parsing script

`04_工具与脚本/campaign2/out/parse_s5_records.py` (reproduced in full):

```python
#!/usr/bin/env python3
"""Parse S5 camsetting blobs' TLV record stream and analyze fields.

Stream layout (verified): 44-byte header (0x00..0x2b: "Panasonic" + "DC-S5")
+ 8-byte sub-header `cc ff 00 00 00 03 00 00` (0x2c..0x33, identical across
all six blobs) + 831 TLV records (0x34..0xfff7, first is tag 0x0001 = model
identity = 13x u16 0x0049 'I') + 4-byte trailer `ff ff 00 00`
(0xfff8..0xfffb) + 1-byte checksum (0xfffc, the last byte).

Record = [field_id u16 LE][len u16 LE][flag u16 LE][payload: len-6 bytes].
"""
BLOBS = {
    "A": "06_数据与证据/camera_settings/camsetting.bin",
    "B": "01_研究报告/03_隐藏格式_可分发版_20261012/reference/camsetting.bin",
    "C": "01_研究报告/01_固件AES绕过_调研_20261010/03-离线破解与上传预言机/oracle/burst_183125/live_camsetting_full.bin",
    "D": "04_工具与脚本/campaign2/out/diff_blob_mov.bin",
    "E": "04_工具与脚本/campaign2/out/diff_blob_mp4.bin",
    "F": "04_工具与脚本/campaign2/out/blob_postreboot_20261013_000547.bin",
}

START = 0x34  # first record (after 44-byte header + 8-byte sub-header)
TRAILER = 0xfff8
CHECKSUM = 0xfffc


def parse(blob: bytes):
    recs = []
    off = START
    n = len(blob)
    while off + 6 <= TRAILER:
        field_id = int.from_bytes(blob[off:off+2], "little")
        rlen = int.from_bytes(blob[off+2:off+4], "little")
        flag = int.from_bytes(blob[off+4:off+6], "little")
        if rlen < 6 or off + rlen > n:
            raise SystemExit(f"bad record @0x{off:04x} fid=0x{field_id:04x} rlen={rlen}")
        payload = blob[off+6:off+rlen]
        recs.append((off, field_id, rlen, flag, payload))
        off += rlen
    assert off == TRAILER, f"ended 0x{off:04x}, expected 0x{TRAILER:04x}"
    return recs


def main():
    parsed, raw = {}, {}
    for name, path in BLOBS.items():
        with open(path, "rb") as f:
            blob = f.read()
        assert len(blob) == 65533 and sum(blob) % 256 == 0, name
        raw[name] = blob
        parsed[name] = parse(blob)

    # (a) consolidated field dictionary
    print("=== (a) consolidated field dictionary ===")
    fields = {}
    for name, recs in parsed.items():
        for off, fid, rlen, flag, payload in recs:
            d = fields.setdefault(fid, {"n": 0, "lens": set(), "flags": set(),
                                        "payloads": {}, "offs": {}})
            d["n"] += 1
            d["lens"].add(rlen)
            d["flags"].add(flag)
            d["offs"][name] = off
            d["payloads"].setdefault(payload.hex(), []).append(name)

    n_fields = len(fields)
    n_variant = sum(1 for d in fields.values() if len(d["payloads"]) > 1)
    print(f"total distinct field_ids: {n_fields}; fields with >1 payload variant: {n_variant}\n")
    for fid in sorted(fields):
        d = fields[fid]
        const = len(d["payloads"]) == 1
        status = "CONST" if const else f"{len(d['payloads'])} variants"
        print(f"0x{fid:04x} len={sorted(d['lens'])} flag={sorted(d['flags'])} "
              f"blobs={d['n']} [{status}]")
        if not const:
            for ph, names in sorted(d["payloads"].items(), key=lambda kv: kv[1]):
                print(f"      {ph} <- {','.join(names)}")

    # (b) record 0x005e
    print("\n=== (b) record 0x005e (videoformat) payload per blob ===")
    for name, recs in parsed.items():
        for off, fid, rlen, flag, payload in recs:
            if fid == 0x005e:
                print(f"{name}: off=0x{off:04x} len={rlen} flag=0x{flag:04x} "
                      f"payload({len(payload)}B)={payload.hex(' ')}")
                print(f"        bytes[0..13]= {[b for b in payload]}")

    # (c) 0x048f and 0x0495
    print("\n=== (c) records 0x048f / 0x0495 per blob ===")
    for target in (0x048f, 0x0495):
        for name, recs in parsed.items():
            for off, fid, rlen, flag, payload in recs:
                if fid == target:
                    print(f"0x{fid:04x} {name}: off=0x{off:04x} len={rlen} "
                          f"payload({len(payload)}B)={payload.hex(' ')}")

    # (d) 0x0124 videoquality (13 u16 slots, NOT 16 as earlier fieldmap claimed)
    print("\n=== (d) record 0x0124 (videoquality) per blob ===")
    for name, recs in parsed.items():
        for off, fid, rlen, flag, payload in recs:
            if fid == 0x0124:
                vals = [int.from_bytes(payload[i:i+2], "little")
                        for i in range(0, len(payload), 2)]
                print(f"{name}: off=0x{off:04x} len={rlen} ({len(vals)} u16 slots) "
                      f"slots={[hex(v) for v in vals]}")

    # (e) constant container-like byte scan
    print("\n=== (e) constant 0x05/0x06/0x08 bytes across all six blobs ===")
    offmap = {}
    for name, recs in parsed.items():
        for off, fid, rlen, flag, payload in recs:
            for i in range(off + 6, off + rlen):
                offmap.setdefault(i, (name, fid, i - (off + 6)))

    hits = []
    for i in range(START, CHECKSUM):
        vals = {raw[n][i] for n in raw}
        if len(vals) == 1 and next(iter(vals)) in (0x05, 0x06, 0x08):
            hits.append((i, next(iter(vals))))
    print(f"total constant container-like bytes in payload region: {len(hits)}")
    for i, v in hits:
        owner = offmap.get(i)
        if owner:
            name, fid, poff = owner
            print(f"  0x{fid:04x} payload_off={poff:2d} file_off=0x{i:04x} = 0x{v:02x}")
        else:
            print(f"  <preamble/trailer> file_off=0x{i:04x} = 0x{v:02x}")


if __name__ == "__main__":
    main()
```

## Single most important finding

The container is **one byte — field `0x005e` slot 0 = offset `3062` (`0x0bf6`)** — and there is
**no boot-default container, format whitelist, or registered-format-list field anywhere else in
the blob**. To make mov survive a power cycle, flash the full blob with `3062=0x06` and a valid
`sum%256==0` checksum; the only defensible extra (unproven) change is to also set the 12 shadow
slots `3063..3074=0x06`.
