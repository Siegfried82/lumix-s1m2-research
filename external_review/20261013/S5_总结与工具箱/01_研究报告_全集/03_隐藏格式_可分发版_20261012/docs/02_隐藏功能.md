# 隐藏功能：hlg=8k 与 mp4hevc 隐藏档

> "启用但未声明"的隐藏值：curmenu（当前启用项）里 `enable=yes`，
> 但 allmenu（固件声明词表）里**根本没列出来**。这类值是"有本机证据"的隐藏档，不是盲猜。

两个用户重点关注的隐藏功能：`hlg=8k` 与 `videoquality=mp4hevc_25p_72mbps_4k_10bit`。

---

## A. hlg=8k（HLG 照片）

**证据**
- allmenu 里 `hlg` 只声明 `full / 4k / off` 三档。
- curmenu 里存在 `hlg_photo_8k` 且 `enable=yes` → **本机启用了一个 allmenu 未声明的 8k 档**。

**实测（`hidden_test_hlg.py`，play 模式）**
```
基线 hlg = 'off'
setsetting hlg=8k -> 'ok'          # 写入被"接受"（返回 ok，非 err_param）
读回#1 hlg = 'off'                 # 但读回仍是 off
读回#2 hlg = 'off'
判定: 相机未接受（读回='off'，可能模式门控或拒绝）
回滚 hlg=off -> 'ok'  ✓ 已恢复
```

**结论**
- setter 层面**接受**该值（`ok`），但**在照片/回放(play)模式下不生效/不持久**（读回仍 off）。
- 属于**模式门控**：需在**照片(静态)拍摄模式**下才能真正写入并成像。
- 旁证：即使是已声明的 `full`/`4k`，在 play 模式下也不持久 —— 说明整个 hlg 域在 play 模式都是"只读回显"，非"可写生效"。

**下一步（需用户配合）**：把相机切到**照片模式**，重跑 `python3 hidden_test_hlg.py`，
并实拍一张 HLG 照片取文件核对。脚本已就绪，安全（自动回滚）。

## B. mp4hevc 隐藏档（HEVC 视频）

**证据**
- curmenu 里 `videoformat_mp4hevc` 存在但 `enable=no`（play 模式未开）。
- HEVC 质量档（`mp4hevc_*`）是**门控值**：必须先开 `videoformat=mp4hevc` 这道门，
  再设 `videoquality=mp4hevc_*` 才会被接受。

**门控规律（实测 gate_test，play/NTSC 模式）**
```
WRITE videoformat=mp4hevc -> err_reject      # play 模式不允许开门
READ  videoformat -> mp4                     # 仍是 mp4
WRITE videoquality=mp4hevc_30p_72mbps_4k_10bit -> err_reject
READ  videoquality -> mp4_60p_28mbps         # 未变
```
→ **play 模式连"开门"都被拒**。门控依赖**视频/录像(rec)模式**。

**HEVC 隐藏值清单（NTSC / PAL）**

| 制式 | 值 |
|---|---|
| NTSC | `mp4hevc_30p_72mbps_4k_10bit` / `mp4hevc_24p_72mbps_4k_10bit` |
| PAL  | `mp4hevc_25p_72mbps_4k_10bit`（PAL 原生） |

> 本机当前基线为 **NTSC**（`videoquality=mp4_60p_28mbps`），故 `25p`（PAL 原生）在本机
> 可能被拒。脚本 `hidden_test_mp4hevc.py` 的 `TARGET` 常量默认为 `25p`，
> **切到 NTSC 拍摄时请把 TARGET 改成 `mp4hevc_30p_72mbps_4k_10bit` 或 `24p`**（改一行即可）。

**测试方法（`hidden_test_mp4hevc.py`，需 rec 模式）**
1) 健康预检 → 2) 读基线(videoformat=mp4, videoquality=mp4_*) →
3) 开门 `videoformat=mp4hevc`（若 err_reject 说明不在 rec 模式，脚本自动跳过并只读收工）→
4) 设档 `videoquality=mp4hevc_*` → 5) 读回 x2 判定 →
6) 回滚：先关门 `videoformat=mp4`（相机自动把 quality 归位），若未回基线则显式写回 →
7) 健康复查。

**结论（◐ 强证据，待 rec 模式闭合）**：机制与门控规律已实证；
在**视频/录像模式**下开门+设档应能接受，**实际成像**需实拍确认。

>（两者 play 模式 enable=no）。

## 安全提醒

- 两个测试脚本都**严格可逆**：记录基线 → 写入 → 读回 → **自动回滚并验证** → 健康复查。
- **绝不批量写**；每次写后 sleep ~1.2s 再读回；只动相关域，不碰其它。
- 写操作有风险（相机易卡死）：先接交流电源、确认在线、读完 [06_安全约束](06_安全约束与风险.md) 再跑。
