# 安全约束与风险（务必先读）

> **这台相机非常脆弱：会卡死 / 硬挂，且只能拔电池恢复**（研究中已发生多次）。
> 所有操作都以此为前提。**先接交流电源，再动手。**

---

## A. 红线（绝不做）

- ✗ **绝不刷写固件**、不碰 `fw_update_mode` 相关写、不做 `resetDevice`。
- ✗ **绝不**发 PTP 配置写 / `0x9406` 副作用子码 / 长度不匹配的 PTP 包（USB 侧）。
- ✗ **绝不连发 `req_acc`**；**绝不**在已 `ok` 的会话上发 `req_acc_can` 去打断它。
- ✗ **绝不**在 `getstate` 非 `ok`（相机异常）时继续任何写操作。
- ✗ **绝不**把相机留在"非基线"状态就断开——**每次写后必须回滚并验证**。

---

## B. 写操作纪律

1. **健康前置**：任何写前，`state_check.py` 必须 `UP/OK`。
2. **写后复查**：每次 `setsetting` 后 **sleep ~1.2s 再读回**核对。
3. **必回滚**：记录基线 → 写 → 读回 → **回滚到基线 → 读回验证**，四步缺一不可。
4. **健康守卫**：每个写批次后跑一次 `getstate`；若非 `ok`，**立即停手**，按 C 恢复。
5. **一次只动一个域**：不批量写、不并发写；只动目标域，不碰其它。
6. **节奏**：请求间留间隔（脚本 `pace` 默认 ~0.35s），不要打满。

---

## C. 卡死 / 无响应恢复流程

1. **立即停止**所有脚本（Ctrl-C）。
2. **拔电池** → 等 ~30s → 重插 → 开机。
3. 等相机连上 Wi-Fi（~30s）。
4. `python3 state_check.py --ip $S5_IP` 确认 `UP/OK`。
5. 若仍 `err_unsuitable_app`，跑 `safe_handshake.py --verify`（相机上按 OK）。
6. **确认相机在基线**（读回关键域=基线值）后，再继续。

> 若相机反复卡死，说明当前操作触发了不稳定路径——**降级到只读**，不要再写。

---

## D. 只读 vs 写（风险分级）

| 级别 | 操作 | 说明 |
|---|---|---|
| 🟢 安全 | `getstate` / `getsetting` / `getinfo` / 各 recon / fingerprint / surface_probe | 只读，可反复跑 |
| 🟡 注意 | `safe_handshake.py`（req_acc / req_acc_can） | 会改变会话态；按 01 的规则用，别连发 |
| 🟠 风险 | `hidden_test_hlg.py` / `hidden_test_mp4hevc.py` / 6K 激活配方 | 单点可逆写；接电源、确认模式、必回滚 |
| 🔴 高风险 | `enum_videoquality.py --confirm` | 批量写；仅在明确授权 + 接电源 + 基线核对后 |
| ⛔ 禁止 | 固件刷写 / reset / PTP 副作用写 / 连发 req_acc | 见红线 A |

---

## E. 会话污染（"invalid login"）防护

- 根因：未清理的 `req_acc` 留下【陈旧 pending 请求】污染下一会话（详见 [01](01_版本门与握手修复.md)）。
- 防护：
  - 整个握手用**同一 uuid**；终止路径用同一 uuid 发 `req_acc_can` 清理。
  - 手机 App 与脚本**不要同时**连相机（会 `err_others_requesting` 互相抢会话）。
  - 出现 `err_unsuitable_app` 立即用 `safe_handshake.py` 恢复，**不要**硬着头皮继续写。
