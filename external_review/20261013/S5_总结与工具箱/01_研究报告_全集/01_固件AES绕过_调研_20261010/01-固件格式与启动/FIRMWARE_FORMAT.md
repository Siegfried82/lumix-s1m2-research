# DC-S5 固件 .bin 格式（UPD 容器）逆向结果

对象：`S5___V29.bin`（90,238,464 字节 = 0x560EE00，芯片 MC801）
对比样本：`S5m2_V31.bin`（205,683,712 字节，芯片 MC8223），格式一致。

## 总体布局

| 偏移 | 大小 | 内容 |
|---|---|---|
| 0x000000 | 0x200 (512) | 外层 UPD 头 |
| 0x000200 | 0xA0 | `"panasonic"` 标记 + 64B ECDSA P-256 签名（32B r + 32B s）+ 填充 |
| 0x0002A0 | 0x40 (64) | 内层 UPD 头（与外层字段一致） |
| 0x0002E0 | 0x0C (12) | 目录头（数据起点/总长/校验尺寸） |
| 0x0002EC | 0x1140 | 分区表：48 条 × 92 字节（物理至 0x142C，与数据起点 0x1400 重叠 44B） |
| 0x001400 | 0x560D800 | 分区数据（多数加密；前 44B 被分区表尾覆盖，见「分区表条目」节） |
| 0x560EC00 | 0x200 (512) | RSA-4096 签名（= S5___V29.sig 内容） |

## UPD 头（外层 0x000 / 内层 0x2A0，共 0x40 有效字段）

```
0x00  u32  0x00445055  "UPD\0" 魔数
0x04  u32  0x200       头部大小
0x08  u32  0x200       （重复，含义同 0x04）
0x0C  char[8]          芯片型号 "MC801"（S5M2 为 "MC8223"）
0x14  u32  0
0x18  u32  0
0x1C  u32  0x02900290  两个 u16：0x0290,0x0290（机型/板号）
0x20  u32  0x00010004  两个 u16：0x0004,0x0001
0x24  u32  0x07101450  时间戳/版本
0x28  u32  0
0x2C  u32  3           （loader 数量？）
0x30  u32  0
0x34  u32  3
0x38  u32  0x200       数据起始偏移
0x3C  u32  0x0560EC00  数据总长（= 文件长 - 0x200）
0x40  u32  CRC32       zlib.crc32(data[0x200:]) 实测吻合
```

## 目录头（0x2E0）

```
0x2E0  u32  0x1400      分区数据起点
0x2E4  u32  0x560D800   分区数据总长（起点+总长 = 文件长 - 0x200，即签名前）
0x2E8  u32  0x30        每条目校验块尺寸 = 48 字节
```

## 分区表条目（每条 92 = 0x5C 字节，共 48 条，0x2EC 起）

```
0x00  char[12]  名称（'\0' 填充）
0x0C  u32       数据偏移（文件内绝对偏移）
0x10  u32       大小
0x14  u32       目的加载地址（RAM）；loader1/2/3 上=数据区相对偏移（0x0/0x1000/0xA800），非 128KB 对齐 flash 地址
0x18  u32       类型（2=明文数据区，3=加密区；与 IV 零/非零 48/48 完全吻合）
0x1C  char[32]  SHA-256(明文) 摘要（仓库 cross-version 差分确证）
0x3C  char[16]  每分区独立 IV（加密分区非零且唯一；数据分区全 0）
0x4C  char[16]  填充（全 0）
```

相邻条目满足 `偏移[i] + 大小[i] == 偏移[i+1]`（tiling 已验证连续）。

## 结论

- 容器格式（外层头、内层头、目录、48 分区表、RSA 签名尾块）已全部逆向，无未知字段影响解析。
- 分区表物理终点 0x142C（48×92=0x1140），与数据起点 0x1400 重叠 44B：末项 `hr_c_ddr` 的 SHA-256 尾 12B（`45c07d28 0ba270b9 996963c6`）+ IV 16B（`ff0bebb9 56078576 a4678df1 ea86c71b`）+ 零填充 16B。
- **boot 文件类型与启动链**（90KB 连续引导块、loader1→2→3→program 链、RAM 用途图、type=加密标记、与 Milbeaut 参考链对照）详见 `BOOT_FLOW.md`。
- 代码/数据分区（loader2 起、zimage、rootfs1/2、dtb、program、DSP 分区）均为高熵随机数据（熵 ≈7.8），**加密**，无 ELF/gzip/squashfs 等明文魔数。
- 反编译这些文件前必须先解密；加密算法与密钥尚未确定。

## 跨版本/跨机型验证补充（来自 lumix-s1m2-research 仓库，已在本机只读复现）

- 条目 `0x1C` 的 48 字节 = **32 字节 SHA-256(明文) + 16 字节每分区独立 IV**（不是 SHA-384 摘要）。S5 上实测：`lens_hist` 命中 SHA-256 阳性对照；41 个加密分区 IV 非零且唯一，7 个数据分区 IV 全零。
- `0x220` 的 64 字节块 = **ECDSA P-256 签名**（机内 BootROM 公钥验签），不是 IV/密钥材料。
- 三平台对照：S5=MC801、S5M2=MC8223、S1M2=MC8243（Socionext Milbeaut M20V）。UPD 封装同族，但加密算法/密钥按平台隔离，不通用。
- 离线破解路线已被社区穷举排除（含 GH2 自嵌式密钥法移植、AV 固定 key、SL3 交叉、13 万+ 探测）；结论是**密钥固化在芯片硬件（OTP/eFuse/Crypto Engine/TrustZone），固件文件内无密钥材料**。软件离线解密不可行，需硬件提取。
