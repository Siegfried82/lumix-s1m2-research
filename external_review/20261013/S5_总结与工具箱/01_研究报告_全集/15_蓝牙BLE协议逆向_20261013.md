## 3. 连接与握手时序（`E5/j.java j()`）

1. 连接 GATT（20s 超时）→ `onConnectionStateChange` 状态 0/2 才算成功
2. `discoverServices()`（20s）
3. **`A()`：按上表注册全部通知（写 CCCD）**
4. 若 `isUUIDApsSupported`（有 `bb5d2a8c`）：
   - **读 idx35 INITIAL_INFORM** → `p154t5.b.e()` 取前 4 字节大端 = **会话密钥** → 存起来
   - **写 idx16**（`bb5d2a8c`）= `s.d(DLNA_UUID, key, 20)`
   - **写 idx17**（`7b61774f`）= `s.c(friendlyName, key, 20)`
   否则走非 APS 分支：写 idx1（`8d08a420`）、idx2（`cd7a71a0`）
5. **读 idx5 CAMERA_SSID** → `s.a(data, key)` 解码 → SSID
6. **读 idx6 CAMERA_WIFI_PASSWORD** → `s.a(data, key)` 解码 → **相机 Wi-Fi 密码**

## 4. 加解密（`H5/s.java` + `p154t5/b.java`）

- **密钥**：`p154t5.b.e(INITIAL_INFORM)` = 前 4 字节按 **大端** 拼成 32 位；全 0 时用默认
  **`0x9032782C`**（即 Java 的 `-1875740628`）。
- **算法**：不是流密码，是 **"字节置换 + 32 位 XOR"**，4 字节一块：
  - 解码 `s.a(data, key)`：块内 `v = b3<<24|b2<<16|b1<<8|b0` → **字节序翻转** → `^key`；
    首块只输出 3 字节（跳过 1 字节），其余每块输出 4 字节；遇 `0xFF` 截断。
  - 编码 `s.c(str,key,20)` / `s.d(bytes,key,20)`：定长 20 字节缓冲，
    `[len][ASCII...][padding 0xFF]` → 反向置换 + `^key`。
- 已用 Python **复刻并自检通过**（`encode("DC-S5")` → `decode` 还原一致）。

## 5. ⚠️ 安全结论（**已根据实机结果更正**）

**代码层**看，这条链是"无配对即可取 Wi-Fi 凭据"；但**实机验证推翻了它**：

| 实验 | 结果 |
|---|---|
| 连接 + 完整枚举 GATT（41 个特征） | ✅ 允许，**不需要配对** |
| **空闲不发读**，保持 25 s | ✅ **连接稳定，无自发断链** |
| **发出任意 `readValue`** | ❌ **相机立即主动断链**（"device has disconnected from us"） |
| 相机进入**蓝牙配对模式**后再试 | ❌ 行为完全相同（仍一读即断） |
| macOS 侧是否发起绑定 | ❌ 日志中**没有任何配对/绑定尝试** |

**判定**：相机对**未加密链路**的属性读**一律拒绝并断链**。
macOS 的 CoreBluetooth 没有把它当作"需要认证"来处理（正常应回 `Insufficient Authentication`
并触发配对），而是直接被对端关链路 → 无法自动建立绑定。

⇒ **不能宣称"近场任意设备可无认证读取相机 Wi-Fi 凭据"**。该结论**未获实机支持，予以撤回**。
真实的安全姿态是：**连接与枚举开放；读取需要加密/绑定链路**（相机在配对模式下也坚持这一点）。
要到"能读"的状态，需要**在系统层与相机完成 BLE 绑定**（iOS/Android 上由 App+系统自动完成；
macOS 的 CoreBluetooth 在本例中未能触发）。
