# Panasonic LUMIX DC-S1R2 相机 — 已排除路线与风险备忘（给同事）

> 整理：2026-10（由 AI 会话沉淀）。目标：解开固件加密 / 拿 root / dump 运行内存。
> 本文件只讲"结论 + 为什么"，完整证据见同目录各漏洞报告。

---

## 一、一句话结论

- **固件 AES 密钥固化在芯片硬件里**（OTP/eFuse/Crypto Engine），**离线解不开**。
- **软件攻击面已挖穿**：有实打实的漏洞（越界读写 + 持久 DoS），但**没有 RCE**。
- **真正能拿到固件明文的路只有硬件调试（JTAG）**，核心思路是：**不需要密钥，只需要"开机后 DDR 里的运行时明文"**。

---

## 二、已确认的成果（硬通货，可上报）

| 漏洞 | 性质 | 状态 |
|---|---|---|
| **F1/F2：`f_fs.c` 内核越界读写** | `SET_INTERFACE(wIndex 高字节)` 越界写/读 `current_alt_setting[16]` | ✅ 实机验证；影响 **S1R2 / S9 / S1M2** 三机型 |
| **UVC 零长度控制请求 → 持久 DoS** | 网络摄像头模式下，向 VS probe 发 `SET_CUR(wLength=0)` → 守护进程整体挂死，**跨断电不恢复**，须出厂重置 | ✅ 三段式对照复现 |
| 一批 DoS | PTP 容器、Flow XML 长度、配置导入等 | 已记录 |

## 三、已排除 / 判定为死路或高风险的路线（重点）

### ❌ 1. 软件远程入口（USB PTP / Flow / WiFi / BT / HTTP）
全部 fuzz 过：只有 DoS，**无 RCE**。富输入的解析器（Flow XML、配置导入）都被"格式门控"挡死，格式已丢失。

### ❌ 2. UART 串口（拆机读串口）
**死路**——三个证据叠加：
- U-Boot `CONFIG_BOOTDELAY=-2`（**无控制台、无延迟**，注释明说"改成 0 才开控制台"）
- 内核 `console=null loglevel=0`（**Linux 也无串口输出**）
- U-Boot 环境变量 `ENV_IS_NOWHERE`（**不存储、改不了**）
- 结论：接了 UART 也是黑的。

### ⚠️ 3. SD.DAT / ROM-flashing 恢复模式（Milbeaut 的"EDL 模式"）
**高风险，别碰**：
- SD.DAT **没有"只读/RAM boot"模式**，它是烧写器，想跑代码**必须写 flash**。
- **写错 `pardata.par` = 不可逆毁掉出厂标定数据**（变砖且救不回）。
- 松下触发组合**无公开资料**。
- S1R2 用 **NAND**（GoPro 是 eMMC），NAND 路径**在 GoPro 上从未验证成功过**。

### ⚠️ 4. `legacyboot`（U-Boot 从 SD 卡引导自定义内核）
- 命令存在（`fatload mmc 0 KERNEL.BIN/DTB.BI/RAMFS.BIN; booti`），
- 但**默认 bootcmd 不用它**，且需要 U-Boot 控制台才能调（而控制台被第 2 条堵死了）→ 用不上。

### ⚠️ 5. 服务模式组合键（松下传统）
- 松下确实有"多键同时开机"进服务模式的传统：**GX85 = `[回放]+[AF/AE LOCK]+[右键]` 开机；ZS30 = `录像+MENU/SET` 开机 → 屏显 SERVICE MODE**。
- **S1R2 的组合键：无任何公开资料**（零风险，可继续试）。

### ⚠️ 6. 配置文件导入（`0x9422`）/ Flow XML
- 都是"格式门控"，且格式不在 App 里、在加密固件里 → 进不了解析器。

## 四、仍未排除、相对可行的路

| 路线 | 可行性 | 说明 |
|---|---|---|
| **JTAG** | ✅ 最可能 | 硬件级调试、不需要控制台；halt CPU 后 **dump RAM = 解密后明文**。需**拆机 + 找 JTAG 焊点**（当前主板照片分辨率不够，测试点未确认） |
| **服务模式组合键** | 零风险可试 | 见 §三.5 |
| **MDR 寄存器读引导来源** | 需先有代码执行 | `STRICT_DEVMEM` 关闭，若有代码执行可用 `/dev/mem` 只读 `0xd150000` 反推引导/strap 状态 |
| **零风险探针** | 可做 | 相机开机/进菜单时会枚举 SD 根目录做固件文件名匹配（官方"卡里 2 个固件文件会导致不识别"可证），是"相机读不读我放的文件"的探针 |

## 五、关键地址备忘（来自官方 OSS 源码，已证实）

- SoC：Socionext Milbeaut **SC2006A**，板级 `pvc04v-MC8259`
- 存储：**Cadence HP-NFC NAND**（`emmc@19810000` 在 DT 里是 disabled）
- SD：`sd0: mmc0@19830000`
- UART：U-Boot 控制台 = **serial7 @ 0xe700070**；Linux = **uart1 @ 0xe700010**（但 `console=null`）
- bootargs：`nokaslr loglevel=0 console=null nr_cpu=1`
- 引导模式寄存器：**MISCTOP.MDR @ 0xd150000**

---

## 六、给同事的一句话建议

**别在软件面和 SD.DAT 上浪费时间了。** 最该做的是：**拆机 → 拍高清主板正反面照片 → 找 JTAG/UART 测试点 → JTAG dump RAM 拿明文**。JTAG 是当前唯一"确定能到终点"的路。
