# 11 · 安全约束（硬性规则，务必遵守）

> 相机**极易砖**（本会话已多次 brick / 卡死），恢复只能靠**拔电池**。以下规则是"不造成不可逆损坏"的底线，任何实验必须满足。

## 11.1 电源与恢复

- **AC 常供电**：任何可能触发 ~31s 定址 / 卡死 / 流送的实验，**必须**接 AC 电源（电池供电 + 大镜像流送 = 高 brick 风险）。
- **恢复手段唯一 = 拔电池**：相机卡死 / brick 后，**拔电池（断电）重启**是唯一可靠恢复方式。
- 实验前确认：相机开机、AC 接好、能随时拔电池。

## 11.2 绝对红线（NEVER）

1. **绝不真刷固件**：`S5___V29.bin` 仅为 **RECOVERY-ONLY**，**永不**让相机真正落盘刷写它。
2. **绝不 `resetDevice`**（会触发整机重置 / 潜在 brick）。
3. **绝不执行 PTP 配置写回**（`0x9422` / `0x9423`）。
4. **绝不执行 `0x9406` 的带副作用子码**（保存/格式化/升级准备/完成/除尘/坏点刷新/升级中止/全量重置）与 `0x940d`（电源）。
5. **绝不发送 length 不符的 PTP 包**，除非是**最后的、已授权**的 length-DoS 演示（跑完需拔插 USB 恢复）。

## 11.3 每次探测后的健康守卫

- 每个探测 / 上传阶段后：`GET /cam.cgi?mode=getstate` → 必须 `ok`。
- 若掉线：**等待 ≤180s** 让它自行恢复；超时未恢复则**停止**并拔电池。
- 上传类实验：用 `finalfix.py` **手动驱动**末块，**不要用 `Upload.stream()`**（它的 12× 重试风暴 + `abortsenddata` 会关闭会话、驱动状态机进未处理分支 → 卡死）。

## 11.4 同版本对照实验的安全性

- **同版本（2.90）对照流送是相对安全的**：最坏情况是相机拒绝 / 重启进**相同的 2.90**，不会降级。
- **跨版本 / 改版本 / 改内容（Phase J data-flip）= 高 brick 风险**，**必须用户明确授权**后才执行。

## 11.5 实验前检查清单

- [ ] 相机开机、AC 供电、可拔电池
- [ ] `getstate` → `ok`（确认在线 + 健康）
- [ ] 确认本次操作**不触碰** §11.2 红线
- [ ] 上传类：用 `finalfix.py` 手动驱动，末块单次
- [ ] 崩溃/DoS 类：预留"拔电池恢复"时间，不连续猛打

## 11.6 数据 / 会话卫生

- 先单独 `getstate` 确认健康，避免把"残留会话导致的 `err_reject`"误判为"离线"（§08.4）。
- CAMSET 写实验：写完**回写原值**即安全（可逆）；不要长期停留在改过的设置态。
- 原始日志 / dump 保留在 `logs/`、`data/`，便于复现与审计。
