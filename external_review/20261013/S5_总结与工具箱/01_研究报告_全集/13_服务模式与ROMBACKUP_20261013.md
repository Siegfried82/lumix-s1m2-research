## 2. LUMIX 服务模式常见项（据 S1M2 维修手册分析 + 松下服务手册传统）

> 以下为同族机型的通用清单，**S5 逐项名称以用户实拍为准**；标 ⚠️ 的是危险项。

| 项 | 作用 | 风险 |
|---|---|---|
| **ROM BACKUP** | 把 Flash-ROM 里的**校准/参数分区**（Factory Data）导出到 SD 卡 | 读为主，相对安全 |
| ROM WRITE / FACTORY DATA WRITE | 把备份数据**写回**覆盖 | ⚠️ 写错=不可逆 |
| **ERR CODE DISP** | 循环显示历史错误码（约 16 条） | 只读 |
| VERSION / VERSION UP | 版本显示 / 升级 | ⚠️ 升级有风险 |
| ADJUST / CALIBRATION | 法兰距、AF、BIS 防抖、快门等**校准** | ⚠️ 破坏性 |
| INITIAL SETTINGS / CANCELLATION | 解除初始设置（许多项的**前置门**） | ⚠️ 改持久状态 |
| REGION / MODEL SUFFIX | 地区后缀选择 | ⚠️ **单次写入锁止**，选错可能永久锁死 |
| FLAG SET（all flags → 'F'） | 清/改标志位 | ⚠️ 破坏性 |

## 3. ROM BACKUP 到底是什么（据 S1M2 维修手册）

手册原文（S1M2 第 8 页 3.4.2 / 第 74 页 10.1）要求：

> *"After releasing the initial settings, download the Flash-ROM data using the menu ROM BACKUP function."*
> *"After releasing the initial settings, change the setting of all flags to 'F' using the menu ROM BACKUP function."*

由此确认：

1. **它是固件内建的隐藏功能**，不需要外部调整软件下发专有指令。
2. **导出的是 Flash-ROM 中的校准与参数分区**（法兰距、BIS、快门参数、机身序列号等 Factory Data），
   **不是**完整操作系统/专有程序的明文，更不是 AES 密钥（密钥在 MC801 片内 OTP）。
3. 用途：主板更换前后保留/回写出厂标定，避免重新全量校准。
4. 前置条件：手册流程明确是**先"解除初始设置（Initial Settings）"**，并按需释放 **Strict 模式**
   （部分机型为 `DISP` 键解除），之后相关项才可用。

## 4. ROM BACKUP 变灰的可能原因（按可能性排序，**待 S5 手册核实**）

1. **Initial Settings 未解除 / Strict 模式未释放** —— 最可能。仅进入服务模式不够，
   手册流程要求先做"解除初始设置"（通常是一组多键开机 + 关机时屏闪 `!` 警示符）。
2. **SD 卡条件不满足** —— ROM BACKUP 要写卡：需 FAT 格式、剩余空间足够、且可能限定某个卡槽
   （本机 `current_sd=sd2`）。
3. **供电** —— 部分服务项要求 AC 适配器；当前电量 5/5，建议接 AC。
4. **主板已被视为"已配置"** —— 地区后缀一旦写入即锁定，某些导出项随之关闭。
5. **零售固件不含导出例程** —— 若该功能只在服务固件中存在，灰态将永久保持。

用户反馈：**点 ROM BACKUP 无任何提示文字**（灰态）。这与第 1 条最吻合——菜单项的可用性由
"是否已解除初始设置"这一状态位门控，而不是运行时校验。

## 5. 对本项目的意义

- **不是**固件解密/密钥路径：ROM BACKUP 只导出标定与参数分区，拿不到内核/业务程序明文或 AES 密钥。
- **可能有价值**：导出的参数分区若含机型/地区/能力标志，可与 camsetting 交叉印证；
  但价值远低于 JTAG dump RAM（运行时明文）。
- **风险**：服务菜单同屏就有破坏性项（ROM WRITE / ADJUST / REGION）。**本项目红线：只读不动写**。

### 7.4 ROM BACKUP 为何是灰的（结合实拍再判定）

菜单里 `Language Change` / `SCREEN CAPTURE` / `VERSION INFO DISP` / `ERR CODE DISP` 都可用，
**只有 ROM BACKUP 被单独门控** → 说明不是"服务模式没进对"，而是**缺某个前置状态**。
按 S1M2 维修手册流程（p13–15、p7–8、p73–74），最可能是：
**尚未执行"解除初始设置（Cancel Initial Settings）"并释放 Strict 模式**。
其余可能：SD 卡格式/剩余空间、AC 供电、主板已被视为"已配置"、或零售固件不含导出例程。

**红线**：不要为了点亮 ROM BACKUP 去贸然做"解除初始设置/Strict/地区后缀"——那是**不可逆的持久改动**
（地区后缀单次写入锁止）。且 ROM BACKUP 本身只给标定/参数分区，**拿不到固件明文或 AES 密钥**，
收益与风险不成比例。

## 8. 服务模式下的 USB 个性变化（2026-10-13 实测，**新发现**）

相机接 USB 后，macOS 侧表现与项目文档记录的 PTP 模式**不一致**：

| 项目 | 文档中可用的 PTP 模式（2026-10-11） | 本次实测（服务模式下） |
|---|---|---|
| `idProduct` | **0x2382 (9090)** | **0x2370 (9072)** |
| 接口类 | （当时 dump 成功） | **vendor-specific：class 0xFF / subclass 0xA0 / protocol 0xB0，3 端点** |
| `bNumConfigurations` | — | **2**（当前用配置 1） |
| macOS 是否识别为相机 | 是（ImageCaptureCore 可 dump） | **否**——`system_profiler SPCameraDataType` 里没有 DC-S5；无 PTP/相机驱动匹配 |
| `s5_ptp_dump`（原生 ImageCaptureCore） | 成功 dump 65,545 B | **连续 5 次 3 分钟超时** |

**已排除的因素**：
- 不是第三方占用：曾发现**夸克网盘 `QuarkCloudDrive` 抢占了该 USB 设备的 IOUserClient**
  （`IOUserClientCreator = "pid …, QuarkCloudDrive"`）→ 结束进程后设备已释放，**但 dump 仍超时**。

**结论（待验证）**：当前 USB 个性**不是** macOS/icdd 认得的 PTP 相机个性。
最可能是**服务模式把 USB 个性切成了服务/厂商模式（PID 0x2370）**；
回到普通模式应恢复 `0x2382`。这也是"服务模式确实改变了运行时对外行为"的一条旁证。

**要跑 PTP dump 的前提**：`idProduct` 变回 **9090 (0x2382)**，且
`system_profiler SPCameraDataType` 能看到 DC-S5。改 USB 连接方式后**必须拔插一次 USB** 才会重新枚举。

（已留后台守望脚本：PID 变为 9090 时自动跑只读 dump。）

## 9. 自建原始 USB PTP 客户端（`s5_ptp_raw.c`）与结论

因为 macOS 的 ImageCaptureCore 认不出当前 USB 个性，自建了一个 **绕过主机相机库、直接走 IOUSBLib
bulk 端点**的只读 PTP 客户端：`04_工具与脚本/ptp/s5_ptp_raw.c`（clang 编译出 `s5_ptp_raw`）。

**它做到了什么（实测）**：

| 步骤 | 结果 |
|---|---|
| 按 VID/PID 匹配设备 | ✅ `04da:2370`，`configurations: 1` |
| 打开 + **独占(seize)** 接口 0 | ✅ `USBInterfaceOpen -> 0` / `USBInterfaceOpenSeize -> 0` |
| 发现 bulk 端点 | ✅ **bulk OUT `0x01` / bulk IN `0x82`，mps 512** |
| 装载管道 | ✅ `SetAlternateInterface(0) -> 0`（**必须显式设置**，否则写入必超时） |
| **发 PTP 命令（bulk OUT）** | ✅ 写入成功（设备 ACK 了数据） |
| **收 PTP 响应（bulk IN）** | ❌ **永远超时 `0xE0004051`（kIOUSBTransactionTimeout）**；无中断端点 |

**结论：当前 USB 个性（PID `0x2370`，vendor class `0xFF/0xA0/0xB0`）不是标准 PTP。**
它接受 bulk 写入但从不回应——符合"**Panasonic 私有 Tether 通道**（LUMIX Tether 专用协议）"的特征，
而不是 PTP。项目文档里 dump 成功的那次是 **PID `0x2382`** 的另一种 USB 个性，本机当前菜单里
没有能切到那个个性的选项。

**工具价值**：`s5_ptp_raw` 本身是可用的**原始 USB PTP 发送器**（精确长度、只读操作码白名单），
一旦相机进入标准 PTP 个性即可直接 dump；当前受限于相机侧个性。

**注**：发送未读的 PTP 命令会让该 bulk 通道卡住（需 USB 重插复位）；相机本身不受影响
（同时段 Wi-Fi `getstate` 仍 `ok`）。
