# DC-S5 隐藏格式研究 —— 思路总结（全文）

2026-10-13 · 本文件是整个项目**方法论与结论的总入口**，配合 `01_研究报告_全集/` 的 16 份报告阅读。

---

## 0. 一句话概括

> 目标不是"破解固件"，而是**从外部接口把相机的可写面、可读面、判定面全部枚举清楚**，
> 用一个可复现的最小写入原语（`setsetting`）把**隐藏录像格式**落到 flash 并跨断电保持；
> 同时把**做不到的部分**用实验排除，而不是靠推测。

---

## 1. 问题定义

**用户目标**：DC-S5（MC801，固件 VD4.30 研究版）上打开官方菜单里不显示的录像格式（MOV 全集、6K 片门全开等），并使其持久可用。

**技术问题拆成三层**：

| 层 | 问题 | 判定方式 |
|---|---|---|
| L1 数据层 | 隐藏格式的**字段在哪、取值是什么** | 二进制差分 + 实机写读回 |
| L2 协议层 | **怎么写进去**（上传协议、校验、分块） | 协议闭合（长度/校验/回执三对齐） |
| L3 呈现层 | 写完**机身菜单认不认** | 机身实拍 + `allmenu`/`curmenu` 交叉 |

---

## 2. 总体方法论

### 2.1 通道分层

相机的对外面只有**四条通道 + 一个服务面**，我们按"离固件内核的距离"排序：

```
           ┌── 蓝牙 BLE ──────── 配对/凭据交付（最外层，能力最小）
           │
 外部 ─────┼── Wi-Fi HTTP ────── cam.cgi（主战场，全部可写原语都在这里）
           │
           ├── USB PTP ───────── 只读配置 dump / 协议 fuzz（写路径红线）
           │
           └── 服务模式 ──────── 机身 UI，暴露 ROM BACKUP / 错误日志（只读）
                                     │
                                （物理线：UART / JTAG / SD.DAT —— 需拆机）
```

**核心判断**：真正有"改内容"能力的只有 **Wi-Fi HTTP 的 `setsetting` + 配置块上传**，
其余通道要么只读（PTP/BLE/服务模式），要么需拆机（物理线）。

### 2.2 证据强度分级（贯穿全项目）

| 标记 | 含义 | 举例 |
|---|---|---|
| ✓ | 已实机验证 / 协议闭合 | MOV 持久化跨断电；CAMSET 校验和公式 |
| ◐ | 强证据但未闭合 | CVE-2019-5096 未测；PTP 写出未执行 |
| ✗ | 已实验证伪 | AES 密钥离线提取；网络 RCE 各路线 |

**铁律**：`setsetting` 返回 `ok` **不等于**生效。所有格式类结论必须以
**实拍文件头**（`tkhd`/`stsd`/`stts`）或**断电后读回**为准。

### 2.3 预言机思维（Wi-Fi 线的关键手法）

相机不是"可编程目标"，而是**判定机**。我们反复利用它的三种判定来做测量：

1. **版本门**：写入不合法版本 → `err_param`（用于确认字段方向）
2. **签名校验**：改固件内容 → 校验失败（用于确认 UPD 结构）
3. **CAMSET 校验和**：改一个字节不改校验 → `err_reject`（用于**反推校验算法**）

> 由"拒绝"反推"规则"，比由"接受"反推更可靠——因为接受可能被静默忽略。

## 3. 各通道的思路与结论

### 3.1 固件 / 密钥线（阶段一）

**思路**：从固件二进制 + UPD 结构入手，找 AES 密钥或可控解密路径。

| 结论 | 强度 |
|---|---|
| AES 密钥在 **MC801 芯片 OTP/eFuse**，不在固件/转接环/I2C → **不可离线提取** | ✗（终局） |
| 版本门不可靠改号绕过 | ✗ |
| UPD 格式与启动链已完整解析（`s5_layout.json`） | ✓ |
| 固件升级 = 真正的"改内容"原语（一旦成功即重写 rootfs） | ✓（协议级） |
| 最终-chunk flash 定址失败（~31s 超时/磨损）→ 升级路径**阻塞** | ◐ |

**沉淀**：固件线的最强路径不是"解密"，而是**物理侧**（JTAG dump RAM / U-Boot console）
——因为芯片级密钥不在我们能读的地方。

### 3.2 Wi-Fi / `cam.cgi` 线（主战场，产出最多）

**思路**：把 HTTP 面当成一个**可枚举、可判定**的协议面，逐层扒开：
`mode` → `getinfo` 子类型 → `getsetting` 域 → 配置块偏移。

| 面 | 有效数 | 候选总数 |
|---|---|---|
| `mode` | 7（getstate/getsetting/setsetting/getinfo/accctrl/camcmd/camctrl） | ~90 |
| `getinfo` 子类型 | 5（capability/allmenu/curmenu/camsetting/**lens**） | ~110 |
| 可写设置域 | **47** | — |

**关键突破（阶段三）**：

1. **CAMSET 块结构**：65,533 B；44 B 头 + 8 B 前导 + TLV 记录流（831 条，
   `[fid u16][len u16][flag u16][payload]`）+ 尾部 `ff ff 00 00`；
   **校验和 = `(256 − Σ(byte[0..65531])) mod 256`**。
2. **写入协议**（曾长期卡住）：`startsenddata` 返回 `method=separate, bufsize=61460`
   → 必须按 **61192 + 4341** 分块 `senddata` + `requestsenddata` + `endsenddata`。
   **单次 65 KB POST 永远不会落地**（早期"mov 回落到 mp4"的真因就是这个 bug）。
3. **容器门**：`videoformat` 单字段互斥 —— `0x00`AVCHD / `0x05`MP4 / `0x06`MOV /
   `0x07`MP4ed / `0x08`MP4hevc，偏移 3062。
4. **质量门**：持久化值必须存在于机身 `allmenu`，否则机身【录制质量】**变灰**。
   `0x8b`(mov_60p_200mbps_**c4k**_10bit) 不在 allmenu → 不可用；
   `0x92`/`0x9b` 等已声明档可用。
5. **成品**：`ntsc + mov + mov_60p_150mbps_c4k`（`0x5e=0x06`, `vq=0x92`）**跨断电持久**。

**排除的路线**（同样有价值）：

- Wi-Fi 无调试后门（~70 候选 mode 全 `err_param`）
- 网络 RCE 各路线全失败（GoAhead 溢出 / LD_PRELOAD / file-op / exec）
- 菜单项**无法注入**：`allmenu` 由固件提供，普通/工程模式完全一致，
  S5 无 My List 机制 → "给 6K PHOTO 换个皮塞进录制格式菜单"**不可行**
- 5.9K 片门全开：token 可写入但**不生效**（实拍仍是 4096×2160 C4K 60p）

仅存的 DoS 原语：**PTP length-DoS**、**senddata 尾块拒绝**（均需拔插/拔电池恢复，不砖机）。

### 3.3 USB PTP 线

**思路**：PTP 提供**同一个配置块的第二个读取通道**（`0x9421`，65,545 B），
以及协议 fuzz 面。

| 结论 | 强度 |
|---|---|
| `0x9421` 全量配置可 dump（与 camsetting 同源、字节数接近） | ✓ |
| PTP 解析**无 length 校验** → 可复现挂死（拔插恢复） | ✓ |
| 配置**写回**路径（`0x9422/0x9423`）未执行（红线） | ◐ |
| 服务模式把 USB 个性切成 **PID `0x2370` / vendor class `0xFF`**，macOS 相机栈不识别 | ✓ |
| 自建**原始 IOUSBLib PTP 客户端**可绕过主机相机库、成功写入 bulk；但该个性**不回 PTP 响应**（非标准 PTP） | ✓ |

**沉淀**：macOS 的 ImageCaptureCore 依赖 VID/PID 数据库匹配；遇到非常规个性时，
**直接走 IOUSBLib 反而是可控路径**（本项目的 `s5_ptp_raw.c`）。
另注意：**云盘类 App（夸克网盘）会抢占 USB 设备的 IOUserClient**，PTP 调试前需先排除。

### 3.4 蓝牙 BLE 线（最新）

**思路**：先用 CoreBluetooth **扫描/连接/枚举**，再从 Android APK 反编译出**协议实现**。

**实机结果**：

| 行为 | 结果 |
|---|---|
| 广播 | `S5-70E253`（机型 + Wi-Fi MAC 后 6 位） |
| 连接 + GATT 枚举（41 特征 / 9 服务） | ✅ **不需要配对** |
| 空载保持 25 s | ✅ 稳定 |
| **任意属性读** | ❌ **相机立即断链**（普通模式与配对模式相同） |

**协议逆向结果**（APK，离线可复现）：

- **三张路由表**：写 `K(type)`、读 `z(idx)`、通知 `T0(idx)`
  - 读 **idx5 = CAMERA_SSID**、**idx6 = CAMERA_WIFI_PASSWORD**、**idx35 = INITIAL_INFORM（密钥来源）**
- **握手时序**：连接 → 服务发现 → 注册 12 个通知 → 读 idx35 取密钥
  → 写 DLNA_UUID + FRIENDLY_NAME → 读 SSID → 读密码
- **加解密**：字节置换 + 32 位 XOR；密钥 = INITIAL_INFORM 前 4 字节大端
  （默认 `0x9032782C`）；已用 Python 复刻并**回环自检通过**

**⚠️ 结论更正**：曾据此推断"近场任意设备可无认证读取 Wi-Fi 凭据"，
**实机验证推翻**——相机对未加密链路**拒绝读并断链**。该安全结论已撤回。
真实姿态：**连接与枚举开放，读取需要加密/绑定链路**。

**沉淀**：**"代码层能读" ≠ "实机可读"**。安全结论必须过实机，否则不能写进报告。

### 3.5 服务模式线（机身 UI）

工程模式进入后多出：准入规则（空）、ROM BACKUP（**灰**）、Language Change、
SCREEN CAPTURE、VERSION INFO DISP、ERR CODE DISP。

- `CAMERA INFO`：`VER 2.90`、序列号、`PWRCNT 3096`、`SHTCNT 20425` 等
- `ERR CODE DISP`：按子系统分页（SD CARD / LENS COMM / SOFT），左列时间戳 + 右列错误码
- **工程模式没有新增录制质量档**（`curmenu` 与普通模式一致，18 档）→ 隐藏格式不是靠工程模式开
- ROM BACKUP 灰的最可能原因：缺少"解除初始设置/释放 Strict"这一前置状态；
  **红线内不执行**（地区后缀单次写入锁止，不可逆）

### 3.6 App 在线 / 单客户端

- 相机**同时只允许一个控制客户端**（手机 App 占用时 `err_already_connected`/`err_reject`），
  但**读类端点不受限**（`camsetting` 全量仍可下）
- `accctrl&type=req_acc` → `ok_under_research_no_msg,S5-70E253,remote,encrypted`
- `getinfo lens` 泄露镜头型号/ID
- **端口扫描：只有 80/tcp**（无 FTP/DLNA/RTSP）
- 配置块含**运行时状态**（18 字节随时间漂移）→ 做块比对时不可把这些差异当成"被改过"

## 4. 方法论沉淀（可复用）

1. **先问"判定面"，再问"写面"**：相机的拒绝信息（`err_param`/`err_reject`/`err_critical`）
   是免费的测量工具。
2. **协议必须闭合**：长度、校验、回执三项对齐才算"能写"。只看到"没报错"是不够的
   （单次 POST 从未落地，却一直"成功"）。
3. **有效性必须用物理证据**：实拍文件头 / 断电读回 / 机身菜单是否变灰。
4. **静态数据也会动**：配置块里混有运行时状态，比对要找**稳定锚点**。
5. **跨机型移植要看代际**：S5（MC801，32 位）vs S5II（MC8243，4×A53），
   CAMSET 块 65,533 B vs 2,252,861 B（966 条记录）→ **跨代移植不可行**；
   同代（S1H/S1R2）才可参考。
6. **主机侧的限制要分开归因**：macOS 认不出相机 ≠ 相机 PB。先分清
   "对端个性问题"还是"主机识别问题"，再决定是放弃还是自建客户端。
7. **红线清单**（始终遵守）：
   - flash 写入必须 AC 供电
   - 绝不刷真实固件、绝不 `resetDevice`、绝不 PTP 配置写回
   - 服务模式只读（不动 ROM WRITE / ADJUST / REGION / 初始设置）
   - `4kcrop` 不碰
   - 读 camsetting 前退出机身菜单

## 5. 仍未闭合 / 下一步

| 方向 | 状态 | 建议 |
|---|---|---|
| 固件升级最终-chunk 定址 | ◐ 阻塞 | 优先级最高但风险大；需 AC + 充分准备 |
| 物理线（JTAG dump RAM） | 未做 | **零风险绕开 AES 的最现实路径**，需拆机 |
| S5 `f_fs` OOB 审计（S1R2 F1/F2 同款？） | 未做 | 零风险，可离线做 |
| CVE-2019-5096（multipart UAF） | 未测 | 唯一剩余公开 RCE，需堆控 |
| BLE 完整链路 | ⏸ 被绑定挡住 | 需先在系统层完成 BLE 绑定（iOS/Android 由 App 自动完成） |
| 相机热点安全测试 | ⏸ 待接入 | Mac 需接入相机热点；测无认证 / CSRF / 开放热点 |
| 菜单项注入 | ✗ 已证伪 | 不再投入 |
