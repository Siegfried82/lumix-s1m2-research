# S1M2 配置色表数值分析

输入为现有基线 config_1.DAT；SHA-256 和完整统计保存在 results.json。analyze.py 只读配置，不访问设备、不生成回写镜像。

在既有 0x051f 结构边界假设下，每块 +10 起读取 33³×3 个小端16位数；40块网格为33，末块网格0且数据全零。41块数据共40种不同SHA-256，不能称41张不同有效LUT。

以第一张表为例，值域0–65535；相邻格点的主要变化通道为：最快轴→第二分量、中间轴→第三分量、最慢轴→第一分量。这三个主方向都无负增量；表现比仅靠尺寸更符合连续三维色彩映射。完整各槽轴差分、角点、取值范围与重复关系见JSON。RGB名字尚未由调用者确认，不能把分量位置直接定为相机RGB语义。

同一原始字节按IEEE半精度浮点解释，第一张表107811个值中只有83112个有限值，存在24699个NaN/Infinity，范围约±65400；这不支持把该配置表直接作为普通归一化float16色表。Lab util/F0.java确实有88字节头及float16/float32读取，但其格式与DAT记录头不同，没有证明两个路径对应。

这次推进了数值编码与轴排列线索，未证明槽位代表用户LUT或照片风格，也未证明这些表进入照片/视频录制路径。布局起点仍需原厂调用者或受控导入样本确认；数值结果不能替代该证据。

40个有效网格块中，按各轴平均绝对差分选主通道的组合统计：{(1, 2, 0): 39, (0, 2, 0): 1}。所有有效块按float16解释的非有限值合计 407368，总值数 4312440。重复数据槽组：[[13, 23]]。

## S5II / S5IIX 跨机型对照

cross_model.py直接读取既有两份原始DAT并核实目录指定的记录头和边界。两机型的0x051f仅236字节，不能按S1M2同标签的8840924字节大块解释；0x0520则均为2156292字节，结构包含10个215628字节块，每块开头长度215624，剩余215624字节全零。两机型相应完整记录散列相同。

因此现有对照样本没有非零用户色表可用于识别S1M2槽语义，但明确证明“按相同tag跨机型套用结构”的方法不可靠。10块的尺寸与33³×3×2接近吻合，具体多出的字段、用途仍未证实；旧报告将其称为Custom Mode Preset Slots并未给语义证据，不采纳该名称为事实。原始范围、散列及逐块统计见cross_model_results.json。

## 原厂 APK 资源与数值匹配

直接读取现有 LUMIX Lab APK（SHA256见app_assets_results.json），而不是依靠源码名字：426份photoStyleLUT二进制资源全部通过88字节PSL1头、维数和实际数据长度校验。其中142份为2048点一维半精度曲线，284份为33点三维RGB半精度表。S1M2包含19份一维和38份三维资源。源码util/F0.java的header与半精度读取行为在这些资源上有实际对应，但仍未关联DAT槽。

21份实际33点文本cube，以原始顺序、clamp[0,1]、乘65535四舍五入转u16，未与DAT40槽完整散列匹配。另对38份S1M2三维二进制表验证所有float16值有限，再以65535/65536两种缩放及四舍五入/截断两种量化执行152个完整数据匹配，均未匹配。

这限定排除了这批资源直接按所测量化、原顺序复制到所测DAT起点的假设，不排除轴/通道置换、不同定点精度、重采样、处理管线组合或表数据起点。配置色表不是直接套用App半精度文件；App中存在真实同维色表资源，为后续置换与转换分析提供了可信输入。没有修改设备或生成固件补丁。

复现脚本app_assets.py与compare_binary.py及结果JSON保存在本目录；它们从现有APK和原始DAT读取，保留源散列及逐项匹配统计。

## 纯排列假设的完整数值分布检验

permutation_invariant.py以排序后的全部u16数值序列散列作为多重集合指纹，保留重复值数量；重排阳性与改值阴性对照通过。40个配置槽逐一生成完整指纹，与38个S1M2原厂资源的四种量化结果（152个候选）对照，没有匹配对。

在已测block+10数据起点、两种缩放与两种量化条件下，任何仅重排数值的变换都不可能使这些资源成为配置表；包括轴排列、通道排列及其组合。该结论是必要条件排除，没有逐一执行全部排列，也不排除其它数据起点、数值转换、插值或不同资源。

下一步应核实数据起点或寻找实际数值变换，不再只反复试轴/通道顺序；仍未确认配置槽身份、处理链与输出效果。

## 起点与字节序敏感性复核

`origin_sensitivity.py` 对同一 baseline DAT（运行时校验与既有 source hash 相同）扩大了整数表比较：固定候选块长 215632 字节，33³×3×2 字节完整表能容纳的全部块内起点是 0..10，共 11 个；40 个非空候选槽分别按 little/big u16 解释，得到 880 个多重集合指纹，与既有 38 个 S1M2 App 3D 资产的四种量化指纹（152 个）比较，无匹配。结果为 `origin_sensitivity_results.json`。

因此，在该固定块边界和四种量化规则范围内，早前无匹配不只是“起点 +10 或小端选错”的结果。多重集合保留每个值的重复次数，任意纯值排列都不能修复此不匹配。此复核不确定哪个起点正确，不排除跨块、其它块长、插值/数值变换、其它资产或非 u16 编码。没有进行设备通信或写入。
