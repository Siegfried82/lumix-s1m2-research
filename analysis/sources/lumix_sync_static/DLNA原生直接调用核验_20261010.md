# DLNA 原生直接分支核验

2026-10-10，使用自行编写的 ELF/AArch64 静态读取脚本，不运行库。

已定位两个浏览 JNI 函数：dmpBrowseExtentionTag 位于 0x8a608，668 字节；dmpBrowseExtentionTag2 位于 0x8a8a4，808 字节。各自有直接调用 DM_DMP_BROWSE_CONTENT_ITEM_LIST_Delete，其他多处直接调用落入尚未解析名称的 PLT 跳板。结果保存在 dlna_direct_branches.json。

JNI_OnLoad 位于 0x8bb14，28 字节，在已扫描的立即数 B/BL 指令中没有直接分支。脚本没有解码所有指令或间接 BLR，因此不能声称已排除动态注册。

目前只验证了地址范围及直接分支，不是完整反汇编；无法由列表删除函数单独确定整个浏览实现语义。已知 Java 消费链仍是媒体目录文本，没有程序导出证据。下一步必须解析 PLT 重定位和间接 JNI 调用，避免把未识别跳板当成未知解密函数。

audit_dlna_branches.py 需要单独取得的 Sync APK，解析 ELF 符号与程序段，以正确的虚拟地址到文件偏移映射读取指令。
