# 开源平台调用核验

2026-10-10，直接读取本地官方 Linux tar.gz，未运行或编译厂商代码。

压缩包含 61993 个文件成员；按 milbeaut/m20v/sniipcu 路径筛出 53 个 C/H 文件并逐个记录哈希。此限定范围未出现 decrypt、eep_act、postboot 或 UPD 字符串解析线索。结果不覆盖所有通用代码，也不证明全部源码不存在相关逻辑。

发现两处真实 Secure Monitor 调用：drivers/dma/milbeaut-xdmac.c:25 定义 SMC_CMD_PANA_SECURE_WRITE64=0x8200C001，:182 调用；drivers/dma/milbeaut_hdmac.c:25、224 同类。调用者 milbeaut_noc_addr_set 将寄存器地址及 noc_addr 作为参数传入。源码明确用途是更新 DMA/NOC 寄存器，不是固件解密、密钥导出或内存读取。没有对应安全世界处理函数证据，不能从 SMC 存在推断 UPD 的密钥位置或算法。

已有 U-Boot 的 mach-milbeaut/Kconfig 选择 SC2006A，milbeaut.c 提供复位、内存映射与 DRAM 初始化。没有验证这是目标机实际运行映像或 loader1。不能把公开的板级地址直接当成 S1M2 的运行布局。

旧汇总中“密钥必在 eFuse、安全世界解密、上位机不可能包含算法”等表述仍超出当前证据。本轮没有闭合固件加载链，只确认具体平台调用用途。

证据 oss_platform_inventory.json，包含包哈希及 53 个源文件哈希。所有工作离线，只读。
