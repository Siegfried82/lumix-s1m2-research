# Sync 下载器原始 DEX 复核

2026-10-10，Codex 离线读取 Sync 2.0.17 APK。没有连接机身或执行 APK。

## 结论

已确认 H5.c 下载器将 HTTP 响应输入流直接保存到文件。结合上一阶段，已定位的更新数据链为 HTTP 响应 → 本地 ZIP → 第一个 ZIP 条目解压 → 文件读取 → 数组切片 → multipart 发送。没有在这条已检查路径找到专有固件组件解密或原生解码调用。此结论仅针对该路径，不证明其他应用或机身处理不存在解密。

## 原始指令证据

DumpDownloadDex.java 使用 dexlib2 读取 APK 中 LH5/c; 的方法。结果保存在 download_raw_dex.txt，偏移为方法内 DEX code unit。实际实现方法在原始 DEX 中名为 u，JADX 合并桥接后显示为 g。

- 0x0034 取得 HTTP 状态；0x0038–0x0060 处理 302/301/303 重定向，并采用重定向后的响应状态。
- 0x0094 常数 200；0x0096 if-ne 跳到 0x0147 错误路径。HTTP 200 落入下载路径。
- 0x0098 getInputStream；0x009e FileOutputStream 构造。
- 0x00ad InputStream.read 写入 v9 数组，返回长度 v2；0x00b2 遇到 -1 才跳到结束。
- 0x00cb FileOutputStream.write 使用同一 v9、偏移 v5（写入前为零）、长度 v2。两者之间处理取消判断及日志，没有修改输入数组。

JADX 的 H5/c.java 把 HTTP 200 判断及 EOF 判断显示成反向条件。不能执行或照抄该反编译 Java；本次结论使用原始条件跳转复核。

FwUpdateActivity:2651–2654 创建 H5.c，以 f22276V0 作为 URL、p126p5.m.e 得到的路径作为输出。下载回调及后续本地路径仍需注意重名文件处理：N5.f.a 在文件已存在时生成带括号的新路径；因此不能假定下载文件名与后续 m.f 的固定 basename 永远相同。
