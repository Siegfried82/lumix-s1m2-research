APK 的 arm64-v8a 含六个共享库，逐库 SHA-256 和长度保存在 native_inventory.json。检查可打印字符串后，没有 firmware/decrypt/eep_act/postboot/camsetting 命中。宽泛 UPD 模式会命中 update 等文本，因此未将其算作固件标记。字符串阴性结果不能排除隐藏、去符号或编码实现。

DlnaWrapper 的声明涵盖设备发现、订阅、内容浏览、媒体服务器及内容删除。此前已检查的更新数组链使用 Java ZipInputStream、FileInputStream、System.arraycopy 与 HttpURLConnection，未发现将该数组交给以上原生声明的调用。没有从库名或缺少 decrypt 字符串证明整个应用无解密能力。

本次没有找到新的固件解码入口。下一步如继续原生分析，应从实际 DEX 调用和 JNI 注册表定位函数，再建立调用链；不能只凭库体积或算法常数宣布解密突破。
