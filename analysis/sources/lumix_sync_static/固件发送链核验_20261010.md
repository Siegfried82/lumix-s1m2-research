# Sync 2.0.17 固件发送链核验

2026-10-10，Codex 离线静态分析。Antigravity 停用；没有执行 APK 或向相机发送命令。

## 结论

已把中断点从 FwUpdateActivity 的发送调用追溯到本地 ZIP 解包，并继续追到 multipart 输出。已检查的 Java 路径是解包、文件读入、数组切片和 HTTP 写出，没有发现 UPD 组件解密步骤。此局部结论不排除其他应用路径、反编译缺失或机身内部处理；不能据此证明整个应用没有解密能力。

## 可定位证据

以下路径相对 decompiled/sources，源文件哈希见 firmware_send_source_hashes.json。

- FwUpdateActivity.java:734-743（完整路径 com/panasonic/jp/view/setting/）：从 p126p5.m.f 得到本地路径，调用 N5.r.b 解包，tb 读入解包文件，然后 zb 发送。
- p126p5/m.java:10、38：生成 Android 外部应用下载目录及 basename 路径，不改变内容。
- N5/r.java:209-240：ZipInputStream 打开 ZIP，取第一个条目，将解压字节直接写入目标文件。ZIP 解压不等于固件解密；未见遍历全部条目或挑选指定固件文件的逻辑。
- FwUpdateActivity.java:2258-2275：tb 用 FileInputStream 及 ByteArrayOutputStream 读取原始文件内容。
- 同文件 :2180、2199：类型分别赋值 fw / lens_fw；:2144-2164 向机身请求 fw_update_mode / lens_fw_update_mode 并处理版本及状态响应，不是本地程序解码。
- 同文件 :2367-2369：zb 将类型、数组长度、原数组交给 B5.a.O。
- B5/a.java:675 起：startsenddata 获取 once/separate 发送方式，System.arraycopy 切片后经 J 发送，requestsenddata 协调后续块。
- B5/m.java:238、B5/n.java:37：将同一切片包成 ByteArrayInputStream、application/octet-stream multipart；没有内容转换。
- p142r5/f.java:183 起：multipart 输出实现从输入流读取并直接写出数据，另加 HTTP 表单头和边界。

## 对研究目标的意义

这条 Sync 更新路径未提供 S1M2 固件明文或 RAM。握手中的 XOR 变换不在已追踪的固件数组处理链里；不能拿它当固件密钥。Sync 官方支持列表未列 S1M2，因此也没有确认这些更新命令适用于 S1M2。

   S5m2_V31.bin 205,683,712 B），即"第一个条目"就是整份 UPD 容器，应用原样分块发送，
   与应用层"无解密"结论一致。

5. **N()（once 模式）数据流**：B5/a.java:616-675，startsenddata 同端点，
