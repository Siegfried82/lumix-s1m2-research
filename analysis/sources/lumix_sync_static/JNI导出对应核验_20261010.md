# Sync DLNA JNI 导出对应核验

2026-10-10，自己解析 APK 内 arm64 ELF 的动态符号表，不执行共享库。

原始 DEX 的 DlnaWrapper 有 25 个 native 声明；libdlnaCore.so 的 46 个 Java_* 导出中，25 个声明全部有对应已定义符号，无缺失。另有 21 个导出没有本版本 DEX native 声明，主要是播放、暂停、定位、内容计数等 DLNA 接口；库包含导出不代表应用实际调用。

已记录每个 JNI 导出地址、大小、输入库哈希，见 jni_export_inventory.json；声明与导出映射见 dlna_jni_mapping.json；原始 DEX 外部引用见 dex_dlna_references.jsonl。JNI_OnLoad 为 28 字节导出，但尚未反汇编其内部，不能由大小直接排除动态注册或其他行为。

没有发现名为固件解码或内存读取的 JNI 接口，也未在已追踪更新数据链找到进入 DLNA 原生接口的调用。接口名称与符号对应不能替代函数语义证明：当前未对全部 9 MB 原生代码反汇编，没有声称整个库不存在解码函数。

下一步应从 dmpBrowseExtentionTag/2 的实际调用和输出消费追踪它是否仅返回媒体目录，或找新的加载材料。只有明确程序字节输出才能推进固件目标，发现更多媒体控制导出不算功能解锁。
