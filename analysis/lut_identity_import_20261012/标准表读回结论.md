# 标准 identity LUT 正常导入后的 HTTPS 读回

用户通过官方 Lab 将 LUT_IDENTITY_33 导入 SET26；API 列表确认对应 LutId 27、VLOG、type 3。输入与读回 SHA-256 及完整 107811 通道对照见 verification.json、numeric_verification.json、quantization_models.json。

读回文本不与输入逐字节相同：TITLE 变为空字符串，数值有约 7.6e-6 的变化。全部读回值重新量化为 uint16 后，与输入乘 65535 最近取整完全一致，0 个通道不匹配；向下取整模型有 52272 个不匹配。读回小数与对应整数除 65535 的最大误差约 9.90e-8。

0.5 读回为 0.5000076，对应 32768。此样本不能区分 half-up 与 half-even：两者在这里均得到 32768。不能把此前已量化 LUT 重导入的字节保留结果推广到任意原始 cube。

当前证据支持官方导入/导出链包含 16 位量化，但尚未取得本次 USB 配置，不能定位量化发生在 App、机身导入还是导出阶段，也不能断言复用了删除后物理块23。下一步采集两份 USB 配置，按目录解析映射并全通道比对。
