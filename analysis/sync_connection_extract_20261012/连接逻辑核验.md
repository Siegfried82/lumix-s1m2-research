# LUMIX Sync 连接逻辑提取

2026-10-12，离线静态提取，不运行 APK、不发起握手。

## 输入与范围

现有 Sync 2.0.17 APK：analysis/sources/lumix_sync_static/lumixsync.apk。此前记录 SHA-256 6986e22f92c9d7a468ee56e948a6e1960128989a8bd90013231b9a27ab10e377，本次主要检查对应已有 Java 反编译代码，并为实际读取源码生成新散列。JADX 原有 62 个错误，因此不能宣称完整逆向或覆盖全部连接路径。

## 已定位的链

1. 发现：DlnaWrapper.f/g 调用 u/v，搜索 MediaServer:1。具体发现报文在原生实现中，未从 Java 证明 SSDP 地址、端口或全流程。
2. 地址：B5/a 构造 http://<设备地址>；控制请求未显式附端口时采用 HTTP 默认 80。另有 60606/Lumix/Server0/ddd 媒体描述入口，不等于握手端口。
3. 标识：N5/l.y 读取持久化 Dlna_UUID_Seed，前缀为 4D454930-0100-1000-8001-。原 App 并非每次生成新 UUID；S5 脚本每次随机生成是自身实现差异。
4. 名称：service/c.u 从首选项取 Network.Name，默认 Android Build.MODEL。普通路径经 N5/l.d0 做 URL 编码。
5. 普通握手：service/c.f -> B5/a.m -> accctrl / req_acc，携带 value 与 value2。
6. Encrypt 分支：service/c.u -> B5/a.U -> req_acc_g；期望 CSV 第二字段为十六进制挑战值，再分别对 UUID 与原始名称调用 N5/o.b。随后 c.f 选择 req_acc_e。
7. 变换：四个 Java 字符一组，不足填字符 FF；组合后与 32 位挑战值 XOR，再交换字节序，输出十六进制。挑战值为零时使用 -1875740628。属于连接参数变换，非固件 AES 解密。
8. 会话：c.T 在至少五字段且首字段 ok 时保存第五字段；p142r5/b 仅在会话字符串非空时添加 X-SESSION_ID。并非所有响应都有令牌。
9. 取消：c.c 发 req_acc_can。建立及取消会话有副作用，不能因为使用 GET 就称纯只读。

## 提取成果

source_manifest.json 列出源码路径、行号范围与 SHA-256；*.excerpt.txt 保留带行号原文；build_requests.py 是不联网的 ASCII 请求构造器，包括普通及挑战变换分支。仅通过三项人工可核验的合成检查，未做 Java 执行对照，不支持非 ASCII，不能称完整 App 移植。

## S1M2 当前障碍

尚未收到当前相机 HTTP 响应。新增 req_acc_e 逻辑无法修复无法访问 80 端口的问题。等待 Tether 的服务是否与 Sync 相同仍未证实。此样本不能证明 S1M2 支持 Sync，不能据此直接执行握手或读取机内程序。

下一步：追踪原生发现实现和连接模式选择的调用者；用实际发现响应确认设备地址、服务地址及协议，再决定是否需要 Lab/Flow 对应连接链。不能凭 60606 字符串认定相机开放该端口。
