## 2. 证据等级划分：已确认 / 作者主张 / 推断 / 未知

### 2.1 已确认（Confirmed）
1. **旧格式（`0x101`）真实消费者与边界闭合**：GH2 (`V1.1/V1.2`)、G3、GF2、GF3、GX1 的官方更新路径仅接受 `header+0x08 == 0x101` 且 `selector (+0x34) in {0, 2}`（AES-128-CBC + 解码后主体 MD5，驻留 key 经启动 ROM→RAM 复制后传入）；TZ10 仅接受 `0x101` 且 `selector in {0, 1}`（驻留 seed 双重 XOR + 奇偶性控制 discard 的 local MT + MD5）；上述已定位官方更新函数遇到 `0x200` 返回 `0x80000064`、遇到 `selector 3` 返回 `0x80000006`（`研究推进_20261011_Ultra.md:18-22, 34-65`）。
2. **`S1m2_V14.bin` 全部 62 个目录项（保留 `index 0..61`）的线性文件偏移与 `destination_field` 空间闭合（本轮静态数学新发现）**：
   - 经 `audit_premises.py` 对 `项目当前进度_20261010.md:307-370` 全部 62 项及 61 次相邻过渡逐一计算：
   - **文件偏移连续性**：从 `index 0` (`0x1a00`, `6,656` B) 到 `index 61` (`mbr_dummy_d`, `0xa3c7e00`, `131,072` B)，61 次相邻过渡 `file_offset[i] + size[i] == file_offset[i+1]` **100% 成立（0 断裂）**，且末尾 `0xa3c7e00 + 0x20000 = 0xa3e7e00 = 171,867,648` B，与 `S1m2_V14.bin` 总字节数逐字节相等。
   - **目标地址字段 (`destination_field`) 的擦除块对齐与唯一真实空洞**：`destination_field` 在全部 62 项上严格单调非递减（`0x0` 至 `0xa4e0000 = 172,883,968` B）。61 次相邻过渡中，**54 次为 `0` 字节紧邻衔接**（`dest[i+1] == dest[i] + size[i]`）；仅存在 **7 处非零间隔**，总计 `1,022,976` B (`0xf9c00` B)，满足恒等式：
     $$\underbrace{171,867,648}_{\text{BIN总长}} - \underbrace{6,656}_{\text{0x1a00头部与目录}} + \underbrace{1,022,976}_{\text{7处目标间隔总和}} = \underbrace{172,883,968}_{\text{0xa4e0000 线性目标空间终点}}$$

## 3. 本轮具体新发现与明确排除项

### 3.1 具体新发现
1. **证实 `S1m2_V14.bin` 的 `loader2` (`index 2`) 与 `loader3` (`index 3`) 对应 Flash `[0x20000, 0x80000)` 的 384 KB 驻留空洞**：V1.4 包中 `index 1 (loader1)` 仅覆盖 `[0x0, 0x20000)`，随后 `index 2/3` 为 `size=0` 占位，直到 `index 4/5 (storage/program)` 从 `0x80000` 开始。这意味着如果二级/三级引导加载器（以及潜在的 `05_program` 解密生产者）驻留在 `[0x20000, 0x80000)`，则**单靠 V1.4 更新包自身在物理上缺少这一环代码**。
2. **揭示其余 6 处 `destination_field` 间隔全为 `0x20000` (128 KB) 擦除块对齐填充，且 `eep_*` 与 `menu_save/lut_data` 物理分离**：`eep_act_a/b` (512B) 与 `eep_exp_a/b` (12KB) 各自独占 128 KB 扇区（位于 `0x5560000..0x55e0000`，均 `flags=3`），而 `28_menu_save` (512 KB, `0x7aa0000`) 与 `39_lut_data` (8.78 MB, `0x8a20000`) 均为 **`flags=2` 未加密组件**，两者体积之和 (`9,306,112` B) 与 `0x9421` 导出的 `.DAT` (`9,197,409` B) 高度吻合。
3. **发现本轮 `tasks.json` (15 个并行分支) 的关键路线遗漏**：`项目当前进度_20261010.md:137` 明确将“优先补足 FunctionFS 的运行版本和接口归属证据”列为下一步之首，但 `tasks.json` 的 `01`–`15` 分支无一覆盖 `f_fs.c`/`composite.c` 的内核配置启用性及 `get_alt` 负值丢弃静态核查。

### 3.2 明确排除了什么
1. **排除“仅凭 V1.4 的 `01_loader1` 即可在不缺失中间段的情况下无缝静态拼接至 `0x80000` (`05_program`)”的隐含假设**（中间存在 384 KB `loader2/3` 未下发区）。
2. **排除“`0x9421` (`.DAT`) 覆盖机身全部实时功能开关与 `eep_*` 原始分区”的隐含假设**（单张/高分受控对照已证伪驱动状态在 `.DAT` 中，且 `.DAT` 为 TLV 封装而非 Flash 原始扇区）。
3. **排除“在纯 `0x101` 老机身主更新器里继续搜索能直接找到 `0x200 / selector 3` 分支”的低效方向**（6 款 `0x101` 机身主更新器已全部闭合为拒绝 `0x200` 和 `3`）。
