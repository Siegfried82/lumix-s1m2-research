# 10 · 下一步与开放问题

> 按"性价比 / 风险"排序。每条标注：目标、现状、动作、风险、是否需用户授权。

## 10.1 打通一次成功 `endsenddata`（软件侧最高价值）

- **目标**：拿到相机对"已签名 vs 未签名 / 已改版本"固件的**真实验签反应**，直接回答"改版本/改内容能否过签名"。
- **现状**：始终卡在最终-chunk flash 定址失败（~31s → `err_busy`/`err_critical`），内容/节奏/状态无关（§04）。
- **动作（低风险变体，详见 §04.5）**：
  1. 末块 `err_busy` 后**立即**发 `endsenddata`（不静置、不重试）。
  2. 末块**静置更久**（60–120s）再 `endsenddata`。
  3. **拔电池全新 flash 状态** + 一次性 fast 流送 + 末块单次 + 立即 `endsenddata`。
  4. **换 SD 卡 / 换机**，排除"当前 flash 已被反复 90MB 流送写坏"。
- **风险**：每次都可能再触发 ~31s 定址 / 卡死（拔电池可恢复）。**绝不真刷**。
- **授权**：属受控实验，需 AC + 健康守卫；建议执行前与用户确认（相机脆弱）。

## 10.2 CVE-2019-5096（multipart UAF → RCE）—— 唯一剩余公开 RCE

- **目标**：打到 shell。
- **现状**：未测；本机 CGI 正是 multipart（`senddata`），具备前置条件。
- **动作**：构造畸形 multipart 触发 use-after-free，再做**堆布局控制**覆盖函数指针/返回地址。
- **风险**：**高** —— 堆控工程量大、成功率低、极可能直接 brick 相机。
- **授权**：**需用户明确同意**后才投入。在此之前不推荐作为首选。

## 10.3 ★ 物理 / 调试侧（推荐最高价值，零风险、不需密钥）

- **洞察**：**不需要那把 AES 密钥** —— 拿到**开机后 DDR 里的运行时明文**，就绕开了密钥本身。
- **路线 A：UART / JTAG（只读 dump 运行时 RAM）**
  - 只读、不需密钥、不写、不 brick。
  - 直接拿到**解密后的 rootfs / 守护进程 / 配置 / socket 路径**（= userland 全部机密）。
  - 这是"不拆 flash、不碰密钥"就能拿到"改内容所需全部情报"的最直接路径。
- **路线 B：SD.DAT / ROM-flashing 恢复模式（绕过验签链）**
  - 若能进入恢复 / 刷机模式且**不强制 Stubby RSA 验签**（S5 若沿用 Milbeaut 默认未开 ENFORCING，自签 kernel+dtb 理论上可启动），则可**写自编代码**。
  - 前提是先进 UART / SD.DAT 入口。
- **风险**：需**拆机**（物理接触），操作不当可能损伤硬件；但**不需密钥、不依赖软件侧的验签门**。
- **授权**：需用户同意拆机 / 硬件接触。

## 10.4 开放问题（待回答）

1. **末块定址失败到底是"可恢复的 flash 状态"还是"硬损伤/磨损"？** → 决定 §10.1 是否还能在软件侧打通。
2. **相机是否强制 Stubby RSA 验签（ENFORCING）？** → 决定 §10.3 路线 B 是否可写自编代码。
3. **签名 oracle 的真实反应**（已签名 vs 改版本 vs 未签名）→ 被 §10.1 阻塞，拿到一次 `endsenddata` 即可回答。
4. **0x9103（PTP 未文档化操作码）具体是什么？** → 唯一新的 PTP 攻击面线索，值得只读深挖。

## 10.5 优先级建议

| 序 | 路线 | 理由 |
|---|---|---|
| 1 | **§10.3 物理 UART/JTAG 只读** | 零风险、不需密钥、直接拿运行时明文（改内容所需全部情报） |
| 2 | **§10.1 打通一次 endsenddata** | 纯软件，回答"改内容能否过签名"这个核心问题 |
| 3 | §10.2 CVE-2019-5096 | 需用户授权 + 高 brick 风险，放最后 |
