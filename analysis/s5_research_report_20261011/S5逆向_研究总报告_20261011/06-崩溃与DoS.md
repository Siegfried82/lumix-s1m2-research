# 06 · 崩溃与 DoS

> 用户问题：除了崩溃，有没有更有价值的东西。本章先把"崩溃 / 挂死"这一类**已打通**的结果讲清楚（它们本身**不是** RCE，但暴露了状态机/解析器的缺陷），并给出唯一"可复现挂死"的实机漏洞。

## 6.1 ★ 唯一"可复现挂死"实机漏洞：PTP length-DoS

（见 §07 细节；原始日志 `logs/USB-PTP/ptp_attack_v1.log`）

- **缺陷**：S5 的私有 PTP 解析器**校验命令 type、但不校验 length**，且**无超时**。
- **触发**：发送 12 字节但头声明 `length=0x400` 的包 → PTP 数据面**挂死**。
- **恢复**：**拔插 USB** 即恢复（相机本身不死机，只是该 PTP 会话的 DMA 卡住）。
- **性质**：**无写操作、不砖机**；纯 DoS。主机侧（macOS ImageCaptureCore）同样不校验 length，约 60s 内部超时后返回空响应。
- **价值**：证明了"解析器长度未校验"这一真实缺陷，但它是**挂死而非内存破坏**，不能直接拿到 shell / 改内容。

## 6.2 senddata 最终块被拒 → 重试循环 → 状态机未处理分支

（与 §04 同源；用户**实测复现过一次需要拔电池的彻底卡死**）

- 路径：`senddata` 最终块被拒 → 客户端**重试循环** → 相机内部升级状态机进入**未处理分支** → 相机卡死。
- 用户报告："相机这次彻底卡死（basil/卡死），拔电池重启才恢复。"
- **性质**：**状态机 DoS**（状态机被驱动到非法/未处理态），**不是**内存破坏、**不可控**、拿不到 shell。
- 意义：说明升级状态机对"末块被拒 + 反复重试"这种序列**没有健壮处理**；是潜在的可用性缺陷，但不是可利用的 RCE 原语。

## 6.3 其它已尝试（全部无有效崩溃 / 无 RCE）

（原始日志 `logs/崩溃/`）

## 6.4 小结

- **已打通的"挂死/卡死"有两条**：PTP length-DoS（拔插 USB 恢复）、senddata 末块重试状态机卡死（拔电池恢复）。
- **二者都是 DoS，不是 RCE**：不可控、不可利用为代码执行 / 内容改写。
- 用户真正想要的"能改内容的漏洞"仍指向 **§04 写路径**（差最后一步）与 **§10 物理/调试侧**。

## 6.5 安全提示

- 反复大镜像流送 / 末块重试**已经多次让相机 brick / 卡死**（拔电池恢复）→ flash / 状态机对大镜像流送非常脆弱。
- 任何崩溃类实验必须 **AC 常供电 + 健康守卫 + 可拔电池**。详见 §11。
