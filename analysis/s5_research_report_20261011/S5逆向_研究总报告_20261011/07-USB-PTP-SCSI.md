# 07 · USB 私有 PTP（pvc_mass_storage）

> 相机在 USB "Tether/PC 连接" 模式下暴露一个**非标准 PTP**（走 `pvc_mass_storage`，SCSI 风格命令，非标准影像 PTP）。本章记录操作码、全量配置 dump、升级状态机、以及"无任意地址写"的结论。原始日志见 `logs/USB-PTP/`，脚本 `scripts/USB-PTP/s5_ptp_dump{,.py}`。

## 7.1 已识别的私有操作码

| opcode | 含义 | 副作用 | 状态 |
|---|---|---|---|
| 0x1001 | GetDeviceInfo | 只读 | 已用（型号 DC-S5 / 固件 2.9 / SN） |
| 0x1002 | OpenSession | 会话 | 已用 |
| 0x1003 | CloseSession | 会话 | 已用 |
| 0x1004 | GetStorageIDs | 只读 | 已用 |
| 0x9104 | GetSyncList | 只读 | 已用 |
| **0x9421** | **全量配置 dump** | 只读 | **已 dump 成功（65,545 B）** |
| 0x9422 / 0x9423 | 配置写回 | **写（安全红线，未执行）** | 仅识别，未用 |
| 0x9605 | Get_Event_Info（升级状态机） | 只读 | 已查询（idle 全零 = 无待升级） |
| 0x9606 | 升级数据面 | 潜在写 | **实测无任意地址写原语** |
| 0x9103 | （未文档化） | — | 被识别（回 SessionNotOpen），唯一新攻击面线索 |
| 0x9406（8 子码） | 保存/格式化/升级准备/完成/除尘/坏点刷新/升级中止/全量重置 | **全带副作用** | **绝不执行** |
| 0x940d | 电源 | 副作用 | **绝不执行** |

## 7.2 ★ 0x9421 全量配置 dump（核心只读成果）

- **大小**：S5（老平台 MC801）全量配置 = **65,545 字节（64.0 KiB）**，已确认完整。
- **完整性三条证据**：结尾 `ff ff 00 00` 终结符、`payload[0:4]=len-4` 自洽、无越界指针。
- **格式（已解码）**：外层 **TLV** + **16 位记录表 831 条**。
- 对比：Tether 在 S1M2（新平台）上 dump 到 9,197,421 字节（约 140 倍）——是**平台代差**，不是 S5 读取上限。
- 产物：`data/config_0x9421.bin`（65,545 B）+ `data/device_info.bin` / `storage_ids.bin` / `capture_log.json`。
- **价值**：拿到了相机的**全量出厂配置明文**（相机参数表），但它是**数据**（设置），**不是代码、不接触 AES 密钥**。可用于理解 userland 配置结构 / 反查字段含义。

## 7.3 升级状态机（0x9605，只读查询）

- 事件 0x41000012..0x41000017。
- S5 idle 态实测：0x41000013 / 0x41000014 回 0x2001 + 20 字节全零载荷（= 无待升级），其余 0x2002。
- **意义**：升级状态机可通过 PTP 只读观察，但**无法**用它触发 / 中止升级（那是 0x9406 带副作用子码，红线）。

## 7.4 "无任意地址写原语"（关键否定结论）

- 对 0x9606 及其它数据面操作码做了只读探测：**没有任何"给定任意地址 + 数据 → 写入"的原语**。
- 0x9422/0x9423 是**结构化配置写回**（写设置分区，非任意内存地址），且属安全红线未执行。
- **结论**：USB 侧**不能**做"底层任意写 / 改代码"；最多是设置数据（与 §04 的 rootfs 重写不可比）。

## 7.5 已知 CVE 核查（11 条 NVD，全部 N/A）

- 命中的 11 条 NVD 相关 CVE 均为**主机侧 PTP/SCSI 解析器**类（攻击相机去解析攻击者构造的响应），**本机是"主机攻击相机"方向，全部不适用**。
- 唯一实机成立的是 §6.1 的 **length-DoS**（type 校验、length 不校验、无超时），属新发现而非已知 CVE。

## 7.6 端点 / 平台细节

- 设备：VID=0x04DA PID=0x2382；接口 0 实测 `0x01` BULK OUT / `0x82` BULK IN / `0x83` INT IN。
- macOS 上 **Python/libusb 的 bulk IN 会 EOVERFLOW（Errno 84）不可用**；**macOS 首选原生 `s5_ptp_dump`（ImageCaptureCore）**，S5 实测 dump 成功就是这条路径。
- 端点按接口描述符**动态发现**，不硬编码（S5=0x82，S1M2=0x81）。

## 7.7 复现

```bash
cd <LOCAL_USER>/Documents/ChatGPT/S5逆向
./s5_ptp_dump ./ptp_out S5            # mode=dump：0x9421 全量配置
./s5_ptp_dump ./ptp_out S5 fwup       # mode=fwup：0x9605 升级状态机只读
./s5_ptp_dump ./ptp_out_fuzz S5 fuzz  # mode=fuzz：43 个安全只读探测
# ⚠ mode=lenprobe 是受控 DoS 演示（最后才跑，跑完需拔插 USB）
```
