## 0. 结论

> **DC-S5 的内核在释放文件簇时，会完全跟随卡上被篡改的 FAT 链值去处理簇号，
> 且不做"该簇是否属于本文件"的校验。**
> ⇒ S1R2 那条越界写的**前置条件在 S5 上成立**。

| # | 结论 | 强度 |
|---|---|---|
| 1 | 只改 **4 字节 FAT** 的卡，相机**正常接受**（不要求格式化、照片可显示、可删除） | ✓ 实机 |
| 2 | 删除文件时，内核**跟着注入的簇号跳转**并把该簇也释放掉 | ✓ 实机（指纹校验通过） |
| 3 | 内核对簇号**不做归属校验** | ✓ 实机 |
| 4 | ⇒ 把注入值换成 **`≥ 491522`** 即触发越界索引 `vol_amap[≥120]` | 由 2/3 推得 |

## 1. 实验设计（可复现）

**干净场景**：相机**关掉 RAW、只拍 JPG**（避免 JPG/RW2"文件集"释放掩盖链路效果）。

```
① 相机拍 2 张 JPG（exFAT 卡，相机自己格式化）
② Mac 上：go1 自动挑第一张 JPG → 找链尾 T → 自动挑注入点 I
          → 存位图基线（含卡指纹）→ 打补丁 FAT[T] = I → fsync → 双重回读
③ 相机里【只删那一张 JPG】
④ go1check 自动比对位图，判断注入点 I 是否也被释放
```

### 1.1 本次实际数据

```
被删文件: P1000024.JPG   起始簇 39，自身链 39–111（73 个簇）
注入:     把 FAT[111] 从 0xFFFFFFFF 改成 4        （4 = 根目录所在簇）
```

```
卡指纹核对（必须一致才采信）:
  baseline: boot_ck=0x2668BB77  ClusterCount=488288  已分配 190 簇   18:02:00
  after   : boot_ck=0x2668BB77  ClusterCount=488288  已分配 112 簇   18:02:43
  ⇒ 指纹一致 ✅ 同一代卡状态

被释放 78 个簇
  注入目标簇 4 在释放列表 = 【True】        ★ 关键
  注入目标不属于被删文件自身链 = 【True】
  额外释放 = [4, 188, 189, 190, 191]
```

**簇 4 是根目录，不属于被删文件** —— 它被释放只能是因为内核沿着 `FAT[111]=4`
跳过去并调用了 `clr_alloc_bitmap(4-2)`。

（附带效果：根目录所在簇被标记为空闲 → 文件系统不一致 → macOS 无法挂载、
相机报"卡错误需格式化"。这本身也佐证了写入真实生效。）

### 2.1 过程中发现并修正的**关键技术点**（复现者必读）

| # | 坑 | 真相 |
|---|---|---|
| 1 | **Boot Checksum 覆盖范围** | 不是 512 字节，而是**整个引导区 11 个扇区**（跳 106/107/112）。S1R2 报告只写了跳过哪几个字节、**没写覆盖范围**——照字面只算 512B 会算错、相机判"卡不可用"。已在 **macOS 镜像**与**相机原生卡**两种实现上验证通过 |
| 2 | **必须 `fsync`** | 块设备写入可能停在页缓存里，**拔卡就丢**。早期"补丁没生效"很可能就是这个原因 |
| 3 | **回读要用新 fd** | 同一 fd 的回读可能命中缓存；必须**关闭后重新打开设备**再读一次 |
| 4 | **卡拔插后设备节点会变** | `disk8s1` → 可能变成 `disk9s1`，脚本需按"卷名 LUMIX + ExFAT + ≥60GB"自动重新识别 |
| 5 | **卡代次守卫** | 用 `BootChecksum + ClusterCount` 当卡指纹；基线和新位图指纹不一致就**拒绝裁决**（否则会把"重新格式化过的新照片"误算成释放簇） |
| 6 | **文件名偏移** | File Name 目录项(0xC1)里文件名从**偏移 2** 开始，前 2 字节是类型+标志 |
| 7 | **"自身链"要排除注入值** | 链集合若在打完补丁后才记录，会把注入值也算进去，从而**掩盖结论** |
| 8 | **bash 变量紧邻全角字符** | `$VAR（` 会被当成变量名一部分，`set -u` 下直接报 `unbound variable` —— 一律写 `${VAR}` |

## 3. 越界阈值（本卡实测）

```
ClusterCount = 488288   簇大小 = 131072 B(128KB)
分配位图 DataLength = 61036 B  →  map_sectors = ((61036-1)>>9)+1 = 120
内核索引公式: i = (clu-2) >> 12
```

| 簇号 | 索引 | 后果 |
|---|---|---|
| ≤ 491521 | 0–119 | ✅ 合法槽（内存安全） |
| **491522 – 524289** | **120–127** | ❌ **必崩**：kmalloc-1024 的 slab 填充为 0 → NULL 解引用 |
| **≥ 524290** | **≥128** | ❓ 落到相邻堆对象（内容未知） |

> 对照 S1R2：其卡 `map_sectors=239`（kmalloc-2048），报告称"239–255 全 0、256+ 才有有效指针"
> —— **规律与本卡一致**（map_sectors 到 slab 档位之间是填充 0）。

## 4. 下一步（第 2 级）与风险

**第 2 级 = 把注入值从"合法簇"换成"越界值"**（如 `524290`，索引 128）：

```
删除照片 → 内核调用 clr_alloc_bitmap(524288)
         → i = 524288>>12 = 128 ≥ map_sectors(120) → 越界读 vol_amap[128]
         → 若该槽是有效指针 → exfat_bitmap_clear(ptr->b_data, b) 执行【内存位清除】
         → 随后 sector_write 失败 → 相机报"写入错误 请检查卡"
```

**判据**：相机报"写入错误"即证明内存写已执行（`clr_alloc_bitmap` 是先内存写、后卡写）。

**风险**：索引 128 的槽位内容未知（S1R2 靠 GDB 定位到 269）。若该槽为 NULL → 内核 Oops。
**必须用牺牲卡**，并做好相机需拔电池的准备。

**可选增强（S1R2 的做法）**：用目录项堆喷控制相邻 slab
（`num_ext` 控制 `kmalloc` 大小，本卡需落在 kmalloc-1024，即 `num_ext≈15–30`），
把 `vol_amap[128]` 变成可控指针 → 位清除目标地址可控。
