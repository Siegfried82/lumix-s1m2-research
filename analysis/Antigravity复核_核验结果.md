# Antigravity SL3/S1M2 复核的核验结果

使用 `gemini-delegate`，模型目录及实际执行记录均为 `MODEL_PLACEHOLDER_M318`（Gemini 3.8 Flash High）。首次调用 120 秒超时、没有文本；后续读取同一个 conversation `19a01ab4-75fb-40fb-aa58-45d79d5464ed`，取得复核文本。SQLite 未确认终态、轨迹状态缺失，因此只按已返回文本处理，不宣称整个委派已完成。记录见 `antigravity_sl3_review_followup.json`。

## 可采纳的部分

- 外层 XOR FF 后的 SL3 属于相同 UPD 容器家族，目录项大小和起始偏移一致。
- 两包的标识、组件数和主程序目录散列不同，不是同一个升级包。
- 候选组件散列相同不足以证明可互刷或已有相同解码器。
- 建议实际比较组件载荷有用；Codex 已独立完成 12 项范围下载与比较。

## 已纠正的错误和过度推断

| 返回文本中的问题 | 本地核验结果 |
|---|---|
| 宣称相同散列证明相同神经网络/主体识别算法 | 仅证实目录字段与长度相同；组件尚未解码，字段含义和模型语义未验证 |
| 将目录散列肯定称为明文 SHA-256 | 填充项验证支持这一假设，但所有编码项的字段含义尚未通过解码验证 |
| 声称密文相同可直接证明算法、密钥和 IV 完全相同 | 字节相同只能直接证明被比较数据相同，不能唯一识别生成它的算法和参数 |
| 声称密文不同证明密钥不同 | 相同密钥、不同 IV/nonce/预处理等也可以产生不同密文 |
| 将 SL3 的 hm_d_nw_1st 载荷起点写成 171998208 | 这是相对字段；实际文件偏移须加 512，为 171998720 |
| 目录结束位置错误 | exclusive end 分别为 SL3 0x18d8、S1M2 0x1934，按 0x2ec + count×92 计算 |
| 主程序散列列举错误 | SL3 为 7b8e7cc6d79250987298db51e61bba5487fc0ac23c3b2b3ae21ece62084c9326；S1M2 为 003209de63fb3e9c0f576493d5c49cf4dacfc9c6acd53ba19234d4e62a8c833d |
| 有限 AES 试验失败可以证明 AEAD、非确定性 IV 或私有变换 | 阴性仅排除被测候选组合，不能识别实际机制 |
| 将互刷必然导致永久损坏作为确定结论 | 当前没有相应实验或恢复机制证据；不兼容且未授权，不进行互刷，不能捏造必然结果 |

## 继续实验

利用已取得 SL3 头部构建有限候选 key 集合，执行不依赖 IV 猜测的 CBC 全 FF 假设检验。对 S1M2 只加入未在既有 S1M2 头部候选中出现的 SL3 候选；对 SL3 使用两包候选的并集。匹配前不推断 IV，匹配后必须再校验完整 SHA-256。

脚本 `probe_sl3_cross_header.py`，结果 `sl3_cross_header_probes.json`。这不是 AES 密钥空间穷举，也不验证相机可修改性。
