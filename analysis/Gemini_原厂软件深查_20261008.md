### 2. 固件更新传输链与“电脑端不参与解密”的实证

在 `<LOCAL_WORKSPACE>/analysis/tether_update_path_comparison.json` 与 `<LOCAL_WORKSPACE>/analysis/tether_client_transport_paths.json` 中，比对了 Tether 2.12 与 AW 2.8 的底层更新实现，证实了以下事实：
1. **直接调用序列 100% 一致**：
   `libLmxptpif.dylib` 中 7 个关键更新符号的 arm64 调用链完全吻合：
   - `__Z30LMX_func_api_FirmwareUpdate_ThPcPhjjhhPj`（更新主工作线程）
   - `__Z46Lmx_func_api_fwup_Check_FileType_from_FilePathPhPj`（通过 open/read 读取文件前 3 字节，比对 `0x55, 0x50, 0x44` 即 ASCII `"UPD"`）
   - `__Z39Lmx_func_api_fwup_Get_FileData_FileSizePhPPvPS_PjS3_Pi`（获取全文件大小并一次性分配缓冲读入）
   - `__Z32Lmx_func_api_fwup_Get_Event_InfojhPcPj`（接收固件就绪事件）
   - `__Z32Lmx_func_api_fwup_Send_FWUP_DataPhjjjhPc`（核心分块发送函数）
   - `__Z35Lmx_lib_ptpif_LmxExt_Send_Data_InfoPhjPc`（发送数据包头）
   - `__Z30Lmx_lib_ptpif_LmxExt_Send_DataPhjPc`（发送数据块实体）
2. **UPD 原始分块传输细节**：
   - 分块大小严格固定为 `0x7d000` 字节（即 512,000 字节，约 500 KB，非 512 KiB）。
   - 地址 `0x4228c`（AW）与 `0x46e4c`（2.12）直接使用原始文件缓冲区指针叠加累计偏移量，未经过任何中间解密或转码算子，直接传递给 `Send_Data`。
   - 数据包说明采用 PTP 扩展操作码 `0x9606`（`Send_Data_Info`），数据体传输采用操作码 `0x9607`（`Send_Data`）。
   - 开始更新前通过操作码 `0x9406` 传入准备控制字 `0x09000013`；全部分块传输完毕后，再次调用 `0x9406` 传入完成控制字 `0x09000014`，触发机身内校验，最后由 `LMX_func_api_Power_Ctrl_DeviceReset` 重启设备。
3. **结论**：电脑端原厂软件在固件更新过程中**只充当原样搬运工（Raw Transport）**，不对 UPD 内部 49 个 Flag=3 加密组件进行解密。UPD 的解密与 RSA/SHA-256 签名校验完全发生在相机的安全引导区（Secure Boot/ROM/`loader1`）内。

### 3. UPD 容器与 Leica SL3 跨机型对比事实

- **S1M2 升级包（`S1m2_V14.bin`）**：
  - 文件大小：171,867,648 字节，SHA-256：`e91620854dd435131e03178076b486767cf9a3d2cfd62d173c537cb2afe9ea0f`。
  - 外层容器：全局异或 `0xFF`。解码后头部偏移 0x00 与 0x200 呈现 `UPD\0`；SoC 平台标识为 `MC8243`；组件总数为 62 项。
  - 49 个组件标记为 Flag=3（加密载荷），字节信息熵均在 7.997~7.999 之间；Flag=2 均为 0 字节占位项；第 61 项 `mbr_dummy_d`（131,072 字节）去除 XOR 0xFF 后全为 0xFF，其实际散列与目录内存储的校验和精确吻合（阳性对照）。
- **Leica SL3 升级包（`SL3__420.lfu`）**：
  - 官方下载源：`https://leica-camera.com/sites/default/files/SL3__420.lfu`（前 8192 字节存根存放在 `analysis/sources/SL3__420.first8192.bin`）。
  - 外层同样为 XOR 0xFF 混淆；SoC 平台标识为 `MC7231`，组件总数为 61 项。
  - 9 个神经网络组件（`hm_d_nw_1st` ~ `8th` 及 `hm_d_reid`）在目录中登记的明文预期 SHA-256 与 S1M2 对应项**完全相同**。
  - 但在提取实际密文载荷（`<LOCAL_WORKSPACE>/analysis/sl3_payload_comparison.json`）后比对发现：**两者在升级包中的实际编码密文完全不同**。这意味着两款机型即使共享了相同算法模型源文件，各自采用了不同的机型派生密钥或加密 IV，不可跨机型直接移植密文。

## 二、 Panasonic 原厂软件实际能力盘点

通过对照 Panasonic 官方功能支持矩阵（网页快照：`analysis/sources/lumixtether_supported_functions.html`，源地址：`https://av.jpn.support.panasonic.com/support/global/cs/soft/download/d_lumixtether2.html`），以及提取 `LUMIX Tether`（主程序）和 `libLmxptpif.dylib`（底层协议库）中的 520 个 `LMX_func_api` 导出函数，官方软件在电脑端所具备的真实能力与架构分层如下：

### 1. 官方功能支持矩阵（S1M2 对照）

在官方功能表中，DC-S1M2 / DC-S1M2ES 与 S5M2X / S1RM2 处于同一最高支持层级：
- **连接介质**：Ethernet（有线网口）与 USB 均标为 **OK**。
- **实时取景控制（LV mode ON/OFF）**：**OK**。
- **多机协同与多画面（Multiple connect / Multi-view）**：**OK**。
- **菜单远程操作（Menu operation）**：**OK**（旧款 S1/S5/GH5 均为 NG）。
- **相机设置数据保存与恢复（Camera setting data save/load）**：**OK**（旧款均为 NG）。
- **固件更新（Firmware update）**：**OK**。
- **HDMI 录制联动（Recorder via HDMI recording control）**：**OK**。
- **电动变焦控制（Zoom operation）**：标为 **NG**。

### 2. LUMIX Tether 2.12 核心功能入口与数据控制

通过对主程序反汇编分析，原厂客户端由 Qt/QML 构建图形前端，通过 `DeviceAdapter` 类封装 PTP 协议，在电脑端具备以下真实配置项与数据流：

```
[UI 界面: QML 模块] 
   └── LTMainObject / LTMainWindow / LTOptionButtonDriveModePopup / LTMainMovieQualityPopup
         │
[核心适配层: DeviceAdapter & ApplicationSettings]
   ├── 传输策略: RawTransferType (StoLocType_SdCard, StoLocType_SdCardPc, StoLocType_PcOnly)
   ├── 参数配置备份: setup_file_config_setting_save_setting / restore_setting (15MB 结构体缓冲)
   └── 驱动模式: DM_Single, DM_Burst, DM_HRS, DM_HANDHELD_HRS, DM_Bracket
         │
[底层协议库: libLmxptpif.dylib (520 个 LMX_func_api)]
   ├── 连拍与快门: LMX_func_api_CameraMode_Set_DriveMode / LMX_func_api_SS_SetParam
   ├── 图像品质: LMX_func_api_ImageInfo_Set_ImageQuality / Set_ImageJpegHeifQuality
   ├── 视频参数: LMX_func_api_Mov_Config_Set_Quality_mode_Param / Mov_Filter_Set_Compression_method
   ├── 对焦与识别: LMX_func_api_AF_Config_Set_AF_Automatic_Reco_Param (人/动物/车辆/部件)
   └── 对象传输: LMX_func_api_Save_ObjectData_to_File (通过 PTP 句柄下载生成好的 RAW/JPG)
```

1. **设置数据备份与写回（`.CAM` 配置文件）**：
   - 主程序符号 `__ZN11lumixtether13DeviceAdapter38setup_file_config_setting_save_settingE7QStringS1_` 在地址 `0x1000987bc` 明确分配大小为 `0xf00000`（精确为 15,728,640 字节，约 15 MB）的连续缓冲区。
   - 随后调用底层 `LMX_func_api_SetupFilesConfigSetting_Get_Info`、`Get_Compatible`、`Get_MaxRecvBuff` 以及 `Set_Data` / `Get_Data`。
   - 可以在无需连接物理相机的情况下，离线研究被导出的 `.CAM` 纯数据结构；也可以通过原厂软件安全将合法配置下发回相机。
2. **RAW 传输模式控制（`RawTransferType`）**：
   - 电脑端可配置图像存储策略：`StoLocType_SdCard`（仅机身存卡）、`StoLocType_SdCardPc`（机身与电脑同时保存）、或电脑单独接收（`CARDLESS.RW2`）。
   - 在联机联调模式下，只要相机触发拍摄生成了对象句柄，电脑端即可自动拉取完整 14-bit RAW 文件至本地磁盘。
3. **驱动模式与连拍枚举（`DriveMode` & `BurstSpeed`）**：
   - 支持枚举清晰包含：`DM_Single`、`DM_Burst`、`DM_Bracket`、`DM_HRS`（三脚架高分辨率）、`DM_HANDHELD_HRS`（手持高分辨率）。
   - 连拍速度支持：`BS_HighSpeed`（机械/电子高速）、`BS_Mid`、`BS_Low`，以及一整套电子快门特有超高速枚举（`BS_EleFast20`, `BS_EleFast30`, `BS_EleFast60`, `BS_EleFast70`, `BS_EleFast75`）。
