# PR #5 的 S1M2 适用性：源码层核验

## 已确认

官方 https://ospo.panasonic.com/oss/dsc/DC-S1M2ES.html 当前标题明确列出 DC-S1M2ES、DC-S1M2。本地 download_manifest.json 给出的内核包来源为该型号目录，归档 SHA-256 实际复算为 2067822653621ff9f3e1acdad99d7777812d0dc1036007921014da18fc9c6fce，与清单一致。逐文件哈希见 source_model_comparison.json。

本地包的 composite.c 校验低字节接口编号，却将原始接口编号传给 get_alt/set_alt。f_fs.c 的 revmap 参数为 u8；current_alt_setting 的实际索引仍使用 unsigned interface。与贡献者描述的根因一致。因此本线索具有 S1M2 官方发布源码支持，不能仅归为 S1RM2 跨型号猜测。

## 新核对的可达性条件

set_alt 会先做接口映射、检查 FFS_ACTIVE，再调用端点 enable。enable 将返回值初始化为 0；若没有任何端点满足 interface 与 alt 的完整匹配，循环不会把返回值改成错误，仍可能走到后续数组写入。故“不存在那个完整接口编号的端点”本身不保证阻止该路径。disable 的其他分支还会调用连接重置辅助函数；写路径具有通信状态副作用。

get_alt 若数组取出的 unsigned 值转换为负 int，composite 会丢弃返回值而不回传数据，故报告所谓部分位置不可读不能直接解释为该地址未映射。低字节泄露也不自动等于可取得完整指针或连续内存。

## 尚未证明

官方发布源码不等于用户机身 V1.4 的逐字节运行内核。实际 USB 功能是否使用 FunctionFS、接口映射/运行状态、漏洞是否在部署版本中修补、作者的实机结果是否可独立复现均未确认。没有证明整机 RAM dump、任意地址读取、代码执行、解密密钥或机内功能修改。

本轮只做离线源码核验，未向相机发送越界读写请求。下一步优先补充机型/版本与 USB 接口归属证据；不把有限读写原语直接称为完成目标。
