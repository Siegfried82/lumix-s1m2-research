## 0. 模板盘的已知特性（重要背景）

模板是 **S1M2 V1.4 真机格式化卡的逐字节克隆**（`camera_ref/camera_*.bin` 真机读回 + `camera_ref/make_cam_template.py` 重建），
改动仅三处：清空 100_PANA/PANA_GRP 目录内容、丢弃 macOS 后写的 `.fseventsd`、根目录追加 TESTFILE.BIN（64KB，簇 10）。

**相机亲笔 exFAT 的私有特征（全部原样保留在模板里）**：

- 几何：MBR 分区@32768(type 0x07)，exFAT 2.1，SecBits=9/ClusBits=8（128KB 簇）/NFats=1，FATOffset=16384/FATLength=16384（各 8MB，2× 超配），ClusterHeapOffset=32768，RootCluster=4，ClusterCount=978512；
- **主引导扇区 VolumeLength=0**（分区总长只写在 MBR 分区表里）；备份引导扇区与主引导只差 1 个字节（offset 106 VolumeFlags：主=0x0002 脏位、备=0x0000）；
- BootChecksum 扇区 11 = 重复 dword `0x26883579`（**不是**规范校验和，是固定魔数）；BootCode=0xF4 填充；扇区 21 = 16 字节 blob；
- FAT[0]=0x0FFFFFF8、FAT[1]=0xFFFFFFFF（脏位态，永不清理）、簇 8-9 预分配 EOC（保留对）、分配器留洞（FAT[37] 跳过）；
- **目录项私有布局（已全解）**：0x83 规范；**0x81/0x82 次项用 C0 式偏移：FirstCluster@20-23、DataLength@24-31**（不是规范 +8/+12；位图 DL=122314、upcase DL=5836 实测吻合），VDL@8-15=0，byte 4-7 未解（82 里是 0d d3 19 e6，照克隆）；
- 0x85 主项 = `85 02 X(4B) 00×6 dt×3(FAT 时间戳) 6464 00×6`（无 GUID、无 SetChecksum）；X 高 16 = 类别（目录 0x0010/文件 0x0020，+2 位=NoFatChain），低 16 未知哈希（模板里同类别克隆）；
- 0xC0 = `c0 flags 00 NameLength(1B@3) NameHash(2B@4,字节级 ror16 over UTF-16LE 名字字节无尾零) 00 00 VDL(8B) 00×4 FirstCluster(4B) DataLength(8B)`——文件条目 VDL=文件大小、目录条目 VDL=1 簇；
- 0xC1 = `c1 00` + 名字 UTF-16LE 从 offset 2 起（无 NameHash/NameLength）；文件条目集 = 85+C0+C1（无 A0/A1/A2）。

**已知兼容性**：macOS 写入的 `.fseventsd` 用的是同一祖先布局（版本 0x0012、哈希算法不同）——相机驱动能容忍外来条目（真机卡带 .fseventsd 仍正常读写）。

**推论**：cam_seed 若被相机接受 = 模板克隆成功、后续 8 张突变全在"相机自己的格式"上做，指纹结论比 Apple 模板干净得多；若 cam_seed 都被拒 = 克隆有漏（先报现象）。

## 1. 准备

- 介质：SD 卡（相机格式化过的、无重要数据的卡即可）；建议先做基线（第 2 步）再刷突变镜像。
- 相机用满电电池或接电源适配器；测试中**绝不选"格式化"**（只读观察，不写机身/卡）。
- 刷镜像（只写前 40MB）：`sudo dd if=images_cam/<名字>.img of=/dev/rdiskX bs=1m count=40`（核对设备号后再确认；GUI 授权走 osascript）。
- 相机设置：菜单 → USB 模式 → **USB-SSD**（外置 SSD 外录模式，相机为 host）。

## 2. 基线（先做，一次）

1. 刷 `cam_seed.img` 前 40MB 到 SD 卡；
2. 相机插卡开机（任何模式均可，开机即读卡）；
3. 观察 60 秒：剩余张数正常、回放能看到 TESTFILE.BIN 的目录、无"记忆卡错误"；
4. 记录结果码（见下表）→ 这给出"相机亲笔模板"的对照行为。
5. 拔盘。相机重启后恢复正常使用。

> 若基线正常（M）→ 模板克隆成功，进入第 3 步。
> 若基线异常（F/U）→ **先停，把现象告诉我**：克隆哪一步漏了就是关键线索（VolLength=0？0x26883579？85 项布局？）。

## 3. 突变镜像测试循环（每张 1-2 分钟）

1. 刷一张镜像前 40MB 到 SD 卡；
2. 相机插卡开机；
3. 观察 30 秒（不点进回放也行——开机列目录即触发）；若进得了回放，尝试播放 TESTFILE.BIN 5 秒；
4. 记录：镜像名 + 结果码 + 屏幕文字（若有）+ 异常细节；
5. 拔盘 → 相机关机再开机（冷重启，清掉可能的状态）；
6. 换下一张。

**建议顺序**（KASAN 预筛后的 8 张短名单，每张预期见 `KASAN_RESULTS.md` §3）：
- 先基线（第 2 步，`cam_seed.img`）；
- 再 **`cam_d19_upcase_chain_loop`**（相机模板复验：v5.7 上挂载成功+根目录列空；相机上 H=目录迭代无 i_size 门）→ **`cam_b16_fat_off_past_heap`**（相机模板复验：KASAN 崩溃同款复现，测松下错误路径与 panic 策略）；
- 再按 `cam_b14 → cam_b06 → cam_d12 → cam_d17 → cam_m11 → cam_d18` 顺序（血统指纹系）；
- 每张之间冷重启。

## 5. 安全与收尾

- 相机死机（H）是预期内的观察结果之一；拔电池重启即可，**不要**在死机状态下反复插拔其他设备。
- 若某张镜像导致**连续两次**同样死机，跳过它并在上报中标注"可复现"——可复现的死机就是下一步深挖的候选。
- 若任何一张镜像导致相机**开机循环无法进入菜单**，停止测试；确认相机在拔盘、换正常卡后能恢复再继续。
- 测试完成后：相机格式化一张正常卡（相机内格式化），确认一切恢复。

## 6. 结果解读预告（看到什么意味着什么）

> 以下"祖先预期"已由 KASAN VM 实测锚定（v5.7 祖先行为，见 `KASAN_RESULTS.md`）——相机私有驱动可能更旧/已补，与祖先行为的**偏差本身就是发现**。相机实测只做 §3 的 8 张，判读对照：

- **d19 挂起（H）** → 相机目录迭代无 i_size 门（与 v5.7 不同源或更老分支），插卡即冻。**若挂载成功且相册空/无照片** → 与 v5.7 相机模板复验一致（负 i_size 短路 readdir，机理见 `KASAN_RESULTS.md` §5②）。
- **b16 自动重启（R）** → 相机错误路径同源崩溃且 `panic_on_oops` 开启；**仅报卡错误（F）** → 松下改过错误路径或崩溃不 panic。
- **b14 被拒（F/U）** → 松下自己验证 BootChecksum（祖先完全不验）。**预期 M**（no-op）。
- **b06 被拒（F）** → 松下加了 NumberOfFats 校验（祖先不验）。**预期 M**。
- **d12 出现 R/H/异常** → 松下按规范读 NameLength（祖先固定扫 15 字符）。**预期 M**（no-op）。
- **d17 挂载成功** → 相机位图校验比 v5.7 祖先更松（更老分支信号，为第二轮突变指路）。**预期 F**（祖先实测：alloc-bitmap 门拦截）。
- **m11 挂载成功** → 相机 vfat 非原版内核代码。**预期 F**（原版 4.19.124 有链环检测，实测干净拒绝）。
- **d18 正常（M）** → 确认"数据读按 DataLength 截断、目录迭代裸奔"的祖先行为组合也在相机成立（与 d19 成对解释）。**预期 M**。
