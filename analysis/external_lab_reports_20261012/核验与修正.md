## 已发现的修正

- p084h6/a.java:74–75、247–248 显式 POST auth；140–141 显式 POST lut/info，参数含 Authorization 头与 LutCameraPostBean 请求体。相册 count/info/thumbnail 亦为 POST。外稿所谓静态没有路径、auth 未知、GET lut/info 均与本地样本不符。相机是否另接受 GET 未实测。
- p084h6/h.java:303–335 的 j() 构造含 Basic 凭据的客户端，k() 将其绑定 panasonic.jp/support/share/eww/com/software/lumix_lab/。相机客户端分支使用 b.f22722a 和其他客户端。存在凭据不证明它属于相机身份认证，更不证明相机接受它。
- C1410v.java:162 使用 UUID.randomUUID；因此“UUID 无熵源”不成立。随机客户端标识也不等于服务端 token 可预测。
- AuthRequestBean 字段只是客户端申请结构，不能证明任意客户端均获令牌、令牌权限完整或无蓝牙/配对前置校验。外稿自己仍注明鉴权端点及 LUT token 要求未确认，与已实锤越权的断言冲突。
- 空实现 TrustManager 是客户端不校验证书的证据；不证明相机自签证书细节、实际 MITM 成功或所有接口权限。
- 内存中出现 URL/JSON 不等于线上完成请求；样例 JSON 与 Content-Length 487 未附完整报文，不能当完整请求捕获。
- Bean 字段、可控文件名不证明服务端缺失范围/路径检查；响应拼写错误不证明手写 C/C++、内存不安全或漏洞概率。
- RequestBody 和字段名不证明实际分块结构、块大小/序号语义；需真实发送调用及报文消费者核验。
- 官方格式化、关机 API 的存在不自动构成后门或漏洞。
- 固定内存区间不适用于所有 Android 进程；须核对 maps 与实际读出范围，缺少原稿所引镜像无法验证。
- “只读零风险”“空槽位即可限制路径穿越影响”“断电保证恢复”均不能成立。此处仅静态核验，未授权异常写入或 fuzz。
