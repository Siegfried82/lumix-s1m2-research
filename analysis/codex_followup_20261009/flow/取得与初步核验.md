## 签名完整性

使用项目已有 JADX JAR 内的 Android `apksig` 库，通过自行编写的 `VerifyApk.java` 对四个 APK 做静态完整性检查，Android 最低检查版本 30：

- 四个分包均 `verified=true`、v3 签名通过、错误和警告均为零。
- 四包签名证书 SHA-256 均为 `f814f6af7e93ddd39b73b90b32192cd5a128b83fda2340ee7592f14b6483624b`。
- 签名完整性证明样本与该签名者匹配；尚未从独立的 Panasonic 官方分发固定证书指纹，不能据此单独确认发行者身份。

结果见 `signature_verification.jsonl`。执行的是本地验证代码，未执行 APK 内程序。

## 可直接复核的协议发现

1. `decompiled/sources/com/panasonic/jp/flow/wireless/http/NetworkManager.java:381-384` 的 `saveToken` 确实构造带单引号的 Bearer 字符串，补上 PR #3 客户端代码证据。不证明相机端普遍强制这种语法。
2. `wireless/http/ApiService.java` 存在 30 个 HTTP 注解、27 个不同路径，包含 auth、拍摄设置、取景、回放、LUT、XML 通道及取景框控制。完整路径与行号见 `http_interface_inventory.json`。该接口类没有明确的内存读取/固件导出路径名，不能用名字扫描排除服务器隐藏接口。
3. `wireless/udp/tls/TLSClient.java:42` 列出 7070、8080、9090；本地 APK 确有 PR 所列证书/密钥资产文件名。未输出、提取或使用私钥内容，尚未分析相机端信任行为。
4. 已定位另一个具体待核验的读取面：USB/PTP 传输实现位于 `p040r1/g.java`、`p040r1/h.java`、`p038q0/X.java`、`p038q0/a0.java` 等，不能把 HTTP 类审计当作整个 Flow 的协议穷尽。

## 反编译缺口及下一步

JADX 已处理 11,762 个类，但以退出码 3 结束，报告 169 个反编译错误。已生成的文件可定点检查；缺失或失败的方法必须回到原始 DEX 或低级指令，不能宣布整个应用调用链完整。

尤其 `RemoteUDPPacketManager.java` 的大方法有反编译失败提示，仍需取得其指令级表示。下一步优先追踪实际 USB/PTP 读取参数和 UDP/TLS 请求分发，识别是否存在与 Lab/Tether 不同的明确只读入口。

目前没有从此样本获得 S1M2 程序明文、RAM 转储能力或新增机内功能。样本取得使上述关键调用链第一次能够用本地原始 APK 独立核验。
