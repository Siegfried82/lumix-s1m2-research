# G3 / GF2 / GF3 / GX1 真实 UPD 消费者核验

2026-10-11。四个已定位真实官方更新路径均只接受 revision `0x101`、crypt selector `0/2`，明确拒绝 `0x200` 和 `3`。本轮没有取得新格式消费者；结论来自实际文件读取后的条件分支，不来自样本自身头部。结论限于所定位调用链，不声称穷尽全部其他消费者。

仅静态读取固件、反汇编和主机 OpenSSL 离线重放；未执行固件或目标 ISA，未联网、访问或写入设备。输出只在本目录。

## 逐机独立映射与 key 来源

每份镜像自己的入口file0x600向ISR0x40000018跳转，ISR实际位于file0x618；启动代码另将VBR设为0x40000000，因此主段VA=file+0x3ffffa00。不是借用GH2常量。

| 机型 | 驻留段ROM起点→RAM0x74000000 | 驻留key file | overlay复制函数 file | ROM源→实际写入地址→执行入口 |
|---|---|---|---|---|
| G3 | `0x405d17b0` | `0x5d1dd8` | `0x4c5d` | `0x408c0000 → 0xbbbc0000 → 0x7bbc0000` |
| GF2 | `0x4054f8c0` | `0x54fee8` | `0x4c4e` | `0x408c0000 → 0xbbbc0000 → 0x7bbc0000` |
| GF3 | `0x4059d0e0` | `0x59d708` | `0x4e53` | `0x408c0000 → 0xbbbc0000 → 0x7bbc0000` |
| GX1 | `0x406398fc` | `0x639f24` | `0x4f37` | `0x40880000 → 0xbbb80000 → 0x7bb80000` |

复制函数逐32位字读ROM/写目的段；各自启动caller确实调用它，随后设置相应执行入口地址。每份对应overlay在file0x8c0600（GX1 file0x880600）具有自指入口/向量，与自身启动跳转一致，分别得到overlay VA=file+0x7b2ffa00。写入地址与执行地址的别名关系由代码使用推断，本轮未实测MMU/缓存。见每机型`main_vectors_and_resident_copy`、`overlay_copy_caller`、`overlay_copy`、`overlay_vectors.disassembly.txt`。

每个更新caller在头读取成功后，明确把RAM0x74000028、长度16交给key setter，再进入主体处理。setter把16字节复制到更新对象+0x28；其ROM来源由各自启动复制核实。用各自驻留key、各原密文IV[0x80,0x90)，AES-128-CBC无padding重放[0x200,EOF)，四个完整主体MD5均匹配头[0x40,0x50)，并与既有明文逐字节一致。完整key和摘要保存在[verification.json](verification.json)。这一阳性不替代消费者分支核验。

## 实际读取、selector与拒绝路径

各自`updater_header_crypt_and_directory.disassembly.txt:110–170`显示虚函数从文件读512字节，再从该缓存+0x08读revision、比较257并逐字节检查`UPD\0`；不是0x101便返回0x80000064。`:188–250`读取digest selector+0x2c、crypt selector+0x34：crypt=0跳过，=2创建AES对象，其他值返回0x80000006。`:260`以后从头+0x38定位主体、按+0x3c长度读入，同一主体随后进入变换和MD5比较。

## 解码后目录实际读取与 ISA 边界

同一处理器校验明文内层头后，`:588–610`从内层头+0x20取偏移、加上主体缓存基址、保存到更新对象+0x50。各样本内层+0x20=0x200，因此指向file0x400目录计数。`:608–654`的getter在完成标志有效时读取计数；entry getter检查index≥0且index<count，再从计数后4字节开始读取记录，读记录+0x0c/+0x10/+0x14对应relative_start、size、field_addr。

index×24处字节`f9 00 18`在GNU am33显示`udf00 24,d0`；GNU官方binutils的AM30 opcode表有`mulq`别名。保留该ISA语义限制，未声称目标硬件执行或完整ISA仿真。目录指针、计数、字段读取有明确独立指令；这一限制不影响前面的revision与crypt拒绝分支。

## 复现、覆盖与未知项

在项目根目录运行`python3 analysis/later_legacy_consumers_20261011/verify_consumers.py`。依赖本地已构建GNU am33 objdump、系统OpenSSL、Python标准库。脚本重新计算全部输入SHA，独立解析目录和resident/overlay来源，实际扫描每个完整输入的所列精确字节模式，生成24个反汇编窗口并重放四个完整主体。[disassembly_manifest.json](disassembly_manifest.json)逐窗保存输入/工具/输出SHA、地址范围及完整参数；[commands.json](commands.json)保存已执行命令，OpenSSL的stdin范围在脚本明确记录。

完整文件精确模式阴性不排除不同指令编码、间接入口或其他消费者；没有把这种阴性当作“全部其他消费者不存在”。本轮闭合的是四个定位到的真实官方更新调用链拒绝新格式。S1M2的0x200/selector3消费者仍缺失，没有由此推出其算法、key、运行能力或新增功能。
