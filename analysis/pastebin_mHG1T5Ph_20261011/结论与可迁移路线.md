## 1. 结论

这份经验值得保留：它提供“通过已有设置接口选择机身菜单未显示的参数”的具体例子。源文件声称在 **GX9 FW 1.5** 上有效。本轮确认了它的命令结构，以及其中部分参数确实出现在保存的 S5 原始菜单中；**没有独立验证 GX9 实际录像效果，也没有证明 S1M2 接受相同命令**。

可迁移的是研究方法：公开菜单/能力 → 候选参数 → 状态或配置读回 → 实际输出 → 重启/自定义模式持久化。仅接口返回成功、图标变化或配置某个字节变化，均不能代替实际功能验收。

这条路线可以研究已存在功能的选择和限制，尚未给出新增机内 HDR、自定义声音、LUT 计算程序或固件解码方法。S1M2 的 49 个不透明编码组件仍未解码。

## 4. 客户端中的真实线索及边界

已有 LUMIX Sync 2.0.17 反编译材料中：

- `analysis/sources/lumix_sync_static/decompiled/sources/B5/o.java:382` 解析 XML 的 `videoquality` 属性；`p188x5/o.java:353` 解析延时摄影能力中的同名元素。二者是解析器，不能仅由字符串引用声称找到画质设置实现。
- `B5/a.java:555—606` 包含通用菜单发送器和 `setsetting` 发送器；`G5/a.java:81—111` 调用菜单发送器并在成功结果后请求当前菜单。
- `p188x5/C2203b.java:47—63` 从相机菜单 XML 提取 `cmd_mode/type/value/value2`；`com/panasonic/jp/view/setting/c.java:738—754` 把这些属性传给发送路径。该链显示应用会回传机身声明的菜单参数，本次没有找到它生成这8个隐藏值的证据。
- USB/PTP能力文件记录的是整数枚举；与 HTTP 字符串之间的语义映射仍未闭合。不能用现有 PTP 枚举证明这些 Wi‑Fi 字符串适用于 S1M2。

## 5. 对当前目标的推进方式

| 方向 | 这份经验的帮助 | 仍缺的关键证据 |
|---|---|---|
| 隐藏录像规格/已有设置组合 | 提供具体参数选择范例，可比较菜单与实际输出 | 同型号同版本参数来源、读回及实际文件 |
| 内置声音选项 | 支持把选项变化和资源替换分开验收 | 不能由此证明自定义音频导入 |
| LUT 配置存储 | 可借鉴单变量前后配置对照 | 正常官方导入前后备份及原LUT路径仍待提供 |
| HDR/高分辨率输入帧导出 | 可查现有菜单/协议是否声明相关路径 | 未取得相应处理函数、输出或可调用证据 |
| S1M2 固件解码 | 不提供 key、算法或新格式消费者 | 实际接受0x200/selector3的处理代码仍是主线 |

后续设备验证需要另有明确授权；本轮不发送候选设置。可先分析用户已有、由正常官方操作产生的材料：

1. 型号、固件版本、PAL/NTSC等制式，以及同一拍摄模式下的菜单/能力与配置基线。
2. 每次只改变一个官方设置的配置、状态与录像样本，先建立已知成功对照。
3. 对实际文件分别检查容器、编码器、分辨率、帧率、位深/色度信息、视频流码率和持续录制情况。文件总码率包含音频等开销；可变码率受画面复杂度影响，标签或单段低码率不能独立判定失败。
4. 将请求返回、状态/配置变化、实际文件变化、重启与自定义模式持久化分别记录，避免把前一层当作后一层成功。

本轮并行完成了较晚旧机型 G3/GF2/GF3/GX1 更新消费者的离线分析：各自定位的官方路径仍只接受0x101及crypt0/2，未取得新格式消费者。主线程重新生成24个窗口并用各自驻留key完整重放四份主体，MD5与既有明文均一致。详见[四款旧消费者报告](../later_legacy_consumers_20261011/较晚旧固件消费者核验.md)。该支线与本经验独立，结果不排除所有其他静态路线。
