# AW 2.8 与标准 2.12 的维护接口比较

只静态读取此前已取得的软件文件；没有运行软件或连接机身。

在标准版中定位的 12 个维护相关函数，在 AW 版库中全部存在，逐函数指令数也相同。保留参数常量和读写指令，将本函数内跳转地址转为指令编号、外部存根地址转为注释中的符号、带明确注释的文字/符号重定位转为占位后，**7 个函数的指令序列完全一致**。

这七个包括通用 `Mnt_GetInfo`、USB 模式查询、`SetMntInfo` 以及预览控制/流接收的底层封包函数。它们没有显示 AW 版额外提供地址可控的内存读取。

另外五个函数保留差异：日志文字寻址、栈保护符号寻址，以及两处未标注的静态数据寻址。随后按 Mach-O ARM64 段映射取得静态字节，确认 USB 写入头部的 8 字节和预览函数静态表开头的 16 字节在两版完全相同。证据为 `maintenance_literal_check_20261008.json`。仍不将有限静态比较当作运行时等价证明。

这项比较限定于已识别的十二个函数，不证明两版库的全部功能相同，更不证明机身不存在其他诊断入口。

证据：`maintenance_aw_standard_normalized_20261008.json`（原始文件散列、函数行号、保留的差异）。可复现工具：`compare_maintenance_functions.py`。

这十二个函数的有限比较未提供新的 RAM 读取候选。下一步可检查 AW 版独有调用者；无需再重复追踪已经相同的通用封包函数。
