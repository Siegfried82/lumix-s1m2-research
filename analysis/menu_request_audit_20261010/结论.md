# Tether 菜单调用与固件读取入口核验

## 可定位证据

Tether 应用直接构造四种菜单请求：Start_Menu = 0x09000021；End_Menu = 0x09000022；Touch_Down_Menu = 0x09000023；Touch_Up_Menu = 0x09000024。前两者参数计数清零，后两者计数为 2，将调用者的两个整数放到 REC_CTRL 偏移 +8 与 +12。对应源行与完整片段、输入散列保存在 evidence.json。

库 Menu 包装函数在反汇编行 68173–68199，将 0x9416 与结构传给 Rec_Ctrl_with_data（指令 0x43f3c、0x43f48）。既有 58 项控制表中，上述四项分别为 0、0、4、4 字节；触摸项使用 UINT16 打包，将两个 32 位结构值各取低 16 位发送。其数据封包包含 tag、载荷长度及载荷。此处是主机代码的静态结论，没有机身支持验证。

触摸调用者可见的边界判断是第一个参数按无符号比较不超过 999，第二个参数符号位不能置位。不能把该片段改写成“两坐标都在 0–999”，也不能把截断行为解释为设备端可利用缺陷。

## 对突破目标的影响

菜单四项属于远程菜单启停/触摸控制。Backup_Req 则通过另一封包器 Rec_Ctrl_with_params 发送 PTP 参数；现有调用者指向照片风格备份、恢复及删除。两者不能仅因共用 0x9416 就混用封包格式，也都没有证明固件或任意内存读取能力。

本次补齐四个控制表项的主机语义，排除了将这些路径当成现成固件导出接口的依据。未取得程序明文、机身侧调用实现、固件修改运行或模块加载结果；没有执行任何机身命令。
