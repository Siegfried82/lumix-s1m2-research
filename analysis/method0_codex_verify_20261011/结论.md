# method=0 独立核验

2026-10-11。AGY 输出了 decode_method0.py、method0_evidence_report.md、method0_verification_results.json 及六份解码文件。其委派 JSON 当前为空，不能核实这轮 finished/model_verified 状态；以下结论来自实际文件与 Codex 独立验证，不以委派状态作为证据。

## 验证结果

verify.py 独立遍历六份源文件的每个34字节记录，按大端17个16位字计算横向模65536总和；同时累计前16列（含最后一条尾记录）的纵向模65536总和。所有横向与纵向总和均为0。剥离每条记录最后2字节并移除最后32字节尾块后，输出逐字节等于AGY保存的镜像。

GH1 V1.2/V1.3、GF1 V1.1/V1.2、G1 V1.5 的结果各8MiB；G2 V1.1为16MiB。完整哈希和记录计数见 verification.json。

静态证据也一致：PTool反汇编0x4f37f6比较记录位置与0x20；0x4f38f3检查低16位校验和；0x4f3930将输出长度减0x20；0x4f450d调用该解码函数。

这是无密钥校验封装的可靠复现，不是AES密钥恢复。不据此断言所有机内数据都没有保护，也不声称新机型可套用这一封装。

AGY报告的补丁原值验证计数与内存映射细节未在本轮全部独立复核，保留为报告中的额外证据；本轮确认依赖全文件横纵校验与独立剥离一致性。
