# PTool `method=0` 落盘解码变换与内部 RC4 内存变换静态分析报告

## 1. 关键结论与变换区分

通过对 `analysis/sources/ptool_static/ptool3.exe`（`disassembly.txt`）的离线静态分析，确认 PTool 中 `method=0`（对应 GH1、GF1、G1、TZ5、G2）的**落盘（on-disk）变换并非加密**，而是 **34 字节分块（32 字节原始镜像数据 + 2 字节大端序 16 位二补数横向校验和）外加文件末尾 1 个 34 字节纵向+横向校验尾块**的无密钥封装格式。

此前 `analysis/ptool_crypto_results.json` 中记录的 `input_md5_and_internal_rc4_key_hex`（位于 `0x6adcec + (index-1)*0xb0`）具有双重用途，但**均不参与落盘加解密**：
1. **输入文件识别校验（`0x4f2f24..0x4f2fad`）**：`0x4f2f5b` 调用 `0x4f0998` 计算输入缓冲区 `0x0(%edi)`（长度 `0x4(%edi)`）的完整文件 MD5，并在 `0x4f2f77` 比对文件长度（`0x6adce8+(index-1)*0xb0`）、在 `0x4f2f8a..0x4f2f95` 比对 16 字节预期 MD5（`0x6adcec+(index-1)*0xb0`）。
2. **进程内内存缓存 RC4 混淆（`0x4f4556..0x4f45a3` 与 `0x4f2ecc..0x4f2f22`）**：
   - 加载分派函数 `0x4f44e0` 先根据 `0x6adc9c+index*0xb0`（即 `0x6add4c+(index-1)*0xb0`）处的 `method` 字段调用对应的落盘解码器（`method=0` 调 `0x4f37bc`，`method=1` 调 `0x4f3c9c` AES-128-CBC，`method=2` 调 `0x4f3f70` MT19937 流密码），将落盘数据 `0x0(%ebx)` 解码至工作明文缓冲区 `0x10(%ebx)`（长度写入 `0x18(%ebx)`）。
   - 随后无论 `method` 为何值，`0x4f4556..0x4f45a3` 均以表项中的 16 字节 MD5（`0x6adc3c+index*0xb0`）为密钥，调用 `0x4f0b44`（内部依次调用 RC4 KSA `0x4f09c8`、PRGA `0x4f0a9c`、状态擦除 `0x4f0a70`）将已解码的 `0x10(%ebx)` 加密复制到内部缓存缓冲区 `0x14(%ebx)`。
   - 在 `0x4f2f24` 完成补丁基线校验后，`0x4f33e6` 调用 `0x4f2708`（内部调用 `0x403a8c` `FillChar`）将明文工作缓冲区 `0x10(%ebx)` 清零，使驻留内存仅保留 `0x14(%ebx)` 中的 RC4 密文。
   - 当导出/打补丁（`0x4f2b14`）时，`0x4f2b2b` 先调用 `0x4f2ecc`（在 `0x4f2f1c` 再次调用 `0x4f0b44`）将 `0x14(%ebx)` 用同一 16 字节密钥 RC4 解密还原回 `0x10(%ebx)`，应用补丁后由 `0x4f2eb8` 调用保存分派器 `0x4f45ac`（`method=0` 分派至 `0x4f3940`）编码至输出缓冲区 `0x8(%ebx)`，最后在 `0x4f463d` 与 `0x4f2ec0` 再次清零 `0x10(%ebx)`。

## 2. `method=0` 落盘解码与重编码精确算法及地址证据

### 2.1 落盘解码器 `0x4f37bc..0x4f393d`（由 `0x4f450d` 调用）
- **输入**：`0x0(%ebx)`（原始文件字节流，长度 $L = \text{0x4(\%ebx)}$，满足 $L = 34 \times N$）。
- **34 字节分块循环（`0x4f37ea..0x4f3905`）**：对文件偏移 `in_pos`（`%ecx`）除以 `0x22`（34，`0x4f37ec..0x4f37f2`）：
  1. 当 `in_pos % 34 < 32`（`0x4f37f6..0x4f382b`）：将字节直接顺序追加至 `0x10(%ebx)[out_pos]`，`out_pos++`（`0x4(%esp)`）。
  2. 当 `in_pos % 34 == 32`（`0x4f3839..0x4f38fe`）：
     - 读取当前记录第 `32..33` 字节的大端序 16 位无符号整数 $C_r = (\text{buf}[32] \ll 8) \mid \text{buf}[33]$（`0x4f3839..0x4f3875`）。
     - 循环 `k = -16 .. -1`（`0x4f387c..0x4f38e7`），累加当前记录前 32 字节的 16 个大端序 16 位字 $W_{r,0..15}$：
       $$S_r = \left(\sum_{j=0}^{15} W_{r,j}\right) \bmod 2^{16}$$
     - 在 `0x4f38e9..0x4f38f8` 检验横向二补数校验和：
       $$(S_r + C_r) \equiv 0 \pmod{2^{16}}$$
       若任一 34 字节记录不满足，置错误标志 `(%esp) = 1` 并跳出循环，在 `0x4f3911..0x4f391b` 将状态码 `0x2c0(%ebx)` 与解码长度 `0x18(%ebx)` 置为 `-1`（`0xffffffff`）。
  3. 当 `in_pos % 34 == 33`（`0x4f3830..0x4f3833`）：跳过校验和低字节。
- **剥离末尾 32 字节纵向校验块（`0x4f392c..0x4f3933`）**：全部 $N$ 个 34 字节记录校验通过后，将有效解码长度置为：
  $$\text{0x18(\%ebx)} = \text{out\_pos} - 0\text{x}20 = 32 \times (N - 1)$$

### 2.2 落盘编码器 `0x4f3940..0x4f3bf9`（由 `0x4f45d9` 调用）
- **第一阶段：计算 32 字节纵向列校验尾块（`0x4f3953..0x4f3a8a`）**：
  - 在栈上 `0x8(%esp)..0x27(%esp)` 清零 16 个 `uint16` 列累加器 `acc[0..15]`（`0x4f3953..0x4f395e`）。
  - 遍历 `0x10(%ebx)` 的全部 $N-1$ 个 32 字节数据块（`0x4f3963..0x4f3a24`），对每一块内的 16 个大端序 `uint16` 字 $W_{r,j}$（$j \in \{0..15\}$），执行模 $2^{16}$ 递减（`0x4f39ef..0x4f39f1`）：
    $$\text{acc}[j] = \left(-\sum_{r=0}^{N-2} W_{r,j}\right) \bmod 2^{16}$$
  - 在 `0x4f3a2a..0x4f3a64` 将 `acc[0..15]` 转为大端序 32 字节，并在 `0x4f3a66..0x4f3a8a` 追加到 `0x10(%ebx)` 偏移 `0x18(%ebx)` 处（临时令 `0x18(%ebx)` 增加 `0x20`）。
- **第二阶段：逐 32 字节块封装 2 字节横向校验和（`0x4f3a8e..0x4f3bf2`）**：
  - 遍历含纵向尾块在内的全部 $N$ 个 32 字节块，每写入 32 字节至输出缓冲区 `0x8(%ebx)`，在 `0x4f3aec..0x4f3bd9` 计算其 16 个大端序 `uint16` 字之和的二补数 $C_r = (-\sum_{j=0}^{15} W_{r,j}) \bmod 2^{16}$，以大端序 2 字节追加至该块末尾，形成 $34 \times N$ 字节输出（输出长度写入 `0xc(%ebx)`，并在 `0x4f3bee` 恢复 `0x18(%ebx)`）。

### 2.3 虚拟地址映射与补丁原值校验（`0x4f24a4`、`0x4f343c`、`0x4f3028..0x4f323b`）
- `method=0` 表项（如 GH1 `0x6adce4`、GF1 `0x6add94`、G1 `0x6ade44`、G2 `0x6adfa4`）在 `+0x20` 处的首段地址映射均为 `0x40000000..0x40800000`（G2 为 `0x41000000`）$\xrightarrow{\Delta = -0\text{x}40000000}$ 缓冲区偏移 `0x0`，证明剥离 34 字节校验封装后的字节流即从 `0x40000000` 起始的裸固件镜像（不含 `method=1/2` 的 `0x200` 字节 `UPD` 文件头）。
