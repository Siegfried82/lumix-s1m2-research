# Lumix S1RM2 / S1M2 (Linux 4.19.124) QEMU 沙箱使用说明

本压缩包是一个**自包含、免编译、开箱即用**的松下 Lumix S1RM2 / S1M2 相机内核（Linux 4.19.124 ARM64）QEMU 虚拟机沙箱环境。无需安装交叉编译工具链，也无需下载完整的内核源码树，只需目标机器安装有 `qemu-system-aarch64` 即可直接运行。

---

## 一、包内文件清单

| 文件 / 目录 | 说明 |
|---|---|
| **`Image`** | 已编译好的相机 ARM64 Linux 4.19.124 内核镜像（14 MB，已修复 GICv2 Group 0 中断屏蔽问题，内置 PL011 串口、ConfigFS、FunctionFS、KASAN 及 `qoob` 虚拟 UDC 驱动） |
| **`initramfs.cpio.gz`** | 根文件系统镜像（内置 `/init` 初始化程序、`ffs_min` FunctionFS 守护进程、静态编译的 ARM64 **BusyBox 1.37.0** 全套 Linux 命令及 `/bin/qoob` 命令行工具） |
| **`System.map`** | 与 `Image` 完全对应的内核符号地址表（用于 GDB 调试或栈回溯解析） |
| **`kernel.config`** | 编译 `Image` 使用的内核 `.config` 配置文件 |
| **`run_qemu.sh`** | Linux / WSL2 / macOS 启动脚本 |
| **`run_qemu.ps1`** | Windows PowerShell 启动脚本 |
| **`sbox.c`** | `/init` 源码：负责挂载 `/proc`、`/sys`、`/dev`、`configfs`、`functionfs`，配置 USB Gadget (`g1`) 并启动 REPL 或 `/bin/sh` |
| **`ffs_min.c`** | 最小化 FunctionFS 用户态端点守护进程源码（向 `/dev/ffs0/ep0` 写入 V2 描述符与字符串表并保持句柄打开） |
| **`qemu_oob.c`** | 内核态虚拟 UDC (`qoob`) 与 `/proc/qoob` 控制请求注入驱动源码 |
| **`patches/`** | 针对松下官方开源内核 `linux-4.19.124.tar.gz` 修改过的源码备份（`irq-gic.c.patched`、`composite.c.patched`） |
| **`build.sh`** | 从源码重新编译内核与 `initramfs` 的构建脚本（日常直接运行无需使用） |

## 二、环境准备（仅需安装 QEMU）

在目标机器上安装 `qemu-system-aarch64`：

- **Ubuntu / Debian / WSL2**：
  ```bash
  sudo apt update && sudo apt install -y qemu-system-arm
  ```
- **macOS (Homebrew)**：
  ```bash
  brew install qemu
  ```
- **Windows (PowerShell)**：
  ```powershell
  winget install SoftwareFreedomConservancy.QEMU
  # 安装后请确保 C:\Program Files\qemu 已加入系统 PATH 环境变量
  ```

解压本压缩包：
```bash
unzip lumix_s1rm2_qemu_sandbox.zip
cd qemu_sandbox
chmod +x run_qemu.sh
```

## 三、四种运行与交互方式

### 方式 1：直接进入虚拟机内 Linux `/bin/sh` 交互式 Shell（推荐）

启动后自动完成所有内核挂载、FunctionFS 描述符注册与 UDC 绑定，随后直接进入 BusyBox `ash` Shell：

- **Linux / WSL2 / macOS**：
  ```bash
  ./run_qemu.sh --shell
  ```
- **Windows PowerShell**：
  ```powershell
  .\run_qemu.ps1 -Shell
  ```

启动约 0.4 秒后即可看到提示符 `lumix-s1rm2:~#`，常用操作示例：
```sh
# 1. 查看内核版本与进程列表
uname -a
ps

# 2. 查看已绑定的 FunctionFS 端点与 ConfigFS USB Gadget 配置
ls -la /dev/ffs0
ls -la /sys/kernel/config/usb_gadget/g1

# 3. 使用内置的 qoob 工具查看虚拟 UDC 状态
qoob status

# 4. 发送 USB SET_CONFIGURATION(1) 激活相机 USB 接口
qoob "cfg 1"

# 5. 查看松下 composite.c 在激活配置时自动写入 /tmp 的相机状态文件
head -n 1 /tmp/usb_configured /tmp/usb_maxpacket*

# 6. 发送 USB GET_INTERFACE 控制请求（wIndex = 0x0000）
qoob "get 0"

# 7. 查看内核日志
dmesg | tail -n 25

# 8. 退出并干净关闭虚拟机
exit
```

---

### 方式 2：使用默认 `sbox` 控制命令 REPL

不带参数运行启动脚本时，默认进入专用的 `sbox` 命令交互循环：

```bash
./run_qemu.sh
```

支持以下命令：
| 命令 | 参数示例 | 功能说明 |
|---|---|---|
| `status` | `status` | 查看 `qoob` UDC 绑定状态、USB 速率与控制请求计数 |
| `cfg <n>` | `cfg 1` | 注入 `SET_CONFIGURATION(1)` 请求（激活前必须先执行一次 `cfg 1`） |
| `get <wIndex>` | `get 0` 或 `get 0x100` | 注入 `GET_INTERFACE` 请求（十六进制 `wIndex`），返回 1 字节结果 |
| `set <wIndex> <wVal>` | `set 0 0` | 注入 `SET_INTERFACE` 请求（十六进制 `wIndex` 与 `wValue`） |
| `scan <s> <n> <st>` | `scan 0x100 8 0x100` | 从起始 `wIndex=s` 开始，以步长 `st` 连续发送 `n` 次 `GET_INTERFACE` |
| `sh` / `shell` | `sh` | 随时切换到 BusyBox `/bin/sh` Shell（在 Shell 中执行 `exit` 可返回 REPL） |
| `help` | `help` | 打印命令帮助 |
| `exit` | `exit` | 调用 `reboot(RB_POWER_OFF)` 干净关闭虚拟机 |

### 方式 3：宿主机管道 / 自动化脚本批处理运行

适合在宿主机使用 Shell 或 Python 脚本批量运行测试并捕获输出：

```bash
( sleep 2; printf 'status\ncfg 1\nget 0\nstatus\nexit\n' ) | ./run_qemu.sh
```

或在 `--shell` 模式下自动执行一段宿主机传入的 Shell 脚本后关机：
```bash
( sleep 2; printf 'uname -a\nqoob "cfg 1"\ncat /tmp/usb_configured; echo ""\nexit\n' ) | ./run_qemu.sh --shell
```

### 方式 4：GDB 内核源码/符号级调试模式

使用 `--gdb`（Windows 下为 `-Gdb`）启动时，QEMU 会在 `tcp::1234` 开启 GDB 调试端口并在启动入口暂停（`-s -S`）：

1. **终端 1 启动虚拟机**：
   ```bash
   ./run_qemu.sh --gdb
   ```
2. **终端 2 连接 `gdb-multiarch`**：
   ```bash
   gdb-multiarch -ex "target remote 127.0.0.1:1234" \
                 -ex "add-symbol-file System.map 0"
   ```
   > **注（内核虚拟地址映射参数）**：
   > - 本内核使用 `CONFIG_ARM64_VA_BITS=39`：
   >   - 内核镜像虚拟基址：`0xffffff8008000000` $\leftrightarrow$ 物理地址 `0x40000000`
   >   - 线性映射区基址 (`PAGE_OFFSET`)：`0xffffffc000000000`，线性区虚拟地址转物理地址公式为：
   >     $$\text{PA} = (\text{VA} \ \& \ \text{0x3fffffffff}) + \text{0x40000000}$$

## 四、如何解包定制 `initramfs.cpio.gz`（放入自定义程序或相机文件）

如果需要在虚拟机文件系统中加入自定义脚本、测试程序或解密后的相机文件，无需重新编译内核，直接在 Linux / WSL2 / macOS 下解包修改即可：

```bash
# 1. 创建临时目录并解包
mkdir rootfs_custom && cd rootfs_custom
gzip -dc ../initramfs.cpio.gz | cpio -idmv

# 2. 向 rootfs_custom 中添加你的文件或修改配置
#    例如放入静态编译的 ARM64 程序或相机数据文件

# 3. 重新打包覆盖 initramfs.cpio.gz
find . | cpio -o -H newc 2>/dev/null | gzip -9 > ../initramfs.cpio.gz
cd ..
```

## 五、常见问题与注意事项 (FAQ)

1. **如何随时强制退出 QEMU？**
   - 在正常情况下输入 `exit`（REPL 或 Shell 下）或 `poweroff` 即可干净关机。
   - 若因内核崩溃/死锁需要强制退出 QEMU `-nographic` 终端：先按组合键 **`Ctrl + A`**，松开后再按 **`X`** 即可立即退出 QEMU。
2. **为什么后台有一个 `ffs_min` 进程，能否杀掉？**
   - **不能杀掉**。Linux FunctionFS 要求用户态守护进程 (`ffs_min`) 写入描述符后必须保持 `/dev/ffs0/ep0` 文件描述符处于打开状态；一旦关闭，FunctionFS 状态会退回 `FFS_DEACTIVATED`，后续 USB 控制请求会直接返回 `-ENODEV`。
3. **如何配合松下官方开源包完全重编内核？（可选）**
   - 从 [松下 OSPO (DC-S9 / DC-S1RM2)](https://ospo.panasonic.com/oss/dsc/DC-S9.html) 或 [DC-S1M2NT](https://ospo.panasonic.com/oss/dsc/DC-S1M2NT.html) 下载 `linux-4.19.124.tar.gz` 解压到 `../ospo/linux-4.19.124/`。
   - 将 `patches/irq-gic.c.patched` 覆盖至 `drivers/irqchip/irq-gic.c`，将 `patches/composite.c.patched` 覆盖至 `drivers/usb/gadget/composite.c`，将 `qemu_oob.c` 放入 `drivers/usb/gadget/function/qemu_oob_sandbox.c`，然后运行 `./build.sh` 即可重新生成 `Image` 与 `initramfs.cpio.gz`。
