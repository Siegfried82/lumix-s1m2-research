# ROM BACKUP 的 S1M2 实机验证：服务模式入口、菜单形态与导出格式

2026-10-09 实机验证，机型 DC-S1M2，固件 V1.4。机身序列号已脱敏（仅保留槽位结构与长度信息）。

## 验证的问题

仓库既有结论《ROMBACKUP_SD路径_证据边界》指出：S1M2 手册 p8/p74 称通过 menu ROM BACKUP 下载 Flash-ROM，但"没有写出是否存在非电脑导出、SD 卡目标、具体文件名或文件范围"，且"旧型号的操作序列与导出格式不能直接套到 S1M2"。本实验回答三个未决问题：

1. S1M2 服务模式（临时解除初始设置）的真实进入条件；
2. 临时解除后 SETUP 菜单的实际形态（ROM BACKUP 是否存在、包含哪些项）；
3. DSC→SD 导出是否存在于 S1M2、导出文件的数量/名称/大小/格式。

## 输入与取得方式

- 设备：Panasonic LUMIX DC-S1M2，固件 V1.4（由 PTP GetDeviceInfo 0x1001 读出，与 EEPROM 内序列号互证）。
- 依据文献：S1M2 维修手册第 13 页 Step1（临时解除）与第 39 页（直接关机恢复），比对表见《S1M2_ROM_BACKUP与原厂维修协议逆向推导报告》。
- 全部操作在机身菜单完成，未连接任何电脑软件，未执行任何写入项。

## 进入条件（实测，含一处此前未记载的前置条件）

**关键前置条件：驱动拨盘必须先拨到 [Single] 单张位置，否则按键组合开机无效、正常进入普通模式。** 其余条件为：照片模式（非视频档）、对焦 AF-S、电池电量充足、卡在位。

操作序列：

1. 关机；
2. 同时按住 [Playback]（左肩）+ [AF-ON]（背面）不松手，将电源开关拨到 ON；
3. 开机约 2 秒后松开；
4. 按 MENU/SET 进 SETUP 菜单，即出现隐藏维修项。

（对照旧平台 TS2 的入口是 [UP]+[DISPLAY] 开机；S1M2 手册比对表写的是 [Playback]+[AF ON]，本次实测确认该序列生效，并补上"驱动拨盘 Single"这一必要条件。）

## 菜单形态（实测 8 项）

| 菜单项 | 方向判定 | 本次是否执行 |
| :--- | :--- | :--- |
| `DSC->SD` | 机身 → SD 卡，只读导出 | ✅ 执行一次 |
| `SDALL->DSC (ID CHECK)` | 写入机身（带 ID 校验） | ❌ 未执行 |
| `SDALL->DSC (FORCE)` | 强制写入机身 | ❌ 未执行 |
| `SDUSER->DSC (FORCE)` | 强制写入用户数据区 | ❌ 未执行 |
| `!->LUMIX` | 方向不明（疑与调整软件/电脑路径相关） | ❌ 未执行 |
| `ADJFLAG->ALL F` | 写入机身（手册 p74：把全部调整标记置 F） | ❌ 未执行 |
| `WBADJ->STEPMODE` | 模式切换，方向不明 | ❌ 未执行 |
| `STEPMODE->WBADJ` | 模式切换，方向不明 | ❌ 未执行 |

观察：**ROM BACKUP 菜单确实内建于 S1M2 固件，临时解除后直接可见，不需要外部调整软件**——与手册 3.4.2/10.1 节文字一致。除 DSC→SD 外的所有项均为写入或方向不明，本次一律不执行；临时解除后直接关机退出（手册第 39 页：直接关机即恢复正常）。

## DSC→SD 导出结果

导出过程中机身屏幕无提示，完成后卡根目录出现 6 个文件：

| 文件 | 大小 (B) | SHA-256（前 16 hex） |
| :--- | ---: | :--- |
| S1m2U.TXT | 356,668 | 3f3ee27eb2dd1f67 |
| S1m2A.TXT | 356,673 | 702bca1b16c24aa8 |
| S1m2F.TXT | 356,670 | 0c41ceaaab16c3e9 |
| S1m2D.TXT | 356,670 | 9be67b917e2e649d |
| S1m2K.TXT | 1,442,112 | 85a93891984a3c93 |
| S1m2X.TXT | 178,493 | ebb3078ddd427ac6 |

文件含机身序列号等敏感字段，按贡献规范不随仓库分发；复现者按上述入口自行导出。仅给出格式观察：

### 文件格式

- 纯文本，头为 `###### EEPROM DATA INFORMATION ######`，随后 `#@1: AREA / #@2: TYPE / #@3: START ADDRESS / #@4: DATA SIZE` 字段行。
- 数据行为 `H<偏移> <16 个 4-hex 逗号分隔值>,`，每个值 16-bit 大端字。
- **头部 DATA SIZE 的单位是 16-bit 字**：实际字节数 = 声明值 × 2。全部 6 个文件均符合该规律，可作为解析时的一致性检查。

各文件区域声明（`#@1` 字段）与实测大小：

| 文件 | AREA 标签 | 声明大小（字） | 实测字节 |
| :--- | :--- | ---: | ---: |
| S1m2U.TXT | UPDATE | 0x10000 | 131,072 |
| S1m2A.TXT | ADJUST ONLY | 0x10000 | 131,072 |
| S1m2F.TXT | FIX | 0x10000 | 131,072 |
| S1m2D.TXT | DSH ONLY | 0x10000 | 131,072 |
| S1m2K.TXT | KIZU ONLY | 0x40000 | 524,288 |
| S1m2X.TXT | XTK ONLY | 0x8000 | 65,536 |

### 区域内容观察（结构，不含具体值）

- **UPDATE**：非零率 10.3%，含若干可读标识串，头部之后大部分为 0。
- **ADJUST**：非零率 5.4%。头部 0x00/0x20/0x40/0x60 处为 4 个 32B 序列号槽，各含 11–13 字符字母数字序列号（已脱敏）；其后为分块调整记录（块边界处出现 ` < < < ` 分隔符，记录长度 ~0x5xx）。
- **FIX**：非零率 22.8%，无长明文串，为二进制调整数据。
- **DSH**：全零（备用）。
- **KIZU**：非零率 0.6%，稀疏非零条目，与"坏点/缺陷像素表"语义一致（标签字面义，未见原厂说明）。
- **XTK**：非零率 11.3%，呈规律重复的短记录，与"串扰（cross-talk）校正"语义一致（同上，标签字面义）。

## 与 PTP 配置镜像的关系

同一台机身此前经 USB PTP `0x9421[0x080000a2]` 采集了 9,197,421B 配置 DAT（两次读取 SHA-256 一致）。将 UPDATE 区的特征串与片段在 DAT 中检索：**全部不命中**，且 DAT 头格式（"Panasonic" 头 + 设置记录）与 EEPROM 文本转储完全不同。观察结论：ROM BACKUP 导出的 EEPROM 参数区与 PTP 可读的配置存储是两个独立存储面。

## 观察 / 推论 / 未知

- **观察**：入口条件（含 Single 前置）、菜单 8 项、导出 6 文件、格式规律（16-bit 字单位）、区域标签与大小。
- **推论**：各区域语义（坏点表、串扰校正等）由标签字面义 + 数据形态推出；EEPROM 导出为校准/参数分区，不含 NAND 中的固件程序（与《终局报告》"Flash-ROM=参数区"的判定一致）。
- **未知**：`!->LUMIX` 与 WBADJ/STEPMODE 两项的确切行为；`ADJFLAG->ALL F` 的完整副作用（未执行，仅据手册文字）；导出是否需要"彻底解除"（本次仅临时解除即成功）。

## 什么会推翻本结论

- 不同固件版本（非 V1.4）菜单项或入口条件不同；
- 另一台机身导出的文件集不同（本实验 n=1）；
- 若后续实机执行表明 `DSC->SD` 在某种状态下会写入机身，则"只读导出"判定需修正（本次依据：方向语义 + 手册文字 + 导出后 PTP 重读状态一致）。

## 复现清单

1. DC-S1M2（V1.4），照片模式、AF-S、驱动拨盘 **Single**、电池满、卡在位。
2. 关机，按住 Playback+AF-ON 开机，2 秒后松开。
3. SETUP 菜单出现隐藏维修项，进入 ROM BACKUP。
4. 仅选 `DSC->SD`；出现写入/初始化类确认一律不确认、直接关机退出。
5. 卡根目录按上表核对 6 文件大小与 SHA-256 前缀。
