# S1M2 录像质量响应与 Tether 2.12 实际消费者

2026-10-11；全程离线，仅解析 2026-10-08 保存的机身响应及客户端文件。没有相机通信、参数写入或供应商二进制执行。

## 本轮闭合的证据

`get_9408_06000010.bin` 的 2852 字节完整解析为 10 个按 `tag:u32 + body_length:u32 + body` 顺序排列的块。两个保存的录像读取响应均带真实 PTP `0x2001` 成功码；事务 ID 分别 13、4，对应保存日志中的读取项目。成功码只证明该次读取。

质量详情块 `0x0600001A` 从文件偏移 `0x48` 开始：块体长 2742，体头为 `count:u16=114`、`wire_stride:u16=24`、`current_quality_id:u16=494`。`6 + 114×24 = 2742` 恰好覆盖块体。`0x06000013` 的当前质量值也是 494；现有 capability 的 `0x06000013` 默认值同为 494，其枚举有 80 个 ID，全部存在于这 114 条详情记录中。额外 34 条原始记录及顺序、原始偏移、全部字段保存在 `decoded.json` 的 `detail_records_outside_capability`；未把集合差分称为隐藏模式。

现代 Tether 的 `Mov_Config_Get_Quality_mode_Param` 读取的是配置结构偏移 `0x1c`，质量详情 API 则把列表头及每条 24 字节记录复制到应用缓存。SDK 接收分发不是按标签名字猜测：本轮读取原始 dylib、根据 Mach-O 段映射，复算 `0x1d08e8` 跳转表，确认 `0x06000013 → 0x38d9c`、`0x06000019 → 0x38e38`、`0x0600001A → 0x38e50`。对应反汇编的全部窗口已保存，带原始一基行号。

## 记录结构与消费用途

下表偏移相对于单条 wire 记录起点；含义来自实际 SDK 复制、App getter 读取及静态 Qt 元数据，不代表机身编码器已经验证这些含义。

|偏移|类型|真实消费用途|
|---|---|---|
|0|u16|video quality ID，QML 用作选择值和当前项比对|
|2|u32|帧率显示：低 28 位除以 100，bit31 选择 `p`/`i`|
|6|u16|pixels enum；App Qt `MoviePixel` 完整数值表已提取|
|8|u16|压缩方式复合码；实际函数拆出三个 enum 值再由 QML 显示|
|10|u16|客户端码率显示；非 ProRes 路径数字后加 `M`|
|12|u16|VFR 字段|
|14|u16|HLG 字段|
|16|u16|S&Q 字段|
|18|u16|SSD 字段|
|20|u16|SD 字段|
|22|u16|CFexpress 字段|

SDK 列表解析见原始反汇编 57376–57430 行；App 的实际帧率、复合码拆分、像素、码率及介质 getter 见 76237–76915 行。复合码低层分支的跳转字节 `00 08 10 18 20 28` 是本轮从原始 App 的 VA `0x100146152` 读取的；分支立即数再接静态 Qt `MovieCompressMethod` 数值表，避免用符号名称直接推断位深。`evidence.json` 同时保存 staticMetaObject 的实际指针、元数据头、enum 项地址及原始文件偏移。

显示控制块 `0x06000019` 是七个 u16：`[1,1,1,1,0,1,1]`。App 将 wire 前两个字段交换后写入自身显示索引，其余依次保留；本例两者均 1，交换不会改变本例结果。字段 1 在 App 转换为 true；第五字段 0 使 VFR 栏隐藏。这些是显示开关，不能作为功能支持位使用。旧 12 字节显示结构没有 S&Q 字段，解析器保留缺失而不填零。

## 当前 ID 494 的具体例子

详情索引 76，原始文件偏移 1910（`0x776`），原始 24 字节：

```text
ee016a170080040000112003000001000000010000000100
```

客户端解释为：pixels enum 4 → `MP_4K_16_9_3840_2160`；帧率 `0x8000176a` → `59.94p`；复合码 `0x1100` → 数值 `[0,2,5]` → `MCPM_422/MCPM_10bit/MCPM_ALL_I`；码率字段 800 → `800M`。当前格式值 `0x06000014=3`，静态 Qt 映射为 MOV，因此是客户端非 ProRes 显示分支。

此记录 VFR=0、HLG=1、S&Q=0、SSD=1、SD=0、CFexpress=1。实际质量弹窗先执行记录介质门：SD 和 CFexpress 均不为 `POSSIBLE(1)` 才跳过，因此 494 在这项门中可凭 CFexpress=1 通过。它另有 S&Q 门：在显示支持且 S&Q 栏可见时，如果 `recordingMode == RM_SQMotion` 或 `shotModeStatus == Shot_Mode_Status_Slow_Quick`，S&Q 不为 1 的记录被跳过。因此在这些条件成立时 494 会被过滤。

本轮没有选定机身处于普通录像还是 S&Q 状态，也没有选定用户滤镜设置；不能推导最终弹窗实际显示项数。34 个多出 ID 的成因也没有闭合，它们的额外帧率/像素和各标志均逐条保留，不能仅凭列表存在就说可设置、隐藏或可成功录制。

主线程补充复算：本例114条及额外34条全部能通过上述SD/CFexpress记录门，因此**不能用这项介质门解释34条集合差分**。额外记录的(S&Q,SD,CFexpress)原始值分布为(0,1,1)25条、(1,1,1)8条、(0,0,1)1条；它们还会受到其他界面和设备条件影响，成因仍未确定。

两份采集日志均标识DC-S1M2，但能力读取时间为2026-10-08 18:26:35 UTC，详情读取为18:28:30 UTC，相隔1分55秒，且读取操作分别为0x9108和0x9408。两次当前值相同不足以证明其他状态相同。本轮比较的是两份历史响应，不能冒充同一时刻、同一模式下的受控差分。

## QML 来源与解析检查

两个用于核对实际过滤和显示的 QML 是 Windows Tether 2.12 原始 EXE 的嵌入资源，本轮重新解析 PE 段映射、资源节点及压缩长度后定点提取，字节与旧成品相同。保存为 `verified_windows_qml/qml/`，精确消费行：`LTMainMovieQualityPopup.qml` 723–823（循环、S&Q/介质门、字段读取、ID）、857–919（显示开关）、1000–1025（压缩方式显示映射）；`LTMainMQComponentsProvider.qml` 4921–5008（对应 enum 的显示键）。它是 Windows 源码，未声称从 macOS QML cache 提取。

此前 `analysis/parallel_routes_20261009/02_host/extract_qml.py` 写的是 14 字节节点，并将两个 flag 反置；本轮没有执行它或修改原稿。当前实际资源节点为 Qt 6 的 22 字节结构，flag 2 是目录、flag 1 是 zlib。当前 parser 的定点提取经过长度检查并成功复算，与旧脚本是否曾执行成功无关。

所有输入完整 SHA-256、段映射及上述定点证据在 `evidence.json`。`validation.json` 记录完整覆盖与五种错误输入拒绝，以及短记录缺字段保留 null 的检查。运行：

```text
python3 analysis/video_quality_consumer_20261011/analyze.py
```

解析器针对当前消费者支持的 16/18/24 字节 wire 结构；未知 stride、长度不符或越界均拒绝，不以 Tether 在旧结构内填充的默认值冒充相机返回。原始记录保留 index，避免同名或同 ID 被字典覆盖。

主线程已重跑解析器，核对114/80/494与五种拒绝、短记录缺字段检查，并从当前原始App/dylib重新生成14个相关arm64函数，与既有反汇编逐函数文本完全一致。复核入口为`verify_current_disassembly.py`，需先运行`analyze.py`；记录在`parent_current_disassembly_check.json`，包含两份采集日志摘要、时间、集合差分标志与函数摘要。未执行供应商文件或调用设备。
