# Windows 独有导出读取路径补查

使用现有 PE 导出比较中的 20 个 Windows 独有名称定位代码，保存各导出起始 160 字节反汇编用于初筛。这些片段不保证覆盖整个函数。

独立追踪了两个读取路径：

- Hl_Shd_Get_Highlight_Adj 在 0x18001514d 调用内部辅助函数 0x180014a30。辅助函数 0x180014a74 构造 0x9402，属于此前已识别的摄影属性读取操作族。包装函数最终取结构内 16 位字段。本路径没有出现调用方指定物理地址或 RAM 读取长度。
- SetupRangeSet_Get_Info 在 0x18002fcdc 跳转内部辅助函数 0x1800301a0；其 0x1800301e0 构造 0x940a。后续解码涉及 0x080000b1–b4，支持配置字段读取解释，不能当作任意地址读取接口。

证据分别在对应导出 txt 与 helper_0x14a30.txt、helper_0x301a0.txt。objdump 为内部函数显示“邻近导出名+偏移”，应以 RVA/地址为准，不能用显示名称认定辅助函数功能。

这是两条路径的初步排查，没有完成 20 个导出的全调用链审计，亦不能断言 Windows 库没有其他读取接口。没有运行 DLL 或发出机身命令。机内功能修改仍未实现。

## 后续扩大核对

现已将 20 个导出片段扩展到下一个命名导出 RVA，范围见 export_regions.json。这比固定 160 字节覆盖更广，但区间可能含未命名私有函数，也不能覆盖跳转到其他区间的代码；不能称为完整函数边界。

Pattern_Info、Highlight_Adj、Shadow_Adj 三个 getter 均直接调用 0x180014a30（0x9402 构造器）。Hl_Shd_GetCapability 可见常量 0x020001e0–e3，并调用 Get_Tag_CapabilityInfo 与辅助函数 0x180034cd0，属于标签能力查询路径；辅助函数未在本次完整追踪。

SetupRangeSet 的 SS、Aperture、ExposureComp、ISO 四个 getter 都将 0x080000b0 传给 0x1800301a0。此前报告提到的 b1–b4 是辅助函数后续处理或 setter 相关编号，不能替代 getter 的实际请求参数 b0。

Lmx_func_api_Get_Error 导出入口仅从主机全局地址 0x18025e704 取 32 位值并立即返回，未发设备请求。其后区间包含另一个未命名函数，不属于该导出的实际返回路径。

新增核对仍未发现任意内存读取接口；这不是全库否定结论。

## 标签能力辅助函数补查

补充保存 capability_helpers.txt（RVA 0x34880–0x34e80）及 capability_cache_helpers.txt（0x34480–0x34880）。前者两个封包路径在地址 0x180034947 与 0x180034b4d 分别构造 0x9107、0x9108，两者写入参数数目 3，交给共同发送入口 0x180051f80。此处接收容量参与主机缓冲分配，不因它较大而证明内存地址可读。

高光/阴影能力路径的 0x180034cd0 辅助函数调用 0x180034480 与 0x180034560。实际指令显示这两者在主机提供的结构中遍历带标签编号和长度的记录，并复制字段；不是新的设备读取封包。检查边界仍限于可见路径，间接调用未穷尽。

本次未发现物理地址读取构造。现阶段不要继续把这一配置能力路径作为 RAM dump 候选；需要不同类型的真实调用证据或相机端代码。
