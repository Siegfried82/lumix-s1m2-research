# 舊結果更正清單

依據：本輪542項原始BIN重讀、14組完整bytes差分、独立結果檢查。原稿保留不改寫；相關 source SHA-256 與快照位置見[歷史索引](results/data/historical_sources.json)。判斷不依賴執行舊工具。

## 偏移錯誤的精確原因

較早 inspect_upd.py 從0x2EC取記錄，使用entry+0x0C＋0x200定位payload。locator 的 analyze_s5m2_versions.py、s5m2_upd_audit.py、s5m2_fourway_compare.py以0x2DC為基址，名稱另加0x10，因此名稱／大小／flags／目錄摘要部分看似正確，卻把oldpos+0x24（即正確entry+0x14）的destination_field當作檔案offset。這不是單純缺少0x200，而是讀錯欄位。

542個舊解釋的範圍全部與正確載荷範圍不同。locator的全版本與X版本兩份JSON中，468個raw摘要不吻合本輪正確摘要；另74個偶然匹配不證明其範圍正確，空項／常量填充可使錯誤範圍碰巧同摘要。每個boot項還被特殊規則讀成檔尾非零範圍，實際目錄size是0。

V3.2的直接例子：

| 目錄項 | 舊offset/size | 正確absolute offset/size | 結論 |
| --- | --- | --- | --- |
| boot#0 | 208561152 / 5632 | 6144 / 0 | 舊boot blob不是此項payload |
| loader1#0 | 0 / 131072 | 6144 / 131072 | 舊切片含外／內層頭與其他資料 |
| hm_d_nw_7th#0 | 208011264 / 1441792 | 206994432 / 1441792 | 正確末尾208436224，在檔內 |
| mbr_dummy_d#0 | 209453056 / 131072 | 208436224 / 131072 | 正確末尾208567296，等於EOF |

V3.3同樣不存在舊報告所稱最後兩項超出檔案的情況；所有十份樣本全542项有效。不能由錯誤offset導出「目录还描述外置payload／特殊存储机制」的結論。

## 分類處理

### 保留（重讀確認）

- 十份樣本的完整BIN身份、型號、CRC自洽及目录項數。
- 正確來源的既有JSON：correct_v20_v22、correct_v20_v31、correct_v31_v32、correct_v37_x27。所選的逐項大小、flags、absolute_offset、directory_digest、raw_sha256、完整16byte欄位零不符。
- 兩組同代跨機型的10個目錄摘要不同identity清單。
- 四方58項的目錄摘要變更模式一致，兩条升級均有相同12項目錄摘要變更。這只是欄位觀測。

### 撤回或替換

- 「V3.2／V3.3最後兩項不在檔案內」：錯誤欄位引起，撤回。
- locator舊raw載荷摘要、raw變更分組及四方active統計：以正确範圍重算結果替代。
- 「digest、12-byte欄位不變但blob變」並由此指定稀疏／隱藏參數：在此轮正确范围、完整尾16bytes下沒有重現，撤回這项證據。不能反向宣稱所有稀疏／其他參數機制不存在。
- 「64bytes r/s落在P-256範圍就已證明ECDSA」：不成立；本輪没有公鑰、簽署範圍或成功驗章。
- 密鑰位於OTP／ROM／硬體安全區、AES特定模式、離線解碼不可能：此輪沒有相應消费者證據，不采信為確認結論。

### 降級為候選（不等於推翻全部線索）

- 相同directory_digest不能直接宣布相同受保護明文；digest的实际处理对象仍未知。
- 同步欄位更換模式可以提示共同構建／平台候選，不證明完全相同更新樹。
- 10個候選摘要差異項可以作後续素材分類，但不能由名稱指定程序用途、功能限制、授权开关或可跨機型替換。
- 此四份BIN沒有active64KiB区块差分完全匹配，只是有限觀測，不排除任意變換下的patch、共享密鑰流或其他密鑰關係。

本清單只審查A＋B涉及的格式、範圍與差分論證；沒有重跑舊密碼枚舉、签章恢复、设备请求或App分析，不能把那些未重驗內容算作本轮通過。
