# 尼康三表 XOR 模型对松下候选的限定检验

来源：https://github.com/WonderLantern/nikon-fw-key-tool ，extract_key.py的recover_family使用256字节扇区的归一化重复关系恢复T1；解密公式按地址的低/中/高8位索引三张表。

若明文为恒定填充值，则在一个对齐256字节扇区内，T2/T3为常数，cipher[j] XOR cipher[0] = T1[j] XOR T1[0]。因此所有扇区的归一化256字节向量必须相同，跨T3区也成立。未知起始对齐可检验256种。

输入：S1M2现有inventory核实的固件；第8、10组件，各131072字节。候选目录摘要与第61项已验证全FF、同长度参考相同。这支持全FF明文假设，但不证明摘要字段一定是解码后散列。

结果：合成三表XOR的512扇区正对照通过。两个真实候选分别测试全部256种对齐，没有兼容对齐；最大相同归一化扇区家族只有1。不存在尼康模型所需的扇区关系。

限定结论：在“这些载荷解码后为全FF且直接采用所述三表XOR”的假设下，原样套用尼康模型不成立。不排除其它明文、封装/预处理、不同表作用域或其它算法。不能推出AES、密钥位于芯片或离线解码不可能。

check.py可复现，results.json保存输入散列、完整256种对齐统计及正对照。没有执行上游项目、接触机身或生成修改固件。

值得迁移的是证据方法：构造已知明文候选→检验算法必然关系→仅在通过后恢复参数→用独立目录/散列校验。尼康的具体表、模块地址和摘要机制不能直接移植至松下。
