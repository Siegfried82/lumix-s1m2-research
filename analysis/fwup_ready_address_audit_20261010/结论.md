# Tether 2.12 升级数据来源与地址核验

## 已确认

证据源是本地 arm64 反汇编 `analysis/tether_2_12_ptp_arm64_disassembly.txt`，SHA-256：f0beab04bef63508de6492cf263f62199548bda97911ab5852b371474537af1d。原始函数、行号和指令保存在 evidence.json 与 file_to_transport_evidence.json。本轮仅静态读取，不执行客户端，不访问相机。

### 地址来自相机 Ready 返回

Get_Event_Info（71292行起）通过0x9605读取事件信息。Ready标签为0x41000013；32位返回的address字段位于响应+0x0c，64位同样从响应+0x0c读取8字节。函数把它们写入输出结构+0x0c或+0x20。外层Get_Event_Info（71024行起）将输出结构置于客户端全局0x49e724，因此32位地址缓存为0x49e730，64位地址缓存为0x49e744。这些是客户端地址，不是相机物理地址。

Send_FWUP_Data（71156行起）从上述缓存取值：0x46d70读取32位，0x46d34读取64位。metadata布局分别为12字节[length u32, address u32, type u32]、16字节[length u32, address u64, type u32]，后者的地址字段未按8字节对齐。元数据通过0x9606发送。

这证实正常客户端传输地址由相机Ready信息提供，不能把它描述为调用者直接传入的任意目标地址。仍未证明相机如何验证元数据地址，也未证明存在任意写漏洞。

### 从文件到传输的路径

FirmwareUpdate_Th（70357行起）接收文件路径，调用Check_FileType_from_FilePath与Get_FileData_FileSize；加载返回的buffer于0x46164进入x24，长度于0x4616c进入w25。0x46178至0x46198检查头三个字节为UPD。

Check_FileType（70783行起）按扩展名前三个字符进行大小写不敏感比较：ROM输出type=0，BIN输出type=1。这是客户端类型选择，不能推断任意后缀文件均被相机接受。

Get_FileData_FileSize（70891行起）使用open/stat/LMX_Alloc/LMX_Lock/read读入整个文件，返回buffer与长度，没有在这个函数中观察到解密、解压或去除UPD外层。

主流程0x4647c将x24作为buffer、0x46480将x25作为length，交给Send_FWUP_Data。该函数0x46e4c以buffer+offset取分块，最大0x7d000=512000字节（500KiB）。Send_Data（71610行起）的0x47494至0x4749c把输入块memcpy至发送缓冲，再于0x474d4调用SendCommand。

因此，这条已定位的升级路径把UPD文件内容送入传输包装层，没有显示先把专有组件变成明文的步骤。传输层的完整实现及机内处理仍需分别验证；不能将结论扩大成Tether所有代码绝无解密密钥，或全部型号固件都由BootROM解包。

## 对下一步的影响

目前没有新增S1M2专有程序明文。单凭0x9606字段追主机密钥的依据减弱。下一步优先检查SendCommand到USB/PTP载荷的最后复制链，以及官方加载器配置与已解出的公开组件是否存在可对应的解码入口；保留机内升级处理位置为未知。

## USB 桥接层继续核验

已新增 usb_bridge_evidence.json，保存5个完整函数。SendCommand的USB分支0x40268至0x4028c将原始发送buffer与length转交Bridge::sendCommand。Bridge在0xf0b8/0xf0bc传入原buffer与length，0xf0c0构造NSData；Controller在0x2d660至0x2d668将此NSData转交LmxSenderThread初始化。初始化0x2b754至0x2b75c仅initWithData复制至对象+0x20。doSendRequest在0x2bd20从对象+0x20取得该数据作为outData，0x2bd40调用requestSendPTPCommand:outData:sendCommandDelegate:didSendCommandSelector:contextInfo:。

到系统PTP API边界为止，已定位的USB发送链仍保留文件数据，未见固件解密/解包步骤。Objective-C动态分发及系统内部实现未被穷尽，此结论限于已定位函数。相机端是否解密、在哪个处理器/启动阶段解密仍无直接证据。
